## 1. 模块概述

- **职责**：由**实货敞口**出发编制套保计划、计算套保比率（三档方法）、生成**套期关系书面文件**、走**审批链**，并将计划分解为**交易计划**。
- **解决的业务问题**：不解决则交易**失去正当性依据**——无法证明"这笔期货交易对冲的是哪一笔实货敞口、依据哪份经批准的方案"；同时 CAS 24 硬性要求的"正式指定 + 书面文件 + 有效性评估方法"三要素无处落地，直接命中"会计文档缺失"风险；8 号文的 90%/80% 规模红线与 12 个月期限红线也**缺少事前校验环节**。
- **上游模块**：`SPOT`（实货敞口，**唯一来源**）、`PRODUCT`（品种、额度指标、计量单位）、`AUTH`（审批人授权与岗位分离）、`CONFIG`（风控参数下发通道）
- **下游模块**：`TRADE`（交易计划是下单依据，每笔交易须绑定计划 ID）、`RISK`（计划占用额度，进入事前/事中风控）、`ACCT`（套期关系文档与有效性评估）、`AUDIT`（追溯链关键环节）

### 2.1 状态机

**套保计划**：

```
   草稿 ──提交──→ 待审批 ──审批通过──→ 已批准（生效）
     ↑                │                      │
     │            驳回│                      ├──挂起/冻结──→ 已冻结
     └────────────────┘                      │                  │
                                             │              解冻│
                                             │                  ↓
                                             │             （回到已批准）
                                             ├──全部执行完毕──→ 已完成
                                             └──终止──→ 已终止
```

| 状态 | 业务含义 | 可执行操作 | 后续状态 |
|------|---------|-----------|---------|
| **草稿** | 计划编辑中，**不占用额度**，对交易端不可见 | 修改、删除、提交审批 | 待审批 |
| **待审批** | 已提交，等待审批；**不占用额度**，不可下单 | 审批（通过/驳回）、撤回 | 已批准 / 草稿 |
| **已批准（生效）** | 计划生效，**占用额度**，可分解出交易计划并下单 | 分解交易计划、挂起/冻结、终止、查看进度 | 已冻结 / 已完成 / 已终止 |
| **已冻结** | 暂停使用，**保留已占用额度**，**不得新增下单**（已挂出委托按 `R-PLAN-5` 处理） | 解冻、终止 | 已批准 / 已终止 |
| **已完成** | 计划数量已被成交全部覆盖 | 查看、关闭 | 终态 |
| **已终止** | 计划提前结束，**释放未使用额度**；已成交部分仍须结算与会计处理 | 查看 | 终态 |

**交易计划**：

```
  待执行 ──下单──→ 执行中 ──全部成交──→ 已完成
                    │
                    └──撤销──→ 已撤销
```

| 状态 | 业务含义 | 可执行操作 | 后续状态 |
|------|---------|-----------|---------|
| **待执行** | 尚未产生任何交易指令 | 发起下单、修改（未下单时）、撤销 | 执行中 / 已撤销 |
| **执行中** | 已产生至少一笔指令 | 继续下单、撤销（未成交部分） | 已完成 / 已撤销 |
| **已完成** | 数量已全部成交 | 查看 | 终态 |
| **已撤销** | 不再执行，释放未使用额度 | 查看 | 终态 |

**状态流转规则**：见 §4 `R-PLAN-1`、`R-PLAN-2`、`R-PLAN-5`。

## 3. 功能性需求

> **编号规范**：`FR-PLAN-<序号>`，序号在**本模块内**从 1 递增，不复用。

### FR-PLAN-1 新增套保计划

- **描述**：作为财务/风控岗，我希望由实货敞口出发新增套保计划并录入其要素，以便形成合规的交易依据。
- **输入**：计划类型（商品类/贸易类）、所属子账户（必填）、套保方向、计划数量、计划期限（起止日期）、套保比率及其计算方法、所绑定的实货敞口标识（**至少一条**）、计算基准日期
- **处理规则**：见 `R-PLAN-1`（**必须从实货敞口出发**）、`R-PLAN-3`（合规预校验）、`R-PLAN-7`（子账户一致性）。初始状态为**草稿**；**套保方向必须与所绑定敞口方向相反**；**计划数量不得超过绑定敞口的未覆盖数量**；计划期限上限取「建仓日 + 12 个月」与「对应实货合同到期日 + 30 天宽限」的**较早者**（`Q-4`，源自变更 `CH-001`）
- **输出**：成功 → 计划以草稿状态创建；失败 → 明确错误（未绑定敞口 / 方向不匹配 / 数量超敞口 / 期限超生效上限 / 子账户与敞口不一致）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 绑定一条买入方向敞口（担心价格下跌需卖出套保）并录入卖出方向计划，保存成功且状态为"草稿"。
  2. 未绑定任何实货敞口即保存，被拒绝并提示"计划必须绑定实货敞口"。
  3. 计划数量超过所绑定敞口的未覆盖数量时被拒绝，提示可用数量。
  4. 计划期限设为 13 个月时被拒绝，提示"超出期限红线（建仓日 + 12 个月）"。
  5. 计划中显式携带子账户标识，且与所绑定敞口的子账户一致。

### FR-PLAN-2 修改套保计划（草稿）

- **描述**：作为财务/风控岗，我希望修改草稿状态的套保计划，以便在提交前调整方案。
- **输入**：计划标识、可修改字段（类型、方向、数量、期限、比率、绑定敞口）
- **处理规则**：**仅草稿状态可自由修改**；`待审批`状态修改须先**撤回**（`FR-PLAN-13`）；`已批准`及之后状态**不得直接修改**——须通过终止后新建，或走变更流程（`R-PLAN-6`）；修改须重新触发 `R-PLAN-3` 合规预校验
- **输出**：成功 → 计划更新；失败 → 明确错误（状态不允许 / 校验不通过 / 无权限）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 修改草稿计划的数量后保存成功。
  2. 对待审批状态的计划直接修改被拒绝，提示需先撤回。
  3. 对已批准状态的计划尝试修改被拒绝，提示须终止后新建。
  4. 修改后重新校验，若违反期限红线则拒绝保存。

### FR-PLAN-3 删除套保计划（草稿）

- **描述**：作为财务/风控岗，我希望删除作废的草稿计划，以便保持计划列表整洁。
- **输入**：计划标识
- **处理规则**：**仅草稿状态可删除**；`待审批`及之后状态**一律不得删除**（只能撤回或终止），以保留审计链；删除操作**须留痕**（记录删除人、时间、计划要素快照）
- **输出**：成功 → 计划删除；失败 → 明确错误（状态不允许 / 已产生交易 / 无权限）
- **优先级**：P1
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 删除一个草稿计划成功，列表不再显示。
  2. 删除待审批或已批准计划被拒绝并提示状态限制。
  3. 删除操作的留痕可在审计中查询到，含计划要素快照。

### FR-PLAN-4 查询套保计划列表

- **描述**：作为财务/风控岗或管理层/审批人，我希望按条件查询套保计划，以便掌握计划全景与待办。
- **输入**：筛选条件（子账户、品种、状态、计划类型、计划期限范围、创建时间范围、创建人）、排序、分页
- **处理规则**：默认按创建时间倒序；分页默认每页 20 条；**仅返回有权限的子账户范围**（管理层与审计岗可跨子账户查看，`FR-AUTH-13`）；列表须展示**计划执行进度**与**占用额度**；审批人视角默认展示"待我审批"集合
- **输出**：计划列表；空结果返回空列表
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 按"状态=待审批"筛选，结果全部为待审批计划。
  2. 列表中每行显示执行进度与占用额度，与详情页一致。
  3. 以审批人身份登录，列表默认过滤出待其审批的计划。
  4. 子账户 A 用户查询时看不到子账户 B 的计划。

### FR-PLAN-5 查看套保计划详情

- **描述**：作为财务/风控岗或管理层/审批人，我希望查看计划的完整信息，以便审批或复核。
- **输入**：计划标识
- **处理规则**：详情须含：计划要素、**绑定的实货敞口及构成明细**、套保比率计算过程（方法、ρ/σ 输入、输出、时点）、套期关系书面文件、审批链记录、分解出的交易计划与执行进度、额度占用情况；**无权限或不存在时返回统一错误**
- **输出**：计划详情；失败 → 统一错误提示
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 详情页展示套保比率的计算过程（含方法与输入参数），可供审计复现。
  2. 详情页可从计划跳转到所绑定的实货敞口详情（为追溯链提供连接点）。
  3. 详情页展示审批链中每一级的审批人、结果与时间。
  4. 查询不存在的计划返回统一错误，不泄露内部信息。

### FR-PLAN-6 按简单比率法计算套保比率

- **描述**：作为财务/风控岗，我希望用简单比率法计算套保比率，以便在敞口明确、单一品种时快速定档。
- **输入**：实货敞口标识、拟套保数量、敞口总数量
- **处理规则**：比率 = 拟套保数量 ÷ 敞口总数量；**结果须在 (0, 100%] 区间**，超出（含 0）时拒绝并提示；**计算过程必须留痕**（方法名、输入、输出、计算时点、操作人）；适用于**敞口明确、单一品种**场景
- **输出**：成功 → 返回套保比率并写入计划；失败 → 明确错误（数量非法 / 超过敞口 / 品种不唯一）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 敞口 100 吨、拟套保 60 吨，计算得 60.00%。
  2. 拟套保数量大于敞口数量时被拒绝并提示。
  3. 计算记录包含方法名、输入、输出与计算时点。
  4. 拟套保数量为 0 时被拒绝。

### FR-PLAN-7 按最小方差法计算套保比率

- **描述**：作为财务/风控岗，我希望用最小方差法 `h = ρ × σ_S / σ_F` 计算套保比率，以便在有多期价格序列时得到统计意义上的最优比率。
- **输入**：品种、现货价序列（来自 `SPOT`）、期货价序列（来自 CTP 行情）、样本区间

- **验收标准**：

  3. 终止后其下未执行的交易计划状态变为"已撤销"。
  4. 终止后 C++ 组件内存中的额度同步释放（构造一笔此前被拒、现在应可下单的指令验证）。

### FR-PLAN-18 计划期限管理与展期

- **描述**：作为财务/风控岗，我希望管理计划期限并在必要时申请展期，以便在合规前提下延续套保（**禁止盲目展期**）。
- **输入**：计划标识、新的计划期限、展期理由（**必填**）、实货合同期限依据
- **处理规则**：见 `R-PLAN-6`。期限上限取「**建仓日 + 12 个月**」与「**实货合同到期日 + 30 天宽限**」的**较早者**（配置 `risk.term.max_months=12`、`risk.term.grace_days=30`，`Q-4`，源自变更 `CH-001`）；约定期限到期前须**提前提示**（提前期见 `R-PLAN-9`）；展期**须重新走审批链**（不得自动延续）；展期理由为空时拒绝；展期属**期限变更**，**不阻断**（仅须重新审批并留痕），**接近生效上限的展期须触发复核提示**
- **输出**：成功 → 期限更新并进入待审批；失败 → 明确错误（超生效上限且无特批 / 理由缺失 / 状态不允许）
- **优先级**：P1
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 计划到期前触发提前提示（提示提前期按配置，默认 30 天）。
  2. 提交展期申请后计划进入待审批状态，须重新审批。
  3. 展期后期限超过生效上限（「建仓日 + 12 个月」与「实货合同到期日 + 30 天」取**较早者**）且未走**风控 + 财务双人特批**时被拒绝（源自变更 `CH-001`，`Q-4`）。
  4. 未填写展期理由即提交被拒绝。

### FR-PLAN-19 绑定实货敞口到套保计划

- **描述**：作为财务/风控岗，我希望把实货敞口绑定到套保计划，以便计划的正当性可追溯到具体现货来源。
- **输入**：计划标识、实货敞口标识（可多条）、每条敞口的拟覆盖数量
- **处理规则**：见 `R-PLAN-1`。**绑定的敞口必须与计划同子账户**（`R-PLAN-7`）；**每条敞口的被覆盖数量合计不得超过其未覆盖数量**；绑定时该敞口状态更新为**部分覆盖/已覆盖**（`R-SPOT-5`）；**已批准的套保计划不得静默变更绑定关系**——增删绑定须走变更并重新校验；绑定关系是 `AUDIT` 追溯链的关键连接点
- **输出**：成功 → 绑定建立并更新敞口状态；失败 → 明确错误（子账户不一致 / 超过敞口未覆盖量 / 敞口已关闭 / 计划状态不允许）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 绑定敞口后，该敞口状态由"待套保"变为"部分覆盖"，被覆盖数量等于绑定数量。
  2. 尝试绑定不同子账户的敞口被拒绝。
  3. 绑定的合计数量超过敞口未覆盖数量时被拒绝。
  4. 已批准计划上尝试直接解绑敞口被拒绝，提示须走变更流程。

### FR-PLAN-20 查询计划执行进度

- **描述**：作为财务/风控岗、期货交易岗或管理层，我希望查询计划的执行进度与偏差，以便掌握套保落地情况。
- **输入**：计划标识或筛选条件（子账户、品种、时间范围）
- **处理规则**：进度 = **已成交数量 ÷ 计划数量**，由成交回报**自动回写**（不得手工填写）；须同时展示：计划数量、已下达指令量、已成交数量、剩余可执行量、**时间进度（已过期限占比）**与**数量进度的偏差**；进度偏差超过阈值时给出提示（阈值见 `R-PLAN-10`）；不得出现"已成交数量 > 计划数量"的情形，出现即告警
- **输出**：进度视图（含量化指标与偏差提示）
- **优先级**：P1
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 计划 100 吨、成交 40 吨时进度显示 40%。
  2. 进度由成交回报自动更新，界面上无手工填写进度的入口。
  3. 时间进度 80% 而数量进度 30% 时给出落后提示。
  4. 若因异常出现已成交数量超过计划数量，系统告警。
