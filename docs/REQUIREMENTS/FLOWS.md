## FLOW-001 期现一体套保全链路闭环（端到端总览）

- **触发**：企业新签一笔采购合同，产生待套保的实货敞口
- **参与者**：财务/风控岗、审批人、期货交易岗、结算岗、资金岗、审计/合规岗、系统（C++ 交易组件 + Java 业务组件）
- **前置条件**：
  1. 品种已在 `PRODUCT` 建档并启用、已建立品种-现货品类映射与计量单位换算关系
  2. 子账户已创建并配置（品种白名单、额度指标、资金台账、数据权限）
  3. 人员已按前中后台分离原则分配角色与授权（人员名单、品种、额度齐备）
  4. CTP 连接已配置且连通；**敏感字段由用户手工录入且仅内存持有**
  5. C++ 组件已完成事前风控参数**全量预加载**
- **完成标志**：从该笔实货敞口可正向追溯到会计凭证与审计报表，链条六段无断点；规模红线、期限红线、时点净持仓校验均未触发违规

> ⚠️ **本流程体现 17 号文「期现一体」的单向结构**：
> 数据流**从实货敞口出发**匹配衍生品；
> **严禁**"先有期货成交再反找现货匹配"——那正是 17 号文点名要防的「以套保之名行投机之实」。

**异常分支**：

| 编号 | 触发条件 | 处理方式 |
|------|---------|---------|
| 1 | 第 3 步：现货品类未建立品种映射 | 该部分数据列入"未映射清单"，**不静默丢弃**；须先完成映射（`FR-PRODUCT-10`） |
| 2 | 第 5 步：最小方差法样本 < 30 个交易日 | **明确提示样本不足**，不静默降级；改选其它方法或先补录现货价（`R-SPOT-8`） |
| 3 | 第 7 步：套期关系书面文件三要素缺失 | **中断**并列出缺失项；**未生成书面文件不得提交审批**（`R-PLAN-8`） |
| 4 | 第 8 步：触及规模红线（商品类 90% / 贸易类 80%，基数 = 年度现货敞口累计量、子账户与全账户双算取严者）或期限红线（上限取「建仓日 + 12 个月」与「合同到期 + 30 天」较早者） | **阻断提交**，输出**规则编号 + 当前值 + 阈值**（`FR-RISK-4`、`FR-RISK-6`） |
| 5 | 第 9 步：审批驳回 | 计划回到草稿；**驳回原因必填**；回到第 6 步修改（`FR-PLAN-12`） |
| 6 | 第 13 步：事前风控不通过 | **直接拒绝、不发往 CTP**；拒绝记录经事件流落库（`FR-RISK-11`） |
| 7 | 第 13 步：C++ 组件重启且重放未完成 | 返回"系统未就绪"，**拒绝一切新指令**（`R-TRADE-13`） |
| 8 | 第 14 步：人工确认超时（默认 60 秒） | 指令**失效**，不发往 CTP，须重新提交（`R-TRADE-6`） |
| 9 | 第 16 步：交易理由或关联对象（计划 ID / 实货敞口 ID）缺失 | 该笔交易在追溯链中标记"**理由缺失 / 关联缺失**"，进入 `AUDIT` 违规筛查（`R-TRADE-9`、`Q-13`） |
| 10 | 第 17 步：加总对账不一致 | **告警并阻断**（差异所属子账户的新开仓、资金划拨、结算关账）；**不阻断平仓与风险处置**（`R-SETTLE-2`、`R-RISK-5`） |
| 11 | 第 18 步：实货盈亏所需现货价缺失 | **实货盈亏/估值用途：沿用最近一期并标注价格时点（"非当日价"）**；仅在无任何历史价格时标注"无法计算 + 缺失原因"并**保留实货盈亏栏位**不省略（`R-ACCT-4`、`R-ACCT-9`，`Q-12`） |
| 12 | 第 19 步：追溯链存在断点 | 输出断点清单并在报表中标注"链条不完整"，**不得**静默输出为完整（`R-AUDIT-2`） |

**备注**：

1. **本流程是总览视图**——`INDEX.md` §5.1–§5.6 是它的分段展开（便于阅读），
   `FLOW-001` 便于端到端验收（对应 `PROJECT.md` §10 成功标准 1）。
2. **子账户维度贯穿全程**：第 1、6、10、11、12、15、17、18、19 步均须携带并校验子账户标识
   （`INDEX.md` §2.1 五类红线）。
3. **组件边界在流程中的体现**：第 13–15 步跨越 C++ 与 Java 两侧——
   第 13 步**必须在 C++ 内全内存完成**，第 15 步的落库**必须由 Java 完成**（单一写库入口）。
4. **两道门禁对该流程的约束**：第 1–11 步依赖 M1 门禁（数据模型三方会签）；
   第 12–15 步依赖 M2 门禁（TCP 协议冻结）。**门禁未通过不得开工**（`PROJECT.md` §9）。
5. **本流程不含自动交易**：第 14 步的"人工确认"是**强制环节**，
   即使方案已批准也**不自动下单**（`PROJECT.md` §4.2 排除项）。
