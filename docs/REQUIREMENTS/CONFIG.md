## 1. 模块概述

- **职责**：CTP 连接配置、品种参数与风险阈值等可配置项管理；**子账户的创建、启停与参数配置**；**组件间 TCP 连接（本地回环 + 连接鉴权）配置**；**敏感字段零落盘的落地约束**；配置变更留痕与下发。
- **解决的业务问题**：不解决则**系统无法部署与调整**——CTP 前置地址、风险阈值写死在代码里，客户环境一变就得改代码；子账户无从创建；更严重的是敏感字段若落盘，直接命中"敏感信息泄露"风险，可能导致期货账户被盗用。
- **上游模块**：`AUTH`（配置类操作的权限与双人复核）
- **下游模块**：**全部模块**——配置项是各模块的运行参数；其中**风控参数、品种白名单、额度**须经控制指令下发至 C++ 内存

> ⚠️ **零落盘红线**（`PROJECT.md` §6）：
> **密码、期货认证码（AuthCode）、资金密码**——**不得写入配置文件、数据库、日志**；
> **每次启动由用户手动填写，仅内存持有**。
> **不持久化 API 下发配置**——下发给被管理端的连接配置**不落盘**；**仅本地 admin 配置可持久化**。
>
> ⚠️ **组件间 TCP 安全**（`PROJECT.md` §5.3 / §6）：
> **仅监听 `127.0.0.1`**，**不得**监听 `0.0.0.0` 或对外暴露端口；
> **必须有连接鉴权**（**不得**以无鉴权的裸 TCP 通信）。

### 2.1 状态机

**子账户**：

```
  启用 ──停用──→ 停用
   ↑               │
   └──── 启用 ──────┘
```

| 状态 | 业务含义 | 可执行操作 | 后续状态 |
|------|---------|-----------|---------|
| **启用** | 子账户可参与交易、结算、资金与权限配置 | 配置参数、停用、查看 | 停用 |
| **停用** | 子账户不可新增交易与划拨；历史数据保留且仍参与加总对账 | 启用、查看 | 启用 |

**配置下发**：

```
  已修改（Java 侧） ──下发──→ 已下发（等待回执） ──回执成功──→ 已生效
                                      │
                                  回执失败/超时
                                      ↓
                                 未生效（须告警并重试或回滚）
```

| 状态 | 业务含义 | 可执行操作 | 后续状态 |
|------|---------|-----------|---------|
| **已修改（Java 侧）** | 配置在 Java 侧已修改，尚未下发 | 下发、回滚 | 已下发 |
| **已下发** | 控制指令已发出，等待回执 | 等待、查询 | 已生效 / 未生效 |
| **已生效** | C++ 组件回执成功，内存已更新 | 查看 | 终态 |
| **未生效** | 回执失败或超时 | 重试、回滚、告警确认 | 已生效 / 终态（回滚） |

**状态流转规则**：见 §4 `R-CONFIG-3`、`R-CONFIG-5`、`R-CONFIG-8`。

## 3. 功能性需求

> **编号规范**：`FR-CONFIG-<序号>`，序号在**本模块内**从 1 递增，不复用。

### FR-CONFIG-1 配置 CTP 连接参数

- **描述**：作为系统管理员，我希望配置 CTP 柜台连接参数，以便系统对接期货公司与行情源。
- **输入**：环境类型（模拟盘/实盘）、交易前置地址、行情前置地址、经纪商代码、用户代码（资金账号）、流文件目录、**认证码 AuthCode（敏感，零落盘）**、**密码（敏感，零落盘）**
- **处理规则**：见 `R-CONFIG-1`。**非敏感项可持久化**；**AuthCode 与密码零落盘**——**不写配置文件、不入库、不写日志**，**仅内存持有**；配置保存后须提供**连接测试**（成功/失败与失败原因）；**模拟盘与实盘配置分离**且须显式标识，**防止误用实盘**；变更须留痕（**敏感字段的值不记录**）
- **输出**：成功 → 连接参数生效并可测试连接；失败 → 明确错误（地址格式非法 / 连接测试失败及原因 / 尝试持久化敏感字段被拒）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 配置连接参数后可执行连接测试，测试结果明确（成功或失败原因）。
  2. 在配置文件、数据库与日志中 **grep 不到** AuthCode 与密码明文（对应 `PROJECT.md` §10 成功标准 4）。
  3. 重启系统后须**重新手工填写**敏感字段（对应成功标准 4：重启后须重新输入）。
  4. 模拟盘与实盘配置可区分，界面上有明确标识。

### FR-CONFIG-2 敏感字段内存持有与启动手工录入

- **描述**：作为系统管理员，我希望敏感字段仅在内存持有并在启动时手工录入，以便落实零落盘红线。
- **输入**：启动时的敏感字段录入（密码、AuthCode、资金密码）、内存持有状态查询
- **处理规则**：见 `R-CONFIG-1`。**密码、AuthCode、资金密码**：**仅内存持有**；**不落配置文件、不入库、不写日志、不写核心转储**；**每次启动由用户手工填写**；**重启后须重新输入**（不得"记住"）；界面上**以掩码展示**，**不得提供"显示明文"能力**；**系统不得提供"保存凭证"选项**
- **输出**：成功 → 敏感字段载入内存，连接可用；失败 → 未填写时明确提示"须手工填写，系统不保存"
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 重启系统后进入配置页，敏感字段为空且提示"须手工填写"（对应 `PROJECT.md` §10 成功标准 4）。
  2. 全库 grep、日志 grep、配置文件审计三项检查**零命中**（对应成功标准 4）。
  3. 界面**不提供**"显示明文"或"保存凭证"的入口。
  4. 敏感字段以掩码展示。

### FR-CONFIG-3 配置本地 admin 配置持久化

- **描述**：作为系统管理员，我希望本地 admin 配置可持久化，以便重启后保留非敏感设置。
- **输入**：本地 admin 配置项（CTP 前置地址、流文件目录、组件通信地址与端口、日志级别等非敏感项）
- **处理规则**：见 `R-CONFIG-2`。**仅本地 admin 配置可持久化**；**持久化范围须显式声明**（哪些项允许落盘）；**敏感字段一律排除**在持久化范围外（系统级强制，不得配置开启）；持久化文件**权限须受限**；变更须留痕
- **输出**：成功 → 配置持久化，重启后保留（不含敏感字段）；失败 → 明确错误（尝试持久化敏感字段 / 文件权限不足）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 修改本地 admin 的非敏感配置后重启，配置保留。
  2. 持久化文件中**不含**任何敏感字段。
  3. 系统中**不存在**把敏感字段纳入持久化的配置开关。
  4. 变更留痕含配置项、前后值与操作人。

### FR-CONFIG-4 配置不下发持久化规则（API 下发配置不落盘）

- **描述**：作为系统管理员，我希望 API 下发给被管理端的配置不落盘，以便满足不持久化红线。
- **输入**：经 API 下发的连接类配置
- **处理规则**：见 `R-CONFIG-2`。**API 下发给被管理端的连接配置不落盘**；下发配置**仅存在于运行内存**；**不得**把下发配置写入本地持久化文件或数据库；下发配置与本地 admin 配置**须明确区分**（不同来源、不同持久化策略）
- **输出**：成功 → 配置生效且未落盘；失败 → 明确错误（尝试持久化下发配置被拒）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 经 API 下发的连接配置生效，但在持久化介质中**查不到**该配置。
  2. 界面上可区分"本地 admin 配置"与"下发配置"两种来源。
  3. 系统不提供把下发配置持久化的入口。
  4. 重启后下发配置**不恢复**（须重新下发）。

### FR-CONFIG-5 配置风险阈值参数

- **描述**：作为系统管理员或风控责任人，我希望集中配置风险阈值，以便风控参数可调整而不改代码。
- **输入**：规模红线比例（商品类 90% / 贸易类 80%，配置键 `sub_account.category`）、规模基数口径（`hedge.scale.base=EXPOSURE_QTY`，可选 `REVENUE`/`PURCHASE_QTY`）与scope（`hedge.scale.scope=BOTH`）、期限红线（`risk.term.max_months=12`、`risk.term.grace_days=30`、`risk.term.action=WARN_THEN_BLOCK`）、时点净持仓校验模式（`risk.position.check_mode=PRE_TRADE_AND_EOD`）、价格偏离（`risk.price.base=PREV_SETTLEMENT`、`risk.price.warn_pct=2`、`risk.price.block_pct=5`）、频繁开平仓阈值（`risk.freq.*`：日内告警 6 / 限制 10、7 日滚动回合 5、平均持仓 3 个交易日）、实货敞口分量开关（`exposure.components=CONTRACT_UNEXECUTED,INVENTORY,PRODUCTION_PLAN`）、现货价缺口策略（`spot.price.gap_calc=REJECT`、`gap_valuation=CARRY_FORWARD_LABELED`）、风险度阈值、保证金占用率阈值、限额使用率提示线（80%/95%）、重大事项触发阈值
- **处理规则**：见 `R-RISK-14`、`R-CONFIG-8`。**全部风控阈值集中配置，不得硬编码**；配置须校验**取值范围**（如比例 ∈ (0, 100%]）；**默认值须与 `PROJECT.md` 及 `INDEX.md` §9.1 的合规口径一致**（**不得把 90%/80%、12 个月、2%/5% 等默认改为更宽松的值**，若客户确需调整须**显式双人复核并留痕**）；变更须**下发 C++ 内存**并留痕（源自变更 `CH-001` / `CH-002`）
- **输出**：成功 → 阈值生效并下发；失败 → 明确错误（取值越界 / 尝试放宽合规红线而未复核 / 下发失败）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 风控阈值集中在一个配置界面可维护，非硬编码。
  2. 默认值中商品类 90%、贸易类 80%、期限 12 个月、价格偏离 2%/5% 与 `INDEX.md` §9.1 确认口径一致。
  3. 输入越界值（如比例 150%）被拒绝。
  4. 修改阈值后 C++ 内存生效（构造一笔应被新阈值拒绝的指令验证）。

### FR-CONFIG-6 配置事前风控参数并下发 C++ 组件

- **描述**：作为系统管理员，我希望把事前风控参数下发到 C++ 组件内存，以便管理操作在交易端立即生效。
- **输入**：参数类型（品种白名单、额度、阈值、启停）、参数内容、操作人
- **处理规则**：见 `R-RISK-9`、`R-CONFIG-3`。**必须显式下发，不得依赖定时轮询**；下发须**等待回执**，**无回执或失败时变更不得视为已生效**并**告警**；下发须**保证顺序**（后发不得先至覆盖新值）；下发结果（成功/失败/未确认）须留痕
- **输出**：成功 → C++ 内存更新并回执；失败 → "未生效"状态 + 告警 + 保留重试
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 修改风控参数并下发后，C++ 内存生效（构造应被拒绝的指令验证，对应 `PROJECT.md` §10 成功标准 30）。
  2. 模拟下发失败时状态为"未生效"并告警。
  3. 连续下发两次，C++ 内存最终值与最后一次一致。
  4. 下发留痕含参数类型、时间、操作人与下发结果。

### FR-CONFIG-7 配置子账户（创建 / 启用 / 停用）

- **描述**：作为系统管理员，我希望创建与管理子账户，以便按业务线划分资金、持仓与结算。
- **输入**：子账户名称、子账户编码、**子账户类别**（商品类 / 贸易类，必填，默认商品类）、初始资金、品种白名单、启用日期、业务线说明
- **处理规则**：见 `R-CONFIG-4`。子账户由**系统管理员**创建（`Q-10`，源自变更 `CH-001`），录入**名称 / 类别 / 初始资金 / 品种白名单 / 启用日期**；子账户编码**全系统唯一且不可修改**；子账户**不得物理删除，仅可停用**——**停用条件**：资金为 0、持仓为 0、无在途指令、当日已结算；**历史数据永久只读保留**并**仍参与加总对账**；彻底清除**只提供"导出归档"**；创建子账户须**双人复核**并留痕；创建后须为其建立**资金台账**（`FR-FUND-1`）与**数据权限配置**（`FR-AUTH-12`）；**生命周期管理须留痕**；子账户类别可按品种覆盖（`Q-2`）
- **输出**：成功 → 子账户创建为"启用"；失败 → 明确错误（编码重复 / 复核缺失 / 类别缺失 / 停用条件不满足 / 无权限）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 创建子账户 A、B（含类别、初始资金、品种白名单、启用日期）后，两子账户在资金、持仓、结算等处可独立使用（对应 `PROJECT.md` §9 M1 验收方式"创建两个子账户"）。
  2. 使用重复编码创建被拒绝。
  3. 尝试删除子账户被拒绝（系统不提供删除入口，只能停用）；**停用条件不满足**（资金非 0 / 有持仓 / 有在途指令 / 当日未结算）时停用被拒绝（源自变更 `CH-001`）。
  4. 创建操作有双人复核留痕。
  5. 停用后子账户历史数据**只读保留**且仍参与加总对账；可执行"导出归档"（源自变更 `CH-001`）。

### FR-CONFIG-8 配置子账户参数

- **描述**：作为系统管理员，我希望配置各子账户的参数，以便子账户按业务线特点运行。
- **输入**：子账户标识、参数项（**子账户类别**、品种白名单入口、额度指标入口、资金额度入口、初始资金、是否允许跨子账户查看的例外）
- **处理规则**：见 `R-CONFIG-4`。子账户参数**须与全局参数区分**（**子账户级参数优先于全局默认值**）；**子账户类别**（商品类 / 贸易类）默认在此设定并可**按品种覆盖**（`Q-2`，源自变更 `CH-001`），类别变更由**风控岗发起、财务负责人审批**并留痕；**额度指标支持三层限额**（子账户 + 品种 / 子账户 + 合约 / 账户 + 品种，`Q-16`，源自变更 `CH-002`）；品种白名单与额度指标实际配置在 `PRODUCT`（`FR-PRODUCT-11`、`FR-PRODUCT-12`），资金额度配置在 `FUND`（`FR-FUND-13`），本模块提供**统一入口与登记**；参数变更须留痕并**下发 C++ 内存**（凡影响事前风控的）

- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 从子账户参数页可跳转到该子账户的品种白名单、额度指标与资金额度配置。
  2. 子账户级参数在全系统生效时优先于全局默认值（构造对比场景验证）。
  3. 参数变更后 C++ 内存同步更新（影响事前风控的参数）。
  4. 变更留痕含参数项、前后值与操作人。

### FR-CONFIG-9 配置组件间 TCP 连接（回环地址、端口、鉴权）

- **处理规则**：见 `R-CONFIG-5`。**只允许监听 `127.0.0.1`**——**尝试配置 `0.0.0.0` 或对外地址时系统拒绝**（安全红线，不得通过配置放开）；**连接鉴权必须启用**——**不得**提供"关闭鉴权"的配置项；鉴权凭据**零落盘**（仅内存持有，启动手工填写）；鉴权失败须**拒绝连接并告警**；心跳与重连参数可配置
- **输出**：成功 → 连接配置生效；失败 → 明确错误（非回环地址被拒 / 未启用鉴权 / 鉴权失败告警 / 无权限）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 尝试把监听地址配置为 `0.0.0.0` 或非回环地址时被系统拒绝（对应 `PROJECT.md` §6「安全红线（4）」）。
  2. 系统中**不存在**关闭连接鉴权的配置项。
  3. 鉴权凭据在配置文件、数据库与日志中 grep 不到。
  4. 鉴权失败时拒绝连接并产生告警记录。

### FR-CONFIG-11 查询与修改系统参数

### FR-CONFIG-12 配置变更留痕

- **描述**：作为审计/合规岗，我希望查询配置变更记录，以便审计系统参数的变更是否合规。

- **处理规则**：见 `R-CONFIG-2`。留痕须含**配置项、变更前后值、操作人、复核人、时间、原因、下发结果**；**敏感字段的值一律不记录**（仅记录"已设置/已重置"这类状态变化）；记录**只增不改不删**；**不得**提供删除入口；进入 `AUDIT`（对应 `R-AUDIT-3`）

- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 修改一个非敏感配置后，记录中出现该变更的前后值（对应 `PROJECT.md` §10 成功标准 15 的授权变更留痕口径）。
  2. 修改敏感字段的记录中**不出现**其取值。
  3. 记录中不存在编辑或删除入口。
  4. 可按配置分类与时间范围筛选。

### FR-CONFIG-13 系统参数导入导出
