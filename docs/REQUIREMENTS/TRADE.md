## 1. 模块概述

- **职责**：按已批准的套保计划执行期货/期权交易——对接 CTP 柜台下单、**人工确认后发出**、每笔交易绑定计划与子账户、记录交易理由形成正当性证据。
- **解决的业务问题**：不解决则套保方案**无法落地**，同时"每笔交易可自证正当性"无从实现——交易所问询"为何频繁开平仓"时拿不出证据；且交易路径一旦引入数据库 I/O 或锁竞争，将破坏高频路径的确定性，风控判定无法在下单前可靠完成。
- **上游模块**：`PLAN`（交易计划是下单依据）、`PRODUCT`（品种白名单与合约）、`RISK`（事前风控的规则与内存参数）、`AUTH`（交易岗授权：人员名单、品种、额度）、`CONFIG`（控制指令通道）
- **下游模块**：`SETTLE`（成交明细是结算核对输入）、`RISK`（事件流构建事中镜像状态）、`ACCT`（交易结果用于会计处理）、`AUDIT`（追溯链核心环节）、`PLAN`（额度占用与进度回写）

> ⚠️ **架构红线**（`PROJECT.md` §5.0 / §6）：
> 交易路径**全内存**——从客户指令到发往 CTP，**C++ 组件不得访问数据库**；
> **单一写库入口**——成交回报与额度扣减经**事件流**推给 Java，由 **Java 统一写入达梦**；
> **人工确认**——即使方案已批准也**不得自动下单**（`PROJECT.md` §4.2 排除自动交易）。

### 2.1 状态机

**交易指令 / 委托**：

```
  待确认 ──人工确认──→ 已提交 ──事前风控通过──→ 已发送 CTP ──→ 部分成交 ──→ 全部成交
     │                    │                          │
     │               风控拒绝 │                      ├──已撤销
     │                    ↓                          └──已拒绝（CTP 拒绝）
  已失效（超时未确认）  已拒绝（事前风控）                 │
                                                      已失效（部分成交后剩余作废）
```

| 状态 | 业务含义 | 可执行操作 | 后续状态 |
|------|---------|-----------|---------|
| **待确认** | 已通过事前风控，等待交易岗人工确认 | 人工确认、放弃 | 已提交 / 已失效 |
| **已拒绝（事前风控）** | 事前风控不允许，**未发往 CTP** | 查看拒绝原因 | 终态 |
| **已提交** | 已人工确认，正在发出 | 等待回报 | 已发送 CTP |
| **已发送 CTP** | 已发往柜台，等待委托回报 | 撤单（未成交部分） | 部分成交 / 全部成交 / 已撤销 / 已拒绝（CTP） |
| **部分成交** | 部分数量已成交 | 撤单（剩余部分） | 全部成交 / 已撤销（剩余作废） |
| **全部成交** | 全量成交 | 查看 | 终态 |
| **已撤销** | 未成交部分已撤销 | 查看 | 终态 |
| **已失控/已失效** | 超时未确认或异常失效 | 查看 | 终态 |

**状态流转规则**：见 §4 `R-TRADE-1`、`R-TRADE-2`、`R-TRADE-4`。

## 3. 功能性需求

> **编号规范**：`FR-TRADE-<序号>`，序号在**本模块内**从 1 递增，不复用。

### FR-TRADE-1 提交交易指令（绑定计划与子账户）

- **描述**：作为期货交易岗，我希望基于已批准的交易计划提交交易指令并显式携带计划 ID 与子账户标识，以便每笔交易可追溯至套保计划与实货敞口。
- **输入**：交易计划 ID（必填）、子账户标识（必填，默认取自交易计划且**显式写入指令**）、合约、买卖方向、开平标志、数量、指令类型（限价/市价）、价格（限价时必填）
- **处理规则**：见 `R-TRADE-1`、`R-TRADE-5`。**无交易计划 ID 或子账户标识的指令一律拒绝**（不得由会话或计划间接推导）；合约必须属于该交易计划所指定的品种且为**境内场内**；数量必须为正且**累计不超过该交易计划的剩余可下单量**；方向必须与交易计划一致。指令创建后状态为**待确认**并**立即触发事前风控校验**（`FR-TRADE-3`）
- **输出**：成功 → 指令创建为待确认并返回风控校验结果；失败 → 明确错误（缺计划 ID / 缺子账户 / 合约与品种不符 / 数量超剩余可下单量 / 方向不符 / 非场内合约）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 提交一条绑定交易计划 P 与子账户 A 的指令，创建成功且指令记录中**自身携带**计划 ID 与子账户标识。
  2. 不传交易计划 ID 时被拒绝，提示"交易指令必须绑定套保计划"。
  3. 数量超过该交易计划剩余可下单量时被拒绝并提示剩余量。
  4. 选择交易计划品种之外的合约时被拒绝。
  5. 指令方向与交易计划方向相反时被拒绝。

### FR-TRADE-2 人工确认后发出交易指令

- **描述**：作为期货交易岗，我希望在指令发出前显式人工确认，以便留下正当性证据并避免误发（**系统不做自动交易**）。
- **输入**：指令标识、确认动作
- **处理规则**：见 `R-TRADE-2`。**未确认的指令不得发往 CTP**；确认前须再次执行**完整事前风控校验**（防止确认期间状态变化）；确认超时（超时阈值见 `R-TRADE-6`，默认 60 秒）后指令**自动失效**，不得发出；确认动作留痕（确认人、时间、被确认指令要素）；确认通过后指令状态→已提交并**由 C++ 组件发往 CTP**
- **输出**：成功 → 指令发出并进入等待回报；失败 → 明确错误（未通过风控 / 已超时 / 无权限 / CTP 不可用 → 指令退回并保留）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 未执行人工确认的指令在超时后变为"已失效"，且**未发往 CTP**（CTP 侧无对应报单记录）。
  2. 确认后指令发往 CTP，返回委托回报。
  3. 确认动作留痕含确认人与时间。
  4. CTP 不可用时指令**不被静默丢弃**，状态明确（退回/待发）且给出提示。
  5. 系统内不存在"自动下单"入口（方案已批准也不自动下单）。

### FR-TRADE-3 事前风控校验交易指令

- **描述**：作为期货交易岗与风控责任人，我希望每笔指令在发出前由 C++ 组件以**全内存**方式完成风控校验，以便在下单前阻断违规操作且不引入数据库延迟。
- **输入**：待校验指令（品种、合约、子账户、数量、方向、价格）、C++ 内存中的白名单/额度/持仓/参数
- **处理规则**：见 `R-TRADE-3`、`RISK.md` `R-RISK-2`。校验项：① 品种白名单 ② 可用额度（**三层限额：子账户 + 品种 / 子账户 + 合约 / 账户 + 品种**，`Q-16`，源自变更 `CH-002`）③ 持仓上限 ④ 规模红线（商品类 90% / 贸易类 80%，基数 = 年度现货敞口累计量，子账户与全账户双算取严者，`Q-1`）⑤ 时点净持仓 ≤ 实货敞口（**下单瞬间 + 日终复核**，敞口取当日最新快照并标注快照时点，`Q-3`，源自变更 `CH-001`）⑥ 期限匹配（上限取「建仓日 + 12 个月」与「合同到期 + 30 天」**较早者**，`Q-4`）⑦ 交易权限与授权 ⑧ 价格偏离（基准 = **昨结算价**，**(2%, 5%] 告警 + 二次确认，> 5% 阻断**，`Q-15`，源自变更 `CH-002`）。**全部为纯内存判断，指令路径零数据库 I/O**；**任一不通过 → 直接拒绝，不发送 CTP**；拒绝记录经事件流上报 Java 落库
- **输出**：通过 / 告警 + 二次确认 / 拒绝 → 返回**规则编号 + 拒绝原因**（如品种未在白名单 / 限额层级不足 / 超期限 / 权限不足 / 价格偏离超限）；C++ 重启未完成重放时返回"系统未就绪"
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 构造超额度指令，事前风控拒绝且**未发往 CTP**（对应 `PROJECT.md` §10 成功标准 24）。
  2. 构造"子账户 + 品种超限""子账户 + 合约超限""账户 + 品种超限"三种场景，**均能阻断**（对应成功标准 35，源自变更 `CH-002`，`Q-16`）。
  3. 品种不在该子账户白名单时拒绝。
  4. 拒绝记录可在 Java 侧查询到（证明事件流已上报落库）。
  5. 从下达指令到发往 CTP 的路径中**不产生任何数据库 I/O**（对应成功标准 23）。

### FR-TRADE-4 接收委托回报

- **描述**：作为期货交易岗，我希望系统接收并展示 CTP 委托回报，以便掌握指令在柜台的处理状态。
- **输入**：CTP 推送的委托回报（报单编号、状态、已成交数量、错误信息）
- **处理规则**：见 `R-TRADE-4`。委托回报须**幂等处理**（重复回报不得产生重复状态变更或重复数量计入）；状态映射到 §2.1 状态机；回报经**事件流**推送至 Java 落库；CTP 拒绝的委托须保留 CTP 侧错误信息原文
- **输出**：委托状态更新；失败 → CTP 返回错误时记录错误信息并状态置为"已拒绝（CTP）"
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 发出指令后收到委托回报，委托状态按回报更新。
  2. 同一委托回报重复推送两次，系统状态与数量**不重复计入**（幂等）。
  3. 被 CTP 拒绝的委托，状态为"已拒绝（CTP）"并展示柜台错误信息。
  4. 委托回报可在 Java 侧数据库中查询到（单一写库入口）。

### FR-TRADE-5 接收成交回报

- **描述**：作为期货交易岗与结算岗，我希望系统接收并记录成交回报，以便形成结算核对与会计处理的原始依据。
- **输入**：CTP 推送的成交回报（成交编号、合约、方向、开平、价格、数量、成交时间、子账户标识）
- **处理规则**：见 `R-TRADE-4`（幂等）、`R-TRADE-3`（事件流与单一写库）。成交记录**不得修改、不得删除**（结算与审计的原始依据）；成交须**扣减可用额度**并**回写交易计划执行进度**（`FR-TRADE-11`）；成交须**按子账户归集**，子账户标识由指令携带并随成交写入
- **输出**：成交记录创建并更新持仓、额度与计划进度
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 成交后成交记录创建，字段与 CTP 回报一致。

### FR-TRADE-18 导出交易记录

- **描述**：作为期货交易岗、结算岗或审计/合规岗，我希望导出交易记录，以便线下核对与提供合规材料。
- **输入**：导出口径（时间范围、子账户、合约、品种）、字段选择
- **处理规则**：**仅导出有权限的子账户范围**；导出字段含**套保计划编号、交易计划编号、实货敞口编号、子账户、合约、方向、开平、成交价量、时间、交易理由**（保证导出即为可自证的证据链片段）；文件含导出时间与导出人；无数据时不生成空文件
- **输出**：CSV 文件；失败 → 明确提示
- **优先级**：P1
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 导出某子账户某日交易记录，条数与列表一致。
  2. 导出字段包含套保计划编号、交易计划编号、实货敞口编号与交易理由列。
  3. 无数据时不生成文件并给出提示。
  4. 子账户 A 用户导出时不包含子账户 B 的数据。

## 4. 模块内规则

| 规则编号 | 规则内容 | 适用 FR | 说明 |
|---------|---------|---------|------|
| `R-TRADE-1` | **交易必须绑定计划与子账户（⬅ 正当性红线）**：任何交易指令**必须**显式携带**交易计划 ID**与**子账户标识**；**无计划 ID 的指令一律拒绝**；**禁止**创建"无计划"的裸指令；子账户标识**不得**由会话、用户或平台信息间接推导，须随指令显式写入并随成交传递 | `FR-TRADE-1`、`FR-TRADE-5`、`FR-TRADE-13` | `INDEX.md` §2.1「交易类」；`PROJECT.md` §4.1.C「④ 交易」 |
| `R-TRADE-2` | **人工确认门禁**：每笔指令（含期权各腿）**必须经交易岗显式人工确认**后方可发往 CTP；**系统不提供自动下单**；确认超时（默认 60 秒）自动失效；确认动作留痕 | `FR-TRADE-2`、`FR-TRADE-13` | `PROJECT.md` §4.2 排除自动交易；"人工确认"本身是正当性证据 |
| `R-TRADE-3` | **交易路径全内存 · 单一写库入口（架构红线）**：从指令到发往 CTP 的路径中 **C++ 组件不得访问数据库**、不得引入阻塞调用或重锁竞争；事前风控所需数据（品种、额度、持仓、参数）**常驻 C++ 内存**；成交回报、额度扣减、事前风控拒绝记录**经事件流推给 Java**，由 **Java 统一写库** | `FR-TRADE-3`、`FR-TRADE-5`、`FR-TRADE-11`、`FR-TRADE-14` | `PROJECT.md` §5.0 / §6「交易路径全内存」「单一写库入口」；核心架构约束 |
| `R-TRADE-4` | **回报幂等与顺序**：委托回报、成交回报**必须幂等处理**——同一回报重复推送时**不得**重复变更状态或重复计入数量；事件流须保证**不丢、不乱序**；断连重连后**补数据**并最终一致 | `FR-TRADE-4`、`FR-TRADE-5`、`FR-TRADE-14` | `PROJECT.md` §10 成功标准 31、32 |
| `R-TRADE-5` | **数量与方向约束**：指令数量为正且**累计不超过交易计划剩余可下单量**；方向必须与交易计划一致；平仓数量不得超过该子账户该合约的**可用持仓**；**期权适用同一约束** | `FR-TRADE-1`、`FR-TRADE-6`、`FR-TRADE-13` | `PROJECT.md` §6「期权附加约束」 |
| `R-TRADE-6` | **超时与失效口径**：待确认指令超时（默认 60 秒）→ **已失效**，不得发出；已发出但长时间无回报的指令须**告警并纳入稽核**（不得静默等待） | `FR-TRADE-2`、`FR-TRADE-16` | 防止指令滞留造成状态不可解释 |
| `R-TRADE-7` | **撤单口径**：仅**未成交部分**可撤；撤单成功后**释放对应额度**并**回退交易计划的可下单量**；已成交部分不可撤销；撤单动作留痕 | `FR-TRADE-6`、`FR-TRADE-11` | 与 `FR-PLAN-14` 的可下单量口径对应 |
| `R-TRADE-8` | **持仓按子账户可比**：持仓须**按子账户分别记账**并**可直接求和**；须提供汇总视图；汇总值必须等于子账户明细之和（为 `FR-SETTLE-8` 加总对账提供基础） | `FR-TRADE-9`、`FR-TRADE-11` | `INDEX.md` §2.1「持仓类」；`PROJECT.md` §4.1.B 关键风险 |
| `R-TRADE-9` | **交易理由留痕**（源自变更 `CH-002`，`Q-13`；语义澄清与校验时点见 `CH-004`）：交易理由 = **结构化必填 + 可选补充说明**——① 关联类型必选 ② 关联对象必选（计划 ID + 实货敞口 ID，须归属**同一子账户**）③ 时点说明必选；**提交时校验不通过即拒绝**（**"关联对象必选"的强制性不变**——缺关联对象 → 拒单）；**数据层允许补填态 / 异常态**——关联对象可空，但该记录**必须带关联对象缺失标记**（`related_object_missing_flag='Y'`，**条件非空**）；**理由缺失（`REASON_MISSING`）与关联缺失（`RELATED_MISSING`）为两个并列独立维度**，不得合并。**归属同一子账户的校验时点三层**：① **权威 = 指令提交时**（Java，DB 事务内，不通过即拒单）② **兜底 = 指令下发 C++ 前**（C++ 事前风控，纯内存，`0x1019`）③ **落库复核 = 理由落库时**（Java，事件流 / 补填写入）；**不得只依赖 C++**（C++ 不访问 DB）。与指令/成交关联并**永久留痕**；**不得事后静默修改**（修改须留痕并保留前后值）；**理由缺失 / 关联缺失的交易须在追溯链中显式标记**并进入违规筛查 | `FR-TRADE-10`、`FR-AUDIT-4` | "每笔交易可自证正当性"（`PROJECT.md` §10 成功标准 2） |
| `R-TRADE-10` | **额度占用三态口径与三层限额**（源自变更 `CH-002`，`Q-16`）：**下单冻结 → 成交扣减 → 撤单释放**；额度权威源为 **C++ 内存**；落库由 Java 完成；**三层限额同时校验**——① 子账户 + 品种（主维度）② 子账户 + 合约（可选）③ 账户 + 品种（总账户，防串用），**单笔按最细命中者、累计任一超限即拒绝** | `FR-TRADE-11`、`FR-TRADE-3` | `PROJECT.md` §4.1 ⑥-a「子账户维度校验」；`Q-16` 已确认 |
| `R-TRADE-11` | **行情零外部依赖且不驱动决策**：行情**只来自 CTP**；过期行情须显式标识；**行情不用于任何自动决策**，系统不做行情分析/预测，也不自动下单 | `FR-TRADE-12` | `PROJECT.md` §4.2 排除行情分析；§6「数据来源」 |
| `R-TRADE-12` | **期权与期货同链同额**：期权各腿与期货交易**共用同一追溯链**（同样绑定套保计划 ID 与实货敞口 ID）与**同一套保额度**；**不得**把期权做成独立旁路 | `FR-TRADE-13` | `PROJECT.md` §6「期权附加约束」 |
| `R-TRADE-13` | **崩溃恢复先重放后服务**：指令流水落盘 + 启动重放；**重放未完成期间拒绝一切新指令**；重放须与 CTP 侧状态核对，**不得**重复计入或漏计；对账不一致时**拒绝服务并告警**（不得带病运行） | `FR-TRADE-15`、`FR-TRADE-3` | `PROJECT.md` §6「全内存崩溃恢复」；对应成功标准 27 |
| `R-TRADE-14` | **拒绝记录不可丢失**：事前风控拒绝记录**必须**经事件流上报 Java 落库；**只增不改不删**；支持按规则编号统计 | `FR-TRADE-17`、`FR-TRADE-3` | 合规证据（8 号文「阻断违规操作」的证据面） |
| `R-TRADE-15` | **已成交与成交类记录不可修改**：委托、成交、指令流水、拒绝记录**一律只增不改不删**；系统**不得**提供任何修改或删除入口 | `FR-TRADE-5`、`FR-TRADE-8`、`FR-TRADE-16`、`FR-TRADE-17` | 追溯链完整性（`PROJECT.md` §10 成功标准 16） |
| `R-TRADE-16` | **仅境内场内**：合约范围为**境内场内**期货与期权；**不得**接入境外或场外衍生品 | `FR-TRADE-1`、`FR-TRADE-13` | `PROJECT.md` §4.2「不做境外/场外衍生品」 |
