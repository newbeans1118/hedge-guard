## 1. 模块概述

- **职责**：用户、角色与授权管理；**前中后台岗位/人员分离**；授权须明确**人员名单、品种、额度**；**子账户数据权限（软隔离）**；**严禁企业负责人直接操盘**。
- **解决的业务问题**：不解决则**岗位分离形同虚设**——同一人可同时下单、审批与结算，8 号文四(一)硬要求落空；企业负责人可绕过内控直接操盘；子账户数据无隔离，各业务线数据互相可见；授权变更无留痕，审计无法证明内控有效性。
- **上游模块**：`CONFIG`（子账户定义）
- **下游模块**：**全部模块**（权限判定、子账户数据可见性、审批与复核资格、事前风控的权限快照）

> ⚠️ **硬约束**（`PROJECT.md` §3 / §6）：
> **财务/风控岗、交易岗、结算岗三者不得由同一人担任**；
> **严禁企业负责人直接操盘**；**不得提供"超级管理员一键通办"的便利后门**。
> 子账户数据为**软隔离**——默认互不可见，**经授权角色（管理层、审计岗）可跨子账户查看**。

## 2. 数据字典

> ⚠️ **边界红线**：本节只写**业务概念**——业务名称、业务语义、业务约束、
> 枚举值的**业务含义**。**不写**列名、数据类型、长度、索引、存储格式。

| 数据项 | 业务名称 | 业务语义 | 业务约束 | 枚举值的业务含义 |
|--------|---------|---------|---------|--------------|
| 用户 | 用户 | 系统内的一个操作账号，对应企业的一名岗位人员 | 用户名在全系统唯一；**一个自然人只应有一个账号**（便于岗位分离判定）；用户**不得物理删除**，只能停用 | 状态：**启用**／**停用** |
| 角色 | 角色 | 一组职责与权限的集合 | 系统预置**六类业务角色**（见下）+ 系统管理员；**角色是岗位分离判定的单位**；核对任务的应签角色映射为 **风控岗（发起 + 核对）/ 交易岗（确认持仓成交）/ 财务岗（确认资金账务）/ 管理层（签收）/ 审计岗（年度全覆盖）**（`Q-14`，源自变更 `CH-002`） | **财务/风控岗**／**期货交易岗**／**结算岗**／**资金岗**／**管理层（审批人）**／**审计/合规岗**／**系统管理员** |
| 岗位组 | 岗位组 | 角色按前中后台归并的类别，用于互斥判定 | **交易岗、风控岗、结算岗三者两两互斥**（8 号文硬要求）；资金岗与交易岗互斥（`R-AUTH-3`）；**管理层的签署权与交易权互斥**（`Q-14`）；互斥判定以**岗位组**为单位 | **前中台（交易）**／**中台（风控、结算、资金）**／**后台（审计）**／**管理（审批，仅签收不操盘）**／**系统（管理员）** |
| 签署权与交易权互斥 | 签署权与交易权互斥 | 管理层（审批人）对核对/季度报告的电子签署权，与期货交易（操盘）能力互斥 | **管理层只能签收报告，不得操盘**；系统须强制——管理层账号**不得**被授予交易岗角色、**不得**执行下单操作；核对任务签署须与应签角色账号一致且**不可代签**（`Q-14`，源自变更 `CH-002`） | — |
| 权限 | 权限 | 对某个功能或数据的操作许可 | 授权须明确**人员名单、品种、额度**（8 号文 四(二)）；**未授权的操作一律拒绝** | 权限类别：**功能权限**（模块与操作）／**数据权限**（子账户、品种）／**额度权限** |
| 岗位分离约束 | 岗位分离约束 | 互斥岗位不得同时授予同一用户 | **系统级强制**——不得仅靠制度；**不得**提供"一键通办"的不受限账号；违规配置须**拒绝保存** | — |
| 企业负责人标记 | 企业负责人标记 | 标识该用户为企业负责人（法定代表人/董事长/总经理等） | **被标记的用户不得被授予交易岗权限，且不得直接下单**；标记变更须留痕 | — |
| 授权记录 | 授权记录 | 明确到人员名单、品种、额度的授权明细 | **必须明确三类信息**；授权是事前风控权限校验的输入（`FR-RISK-7`）；授权变更须**及时下发 C++ 内存**（`FR-RISK-10`） | — |
| 子账户数据权限 | 子账户数据权限 | 用户可查看/操作的子账户范围 | **默认仅限被指定的子账户**（软隔离）；**未指定时默认无任何子账户可见**（安全默认，不得默认全可见） | 类型：**限定子账户**／**跨子账户查看** |
| 跨子账户查看权限 | 跨子账户查看权限 | 可查看全部（或被指定多个）子账户数据的权限 | **仅管理层与审计/合规岗可被授予**；授予须**双人复核**并留痕；**查看权限不等于操作权限**（跨子账户默认只读） | — |
| 软隔离 | 软隔离 | 子账户数据默认互不可见，授权角色可跨账户查看 | 须支持"限定到指定子账户"；**不得**做成硬隔离（管理层与审计岗需总览） | — |
| 登录会话 | 登录会话 | 用户登录后的身份会话 | 会话有**空闲超时**；超时须重新认证；**不得**以"记住我"长期免登录 | — |
| 口令 | 口令 | 用户的登录凭证 | **以加盐哈希存储**；**明文口令不得出现在任何日志与持久化文件中**（`NFR-SEC-1`）；强度策略见 `R-AUTH-5` | — |
| 登录失败计数 | 登录失败计数 | 连续登录失败次数 | 连续 **5 次**失败**锁定 5 分钟**（策略可配置）；锁定事件留痕 | — |
| 越权尝试记录 | 越权尝试记录 | 被系统拒绝的越权操作尝试 | **必须记录**（操作人、时间、尝试的操作、拒绝原因）；进入 `AUDIT`；**只增不改不删** | — |
| 权限变更留痕 | 权限变更留痕 | 角色、授权、子账户权限变更的记录 | 须含**变更前后值、操作人、时间、原因**；**只增不改不删**；进入 `AUDIT` | — |

### 2.1 状态机

**用户**：

```
  启用 ──停用──→ 停用
   ↑               │
   └──── 启用 ──────┘
```

| 状态 | 业务含义 | 可执行操作 | 后续状态 |
|------|---------|-----------|---------|
| **启用** | 用户可登录并按权限操作 | 修改、分配角色、配置子账户权限、停用 | 停用 |
| **停用** | 用户不可登录；历史操作记录保留 | 启用、查看 | 启用 |

**授权记录**：

```
  草稿 ──提交──→ 待复核 ──复核通过──→ 生效 ──到期/撤销──→ 已失效
                    │
                驳回↓
                  已驳回
```

| 状态 | 业务含义 | 可执行操作 | 后续状态 |
|------|---------|-----------|---------|
| **草稿** | 授权已录入未提交 | 修改、删除、提交 | 待复核 |
| **待复核** | 等待复核（**授权变更须双人复核**） | 复核（通过/驳回）、撤回 | 生效 / 已驳回 |
| **生效** | 授权已生效并已下发 C++ 内存 | 查看、撤销、修改（走变更） | 已失效 |
| **已失效** | 已被撤销或到期 | 查看 | 终态 |
| **已驳回** | 复核未通过 | 查看、修改后重新提交 | 终态 |

**状态流转规则**：见 §4 `R-AUTH-1`、`R-AUTH-4`、`R-AUTH-9`。

## 3. 功能性需求

> **编号规范**：`FR-AUTH-<序号>`，序号在**本模块内**从 1 递增，不复用。

### FR-AUTH-1 新增用户

- **描述**：作为系统管理员，我希望新增用户账号，以便为岗位人员开通系统访问。
- **输入**：用户名（全系统唯一）、姓名（**一个自然人一个账号**）、所属部门、是否企业负责人、初始口令（首次登录须强制修改）、初始角色
- **处理规则**：见 `R-AUTH-1`、`R-AUTH-2`。用户名重复即拒绝；**企业负责人标记**须显式选择（影响后续权限约束 `FR-AUTH-9`）；初始口令**以加盐哈希存储**，**不得明文留存**；新增后默认**不授予任何子账户数据权限**（安全默认）；新增操作留痕
- **输出**：成功 → 用户创建为"启用"状态；失败 → 明确错误（用户名重复 / 姓名缺失 / 初始口令不符合强度 / 无权限）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 新增用户后可用初始口令登录，且系统强制要求首次登录修改口令。
  2. 使用已存在的用户名新增被拒绝。
  3. 新增用户后，该用户默认看不到任何子账户数据（需显式授权）。
  4. 库中与日志中**不存在**明文初始口令（`PROJECT.md` §10 成功标准 4）。

### FR-AUTH-2 修改用户

- **描述**：作为系统管理员，我希望修改用户的基础信息，以便与人员变动保持一致。
- **输入**：用户标识、可修改字段（姓名、部门、企业负责人标记）
- **处理规则**：**用户名不可修改**；**企业负责人标记的变更**须**双人复核**并留痕（该标记直接关联"严禁负责人直接操盘"的强约束）；**一个自然人不得存在多个账号**（发现重复须合并并留痕）；修改操作留痕
- **输出**：成功 → 信息更新并留痕；失败 → 明确错误（尝试修改用户名 / 复核缺失 / 存在重复自然人 / 无权限）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 修改姓名与部门后保存成功并留痕。
  2. 尝试修改用户名被拒绝。
  3. 修改企业负责人标记须经双人复核，复核缺失时被拒绝。
  4. 尝试为同一自然人创建第二个账号时给出重复提示。

### FR-AUTH-3 停用用户

- **描述**：作为系统管理员，我希望停用离职或调岗人员的账号，以便收回访问权限。
- **输入**：用户标识、停用原因（必填）
- **处理规则**：见 `R-AUTH-1`。**停用前置校验**：该用户**不得存在在进行中的关键操作**（未复核的资金申请、待确认的交易指令）——存在时须先处理或明确移交；停用后**立即失效其登录会话**并**下发权限变更至 C++ 内存**；历史操作记录**全部保留**（不得删除）；停用操作留痕
- **输出**：成功 → 用户状态"停用"且立即无法登录；失败 → 明确错误（存在进行中操作 / 原因缺失 / 无权限）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 停用用户后其登录会话立即失效，无法登录。
  2. 该用户存在未复核的资金申请时，停用被拒绝并列出待处理事项。
  3. 用户的历史操作记录在停用后仍可查询。
  4. 停用后 C++ 内存中的权限快照同步移除该用户。

### FR-AUTH-4 启用用户

- **描述**：作为系统管理员，我希望重新启用已停用的账号，以便人员复岗（**反向操作，不得遗漏**）。
- **输入**：用户标识
- **处理规则**：启用前须**重新确认角色与授权**（原授权可能已失效）；启用后**默认不恢复**原授权内容，须显式重新配置（避免复岗即获旧权限的风险）；**须强制重置口令**；启用操作留痕
- **输出**：成功 → 状态"启用"并要求首次登录改口令；失败 → 明确错误（未重新配置角色 / 无权限）
- **优先级**：P1
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 启用用户后须重置口令，首次登录强制修改。
  2. 启用后该用户默认无任何子账户数据权限，须显式授权。
  3. 启用操作留痕含操作人与时间。
  4. 未配置角色即启用时给出提示。

### FR-AUTH-5 查询用户列表

- **描述**：作为系统管理员或审计/合规岗，我希望查询用户及其角色与授权概况，以便管理账号与核对授权。
- **输入**：筛选条件（用户名/姓名关键字、角色、状态、是否企业负责人、子账户）、排序、分页
- **处理规则**：默认按创建时间倒序；分页默认每页 20 条；列表须展示**角色、子账户授权范围、企业负责人标记、最后登录时间**；**不展示任何口令相关信息**；审计岗可查看（只读）
- **输出**：用户列表；空结果返回空列表
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 按角色筛选结果正确。
  2. 列表展示每个用户的子账户授权范围与企业负责人标记。
  3. 列表与详情中**不出现**任何口令字段或口令提示信息。
  4. 审计岗可只读查看用户列表。

### FR-AUTH-6 定义角色

- **描述**：作为系统管理员，我希望定义与维护角色，以便把功能权限按岗位归集。
- **输入**：角色名称、所属岗位组、功能权限集合（模块与操作）
- **处理规则**：系统**预置六类业务角色 + 系统管理员**（见 §2.1 数据字典），**预置角色不得删除**（可调整权限）；角色须归属**岗位组**以支持互斥判定；**系统管理员角色的权限不含业务操作**（不含交易、审批、风控判定）——防止"一键通办"后门；角色变更须留痕
- **输出**：成功 → 角色创建/更新；失败 → 明确错误（名称重复 / 权限包含越界项 / 无权限）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 系统预置六类业务角色与系统管理员角色，且预置角色不可删除。
  2. 尝试为系统管理员角色添加"交易下单"权限被拒绝。
  3. 角色须选择岗位组，未选择时无法保存。
  4. 角色变更留痕含操作人、时间与前后值。

### FR-AUTH-7 配置岗位分离互斥（前中后台）

- **描述**：作为系统管理员，我希望配置岗位组的互斥关系，以便系统级强制前中后台分离。
- **输入**：岗位组、互斥组设置（交易岗 / 风控岗 / 结算岗两两互斥；资金岗与交易岗互斥）
- **处理规则**：见 `R-AUTH-3`。**互斥关系为系统级强制**，**不得提供关闭互斥的配置开关**（8 号文硬要求）；默认互斥集见 `R-AUTH-3`；互斥配置变更须留痕且须双人复核
- **输出**：成功 → 互斥关系生效；失败 → 明确错误（尝试关闭强制互斥 / 无权限）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 系统默认配置交易岗、风控岗、结算岗两两互斥。
  2. 系统中**不存在**关闭互斥关系的开关或配置项。
  3. 互斥关系变更须双人复核并留痕。

### FR-AUTH-8 校验岗位分离约束

- **描述**：作为系统管理员，我希望系统在分配角色时自动拒绝互斥岗位，以便从源头防止一人多岗。
- **输入**：用户标识、待分配角色
- **处理规则**：见 `R-AUTH-3`。分配角色时**自动校验互斥**——若该用户已具备互斥岗位的角色，则**拒绝分配**并说明冲突；**不得**以"临时授权""代班"等理由绕过（**不得**提供绕过通道）；拒绝事件记入越权尝试记录；**超级管理员不受限的例外不存在**——系统管理员本身不得拥有业务角色
- **输出**：成功 → 角色分配成功；失败 → 明确错误（与已有角色互斥，列出冲突角色 / 系统管理员不得兼业务角色）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 给已有交易岗角色的用户分配风控岗角色被拒绝，并列出冲突角色（对应 `PROJECT.md` §10 成功标准 15）。
  2. 给已有交易岗角色的用户分配结算岗角色被拒绝。
  3. 系统内不存在绕过互斥校验的入口。
  4. 拒绝事件在越权尝试记录中可查询。

### FR-AUTH-9 禁止企业负责人直接操盘

- **描述**：作为系统管理员与审计/合规岗，我希望系统级禁止企业负责人直接操盘，以便满足 8 号文要求。
- **输入**：用户的企业负责人标记、待分配角色/待执行交易操作
- **处理规则**：见 `R-AUTH-2`、`R-AUTH-13`。**被标记为企业负责人的用户**：① **不得被授予交易岗角色**（分配时直接拒绝）② **不得执行交易下单操作**（即使通过其他途径尝试，事前风控亦拒绝，`FR-RISK-7`）③ 可被授予**管理层（审批）**或**跨子账户查看**权限；**管理层账号同样只能签收报告、不得操盘**（签署权与交易权互斥，`Q-14`，源自变更 `CH-002`）；标记的设定与变更须**双人复核**并留痕；尝试违规须记入越权尝试记录。**操盘拒绝判据为「析取」（`CH-010` 澄清）**：「被标记为**企业负责人**」与「持有**管理层（审批人）**角色」是**两个各自独立**的拒绝条件——满足**任一**即拒绝操盘，**不得**解读为二者须**同时**满足（字段承载：企业负责人标记 / 管理层角色；具体列名以 `DATA_MODEL.md` 为准）
- **输出**：成功 → 配置被拒绝并说明约束；失败 → 明确错误（企业负责人/管理层不得持交易岗）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 给企业负责人标记的用户分配交易岗角色被拒绝（对应 `PROJECT.md` §10 成功标准 15）。
  2. 企业负责人用户尝试下单，事前风控拒绝（该条件**独立成立**，不要求该账号同时具管理层角色，`CH-010`）。
  3. 企业负责人可被授予审批与跨子账户查看权限（不妨碍其管理职责）。
  4. 具有**管理层（审批人）**角色的账号尝试下单被拒绝（**签署权与交易权互斥**，源自变更 `CH-002`，`Q-14`；该条件**独立成立**，不要求该账号同时具企业负责人标记，`CH-010`）。
  5. 标记变更与违规尝试均有留痕。

### FR-AUTH-10 配置人员授权（人员名单、品种、额度）

- **描述**：作为系统管理员或管理层，我希望按人员名单、品种、额度做明确授权，以便满足 8 号文对授权内容的要求。
- **输入**：用户标识、授权品种集合、授权额度（按品种）、授权子账户、有效期
- **处理规则**：见 `R-AUTH-4`。授权**必须明确三类信息**——**人员名单（即被授权用户）、品种、额度**，缺一不可；授权变更须**双人复核**；授权生效后须**下发控制指令至 C++ 内存**（`FR-RISK-10`）；**授权不得超出该用户角色的能力范围**（如无交易岗角色不得授交易品种额度）
- **输出**：成功 → 授权生效并下发；失败 → 明确错误（缺品种或额度 / 超出角色能力 / 复核缺失 / 无权限）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 配置包含人员、品种、额度的授权后，该用户可在授权范围内下单，超出范围被事前风控拒绝（`FR-RISK-7`）。
  2. 仅配置人员与品种、未配置额度时保存被拒绝。
  3. 授权变更须双人复核，复核缺失时被拒绝。
  4. 授权变更后 C++ 内存中的权限快照同步更新。

### FR-AUTH-11 授权变更留痕

- **描述**：作为审计/合规岗，我希望查询授权与权限的变更历史，以便证明内控有效。
- **输入**：筛选条件（用户、时间范围、变更类型、操作人）
- **处理规则**：见 `R-AUTH-4`。留痕须含**变更前值、变更后值、操作人、时间、复核人、变更原因**；**只增不改不删**；**不得**提供删除授权变更记录的入口；授权变更记录进入 `AUDIT`（对应 `R-AUDIT-3`）
- **输出**：授权变更历史列表；空结果返回空列表
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 修改某用户的授权后，历史中新增一条记录，含前后值与复核人（对应 `PROJECT.md` §10 成功标准 15：审计日志记录授权变更）。
  2. 记录中不存在编辑或删除入口。
  3. 可按用户与时间范围筛选。
  4. 审计岗可查询全部授权变更记录。

### FR-AUTH-12 配置子账户数据权限（限定到指定子账户）

- **描述**：作为系统管理员，我希望把用户限定到指定子账户，以便实现子账户数据隔离。
- **输入**：用户标识、可访问子账户集合（可多选）
- **处理规则**：见 `R-AUTH-5`。**默认未指定时用户看不到任何子账户数据**（安全默认）；配置后该用户在**全部业务模块**中仅能看到被指定子账户的数据；**数据权限与功能权限独立**（有功能无数据权限亦无法查看）；配置变更须**双人复核**并留痕
- **输出**：成功 → 数据权限生效；失败 → 明确错误（子账户不存在或已停用 / 复核缺失 / 无权限）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 把用户限定到子账户 A 后，该用户在实货敞口、计划、交易、结算、资金等模块**均看不到**子账户 B 的数据（对应 `PROJECT.md` §10 成功标准 34）。
  2. 未配置子账户权限的用户登录后看不到任何业务数据。
  3. 配置变更须双人复核并留痕。
  4. 数据权限与功能权限独立生效（有功能无数据权限时查询返回空）。

### FR-AUTH-13 授予跨子账户查看权限（管理层 / 审计岗）

- **描述**：作为系统管理员，我希望为管理层与审计岗授予跨子账户查看权限，以便满足总览与审计需求（软隔离）。
- **输入**：用户标识、跨子账户范围（全部或指定多个）、权限性质（**仅查看**）
- **处理规则**：见 `R-AUTH-5`。**仅管理层与审计/合规岗可被授予**——其他角色尝试授予须拒绝；**跨子账户权限默认只读**（**查看权限不等于操作权限**）——跨子账户下不得执行下单、审批、改配置等操作；授予须**双人复核**并留痕；**不得**做成硬隔离（管理层与审计岗需总览，`PROJECT.md` §4.1.B）
- **输出**：成功 → 跨子账户查看权限生效；失败 → 明确错误（角色不符 / 要求写权限 / 复核缺失）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 为审计岗授予跨子账户查看权限后，该用户可查看全部子账户数据（对应 `PROJECT.md` §10 成功标准 34）。
  2. 为交易岗尝试授予跨子账户查看权限被拒绝。
  3. 跨子账户权限下尝试执行下单/审批操作被拒绝（只读）。
  4. 授予操作须双人复核并留痕。

### FR-AUTH-14 用户登录与身份认证

- **描述**：作为系统用户，我希望用账号口令登录，以便访问被授权的功能。
- **输入**：用户名、口令
- **处理规则**：见 `R-AUTH-5`。口令**以加盐哈希校验**；**用户名或口令错误时返回统一错误信息**（不区分"用户不存在"与"口令错误"，防用户名枚举）；**连续 5 次失败锁定 5 分钟**（可配置）；**停用用户不得登录**；登录成功/失败（含锁定）**均留痕**；**不得**记录明文口令到日志
- **输出**：成功 → 建立登录会话并跳转；失败 → **统一错误信息**（不泄露具体原因）；锁定 → 明确提示锁定与解锁时间
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 正确账号口令登录成功。
  2. 口令错误时返回**统一错误信息**，与"用户不存在"的提示完全一致。
  3. 连续 5 次失败后账号锁定 5 分钟，期间登录被拒绝并提示解锁时间（对应角色定义 §7 的示例）。
  4. 日志中**不出现**明文口令（对应 `PROJECT.md` §10 成功标准 4）。

### FR-AUTH-15 用户登出与登录会话管理

- **描述**：作为系统用户或系统管理员，我希望管理登录会话，以便防止会话被长期占用。
- **输入**：登出动作、会话空闲时长、管理员强制下线动作
- **处理规则**：见 `R-AUTH-5`。支持**主动登出**；会话有**空闲超时**（默认 30 分钟，可配置），超时须**重新认证**；**不得**提供长期免登录选项；管理员可**强制下线**指定用户（须留痕）；用户停用或权限变更时**立即失效相关会话**
- **输出**：成功 → 会话终止；超时 → 跳转登录页并要求重新认证
- **优先级**：P1
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 主动登出后会话失效，回退操作需重新登录。
  2. 空闲超过配置时长后会话失效并要求重新认证。
  3. 系统中不存在"记住我/长期免登录"选项。
  4. 管理员强制下线操作留痕。

### FR-AUTH-16 口令管理与强度策略

- **描述**：作为系统管理员或系统用户，我希望系统强制口令强度与定期更换，以便降低账号被冒用风险。
- **输入**：口令修改动作、新口令、强度策略参数
- **处理规则**：见 `R-AUTH-5`。口令**以加盐哈希存储**；**明文口令不得出现在任何日志与持久化文件中**；强度要求（默认：**长度 ≥ 12、含大小写字母、数字、符号**，策略可配置）；**不得与最近 5 次历史口令相同**；支持**管理员重置**（重置须留痕，**不得以明文方式展示或传递新口令**）；**首次登录与重置后强制修改**
- **输出**：成功 → 口令更新；失败 → 明确错误（强度不足 / 与历史口令重复 / 无权限）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 使用强度不足的口令被拒绝并说明强度要求。
  2. 使用最近 5 次内使用过的口令被拒绝。
  3. 管理员重置口令后，新口令**不以明文出现在任何界面或日志**（对应 `PROJECT.md` §10 成功标准 4）。
  4. 口令在库中以加盐哈希形式存储（可通过技术审查验证）。

### FR-AUTH-17 登录失败锁定

- **描述**：作为系统管理员，我希望系统在连续登录失败后锁定账号，以便抵御口令猜测。
- **输入**：登录失败事件、失败计数、锁定阈值与时长
- **处理规则**：见 `R-AUTH-5`。**连续 5 次失败锁定 5 分钟**（阈值与时长可配置）；锁定期间**即使口令正确也拒绝登录**并提示解锁时间；**锁定事件与解锁事件均留痕**；解锁后失败计数清零；**不得**通过提示区分"账号被锁定"与"口令错误"泄露账号是否存在
- **输出**：锁定 → 拒绝登录并提示解锁时间；解锁 → 可正常登录且计数清零
- **优先级**：P1
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 连续 5 次失败后账号锁定，第 6 次即使口令正确也被拒绝。
  2. 锁定 5 分钟后可正常登录，失败计数清零。
  3. 锁定与解锁事件均可在审计中查询。
  4. 锁定阈值与时长可通过 `CONFIG` 调整。

### FR-AUTH-18 查询授权与权限变更记录

- **描述**：作为审计/合规岗，我希望查询授权与权限变更的完整记录，以便审计时证明岗位分离与授权管理有效。
- **输入**：筛选条件（用户、角色、时间范围、变更类型、操作人、是否含越权尝试）
- **处理规则**：见 `R-AUTH-4`。须同时提供**授权变更记录**与**越权尝试记录**两类视图；越权尝试记录须含**操作人、时间、尝试的操作、拒绝原因**；记录**只增不改不删**；**不得**提供删除入口；审计岗可跨子账户查询
- **输出**：权限变更记录 + 越权尝试记录列表；空结果返回空列表
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 查询授权变更记录可见前后值与复核人（对应 `PROJECT.md` §10 成功标准 15）。
  2. 越权尝试（如同一账号发起并复核）在越权尝试记录中可查到。
  3. 记录中不存在编辑或删除入口。
  4. 审计岗可查询全部记录。

| `R-AUTH-1` | **用户不可物理删除**：用户只能**停用**；**历史操作记录依赖用户存在**；停用前须检查是否存在进行中的关键操作（未复核的资金申请、待确认的交易指令）；**用户名不可修改** | `FR-AUTH-1`、`FR-AUTH-2`、`FR-AUTH-3` | 追溯链与留痕的完整性 |

| `R-AUTH-3` | **岗位分离互斥（⬅ 8 号文硬要求）**：**交易岗、风控岗、结算岗三者两两互斥**（不得由同一人担任）；**资金岗与交易岗互斥**；互斥为**系统级强制**，**不得提供关闭开关或绕过通道**；**系统管理员角色不得拥有业务操作权限**（**不得提供"超级管理员一键通办"后门**）；违规尝试须**拒绝并记录** | `FR-AUTH-7`、`FR-AUTH-8`、`FR-AUTH-6`、`FR-AUTH-9` | `PROJECT.md` §3 + §6「国资委 8 号文组织要求」；对应成功标准 15 |
| `R-AUTH-4` | **授权三类信息齐备 + 变更双人复核**：授权**必须明确人员名单、品种、额度**三者，缺一不可；授权变更须**双人复核**；授权生效后须**下发 C++ 内存**（`FR-RISK-10`）；授权变更历史**只增不改不删**，含前后值与复核人 | `FR-AUTH-10`、`FR-AUTH-11`、`FR-AUTH-18` | 8 号文 四(二)；对应成功标准 15、30 |
