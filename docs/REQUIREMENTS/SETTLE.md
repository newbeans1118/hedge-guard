## 1. 模块概述

- **职责**：每日与期货公司核对**仓位、资金、成交记录**；**子账户独立结算**；执行 **Σ 子账户 = 真实期货账户** 的**加总对账**；保证金监控；落地 8 号文的每日/每月/每季度报告与核对机制。
- **解决的业务问题**：不解决则子账户体系**无法自证正确**——期货公司侧持仓与资金是**合并的**，一旦系统记账出错，加总对不上而无从发现，最终表现为"账面套保规模与真实持仓不符"，直接触发超额套保与监管问询；同时 8 号文要求的核对记录（本身即合规证据）无处沉淀。
- **上游模块**：`TRADE`（成交、委托、持仓、事件流）、`FUND`（资金台账与流水）、`PLAN`（计划与额度占用）、`RISK`（保证金与风险度口径）、`AUTH`（结算岗/财务岗权限）
- **下游模块**：`ACCT`（结算结果用于会计处理与盈亏归集）、`AUDIT`（结算报告与核对记录进入审计）、`RISK`（事后风控取结算数据生成风险报表）

> ⚠️ **与 `FUND` 的边界**（`PROJECT.md` §4.1 ⑨）：`FUND` 管**资金流水的记录与调拨**；
> `SETTLE` 管**与期货公司的每日核对**及**子账户加总校验**。
> 两者共享资金台账，但**职责不重叠**。

### 2.1 状态机

**结算单**：

```
  待结算 ──生成──→ 已生成（待核对） ──三类核对完成且加总对账一致──→ 核对完成
                          │                                            │
                          │                                    差异闭环│
                          │                                            ↓
                          └──加总对账不一致──→ 已阻断 ──差异闭环──→ 已确认（关账）
```

| 状态 | 业务含义 | 可执行操作 | 后续状态 |
|------|---------|-----------|---------|
| **待结算** | 交易日已过，尚未开始结算 | 启动结算 | 已生成 |
| **已生成（待核对）** | 结算结果已生成，等待三类核对 | 执行核对、查看 | 核对完成 / 已阻断 |
| **已阻断** | 加总对账不一致，**阻断差异所属子账户的后续操作**（见 `R-SETTLE-2`） | 处理差异、查看 | 已生成（重算）/ 已确认 |
| **核对完成** | 三类核对完成且加总对账一致 | 确认关账、查看 | 已确认 |
| **已确认（关账）** | 结算已确认，进入会计处理 | 查看、重算（须留痕） | 终态 |

**状态流转规则**：见 §4 `R-SETTLE-1`、`R-SETTLE-2`、`R-SETTLE-5`。

## 3. 功能性需求

> **编号规范**：`FR-SETTLE-<序号>`，序号在**本模块内**从 1 递增，不复用。

### FR-SETTLE-1 获取 CTP 日终结算数据

- **描述**：作为结算岗，我希望系统接收 CTP 日终结算数据，以便以期货公司数据为基准开展核对。
- **输入**：交易日、CTP 结算文件/查询接口返回的持仓明细、资金明细、成交明细
- **处理规则**：见 `R-SETTLE-3`。结算数据须记录**接收时间与来源标识**；**数据未到达时不得用推算数据替代**，结算任务置为待重试并记录未达原因；重复接收同一交易日数据须幂等（以最后一次确认为准并留痕）
- **输出**：成功 → 结算数据入库并进入按子账户拆分；失败 → 明确错误（未到达 / 数据不完整 / 格式异常）并保留重试入口
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 接收某交易日 CTP 结算数据后，持仓、资金、成交三类明细均可在系统内查询到。
  2. 数据未到达时结算任务处于"待结算"或明确的重试状态，**不产生**基于推算的结算结果。
  3. 重复接收同一交易日数据不产生重复结算记录。
  4. 接收记录中含接收时间与来源标识。

### FR-SETTLE-2 按子账户拆分持仓

- **描述**：作为结算岗，我希望系统把期货公司合并的持仓按子账户拆分，以便各子账户独立结算。
- **输入**：CTP 持仓明细、系统内成交与委托记录、子账户标识
- **处理规则**：见 `R-SETTLE-1`、`R-TRADE-8`。**期货公司侧持仓是合并的**，拆分**完全依赖系统内按子账户记账的交易记录**；拆分后各子账户持仓**必须可直接求和**等于合并持仓；**拆分不出来（对不上）时必须告警**并列出无法归属的数量，**不得**默认归入任一子账户
- **输出**：成功 → 各子账户持仓明细与汇总；失败 → 无法归属的数量清单与差额告警
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 子账户 A、B 的持仓拆分结果之和等于 CTP 合并持仓。
  2. 人为构造一笔无法归属子账户的成交时，系统告警并列出该差额，**不自动归入**某子账户。
  3. 拆分结果中每条持仓**显式携带子账户标识**（`INDEX.md` §2.1「持仓类」）。
  4. 期货与期权持仓均被正确拆分。

### FR-SETTLE-3 按子账户拆分资金

- **描述**：作为结算岗与资金岗，我希望系统把真实账户资金按子账户拆分，以便各子账户独立记账与结算。
- **输入**：CTP 资金明细（权益、可用资金、占用保证金）、`FUND` 的资金台账与划拨记录、子账户标识
- **处理规则**：见 `R-SETTLE-1`。拆分结果须**与 `FUND` 的资金台账口径一致**（两者共享台账，职责不重叠）；各子账户资金**必须可直接求和**；**子账户划拨为系统内记账调整**，划拨后在拆分结果中体现为"两子账户一增一减、加总不变"；拆分不出时告警并列出差额
- **输出**：成功 → 各子账户资金明细与汇总；失败 → 差额清单与告警
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 各子账户可用资金之和等于真实账户可用资金。
  2. 发生一笔子账户 A→B 划拨后，拆分结果中 A 减少、B 增加且加总不变。
  3. 拆分结果与 `FUND` 资金台账的期末余额一致。
  4. 拆分结果中每条记录**显式携带子账户标识**。

### FR-SETTLE-4 子账户独立日终结算

- **描述**：作为结算岗，我希望对每个子账户独立完成日终结算（盈亏、手续费、保证金），以便各业务线的盈亏与资金各自清晰。
- **输入**：交易日、子账户标识、当日成交与持仓
- **处理规则**：见 `R-SETTLE-1`。**每个子账户独立生成结算结果**；结算内容含**平仓盈亏、浮动盈亏、手续费、保证金占用、可用资金、风险度**；口径全系统唯一；结算结果**一经确认不得修改**（重算须作废旧单并留痕）；**不得**把多个子账户合并出账
- **输出**：成功 → 生成各子账户结算单（状态"已生成"）；失败 → 明确错误（数据缺失 / 子账户未配置）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 跑完一个交易日，子账户 A、B 各生成一份独立结算单。
  2. 结算单含平仓盈亏、浮动盈亏、手续费、保证金占用、可用资金、风险度六项。
  3. 子账户资金为负时告警并进入差异处理（见 `R-SETTLE-6`）。
  4. 已确认的结算单不存在直接编辑入口。

### FR-SETTLE-5 成交记录核对

- **描述**：作为结算岗，我希望逐笔核对系统内成交与期货公司成交明细，以便发现漏记或错记。
- **输入**：系统内成交记录、CTP 成交明细、交易日、子账户
- **处理规则**：见 `R-SETTLE-4`。核对按**成交编号**逐笔比对**合约、方向、开平、价格、数量、时间**；差异须**定位到具体记录并双向列出**（系统有而期货公司无 / 期货公司有而系统无 / 要素不一致）；若采用按日汇总比对（性能考虑），**逐笔差异须可下钻定位**，不得只给汇总差额
- **输出**：成功 → 核对结论"一致"并留痕；存在差异 → 差异清单（逐条定位）+ 结论"存在差异"
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 数据一致时核对结论为"一致"，核对时间与操作人留痕。
  2. 人为删除系统内一笔成交后核对，差异清单定位到该笔并标明"期货公司有、系统无"。
  3. 人为改动一笔成交价格后核对，差异清单标明要素不一致及两侧取值。
  4. 核对结果可在审计中查询。

### FR-SETTLE-6 仓位核对

- **描述**：作为结算岗，我希望核对系统内持仓与期货公司持仓，以便确保仓位记账准确。
- **输入**：系统内持仓明细（按子账户）、CTP 持仓明细、交易日
- **处理规则**：见 `R-SETTLE-4`。核对维度：**合约 × 方向 × 今/昨仓**；**同时校验子账户明细之和 = CTP 合并持仓**；差异须定位到合约与子账户（若可定位）
- **输出**：成功 → 结论"一致"；差异 → 差异清单（含合约、方向、两侧数量）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 数据一致时结论为"一致"。
  2. 人为修改某子账户一笔持仓数量后核对，差异清单定位到该合约与子账户。
  3. 期货与期权持仓均纳入核对范围。
  4. 核对记录含核对时间与操作人。

### FR-SETTLE-7 资金核对

- **描述**：作为结算岗与资金岗，我希望核对系统内资金与期货公司资金明细，以便确保资金记账准确。
- **输入**：系统内各子账户资金与汇总、CTP 资金明细、`FUND` 资金流水、交易日
- **处理规则**：见 `R-SETTLE-4`。核对项：**权益、可用资金、占用保证金、当日出入金、当日手续费**；差异须**定位到具体项**；**与 `FUND` 的资金流水勾稽**（期初 + 发生额 = 期末，见 `FR-FUND-2`）
- **输出**：成功 → 结论"一致"；差异 → 差异清单（含项目、两侧数值、差额）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 数据一致时结论为"一致"。
  2. 人为调整某子账户可用资金后核对，差异清单定位到该项与差额。
  3. 核对结果与 `FR-FUND-2` 的期末余额勾稽一致。
  4. 核对记录留痕含时间与操作人。

### FR-SETTLE-8 子账户加总对账（Σ 子账户 = 真实账户）

- **描述**：作为结算岗与风控责任人，我希望系统执行加总对账校验，以便发现子账户记账错误并阻断风险扩散。
- **输入**：各子账户结算结果（持仓、资金、盈亏）、CTP 真实账户数据、交易日
- **处理规则**：见 `R-SETTLE-2`。校验 **Σ 子账户持仓 = 真实账户持仓**、**Σ 子账户资金 = 真实账户资金**、**Σ 子账户盈亏 = 真实账户盈亏**；**不一致时告警并阻断后续操作**——**仅阻断差异所属子账户**的新开仓 / 资金划拨 / 日终关账，**不波及其他子账户**；**不阻断平仓**（含风险处置平仓、到期交割）（`Q-11`，源自变更 `CH-001`）；**全账户强制告警**（风控 + 财务 + 审计可见）并生成**差异待处理事项**，闭环前该子账户**禁开新仓**；**不得静默通过**；对账结论须留痕并进入报告
- **输出**：一致 → 结论"一致"并允许关账；不一致 → **全账户告警 + 仅阻断差异所属子账户**，输出差额明细（哪一类、差额多少、可能来源子账户）与「差异待处理」事项
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 正常跑完一个交易日，加总对账结论为"一致"（对应 `PROJECT.md` §10 成功标准 36）。
  2. **人为构造不一致数据**，验证全账户告警触发、**仅差异所属子账户**被阻断，**其他子账户不受影响**（对应成功标准 36，源自变更 `CH-001`，`Q-11`）。
  3. 阻断期间**平仓与风险处置类操作不被阻断**。
  4. 对账结论与差额明细可在结算报告与审计中查询；生成「差异待处理」事项，闭环前差异所属子账户禁开新仓。

### FR-SETTLE-9 差异标记与处理

- **描述**：作为结算岗与财务/风控岗，我希望标记、跟踪并闭环核对差异，以便结算结果可信。
- **输入**：差异标识、处理方式（补录/冲正/调整）、处理说明、复核人
- **处理规则**：见 `R-SETTLE-4`、`R-SETTLE-5`。差异须有**处理状态**（待处理/处理中/已闭环）与**责任人**；**未闭环的差异不得标记结算完成**（`R-SETTLE-5`）；调整类操作须**双人复核**（与资金调整同口径）；差异处理全过程留痕并进入审计
- **输出**：成功 → 差异状态更新；未闭环 → 结算单不得进入"已确认"
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 标记差异后，结算单状态**不得**变为"已确认"直到差异闭环。
  2. 差异记录含类型、数量/金额、定位信息、责任人、处理结论。
  3. 差异闭环后结算单方可进入"已确认"。
  4. 差异处理记录可在审计中查询到处理人与时间。

### FR-SETTLE-10 生成每日结算报告

- **描述**：作为结算岗与管理层，我希望生成每日结算报告，以便掌握全账户与各子账户的结算结果。
- **输入**：交易日、结算单集合、加总对账结论
- **处理规则**：报告须含**各子账户结算结果**与**全账户汇总**，以及**加总对账结论**；**加总对账不一致时报告须显式标注"不一致/已阻断"**，不得输出为正常结论；报告生成后留痕；可导出
- **输出**：每日结算报告；失败 → 关键数据缺失时明确提示并拒绝生成
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 报告含各子账户结算结果与全账户汇总，汇总等于明细之和。
  2. 加总对账不一致时报告显式标注"不一致/已阻断"，不输出正常结论。
  3. 报告可导出且含生成时间与生成人。
  4. 数据缺失时拒绝生成并说明缺失项。

### FR-SETTLE-11 保证金监控

- **描述**：作为风控责任人与结算岗，我希望监控各子账户与全账户的保证金占用与风险度，以便动态开展资金风险评估与压力测试。
- **输入**：各子账户保证金占用、权益、可用资金、风险度阈值
- **处理规则**：见 `R-SETTLE-6`。须提供**子账户视图**与**汇总视图**；风险度超过阈值时**告警**（阈值配置见 `FR-CONFIG-5`）；须支持**场景化压力测试**（如价格不利变动若干幅度下的保证金缺口估算，具体情景参数见 `R-SETTLE-7`）；**保证金专门管理**（8 号文要求）
- **输出**：保证金与风险度视图（子账户/汇总）；超阈值 → 告警
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 视图可切换子账户与汇总，汇总值等于明细之和。
  2. 设定风险度阈值后，构造超阈值场景触发告警（对应 `PROJECT.md` §10 成功标准 20 的资金额度告警口径）。
  3. 压力测试可输出给定不利变动下的保证金缺口估算值。
  4. 保证金数据与 `FR-SETTLE-8` 加总对账口径一致。

### FR-SETTLE-12 生成风控日报

- **描述**：作为风控责任人，我希望系统每日生成风控日报，以便落地 8 号文"风控每日报告"要求。

- **处理规则**：见 `R-SETTLE-6`。日报须含：**持仓与敞口概览、规模红线使用率（按品种与子账户）、保证金与风险度、当日告警与违规事项、额度使用情况**；日报**每日必须生成**（缺失须告警）；生成后留痕并进入 `AUDIT`
- **输出**：风控日报；失败 → 生成失败须告警且不得静默跳过
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：

  2. 日报按品种与子账户分别展示规模红线使用率。

  4. 日报可在审计中按日期查询与导出。

### FR-SETTLE-13 月度核对记录（风控 + 交易 + 财务）

- **描述**：作为风控责任人、交易岗与财务/风控岗，我希望在系统内完成并记录月度三方核对，以便落地 8 号文"每月核对"要求。
- **输入**：核对月份、参与人（三个职责角色，须为**不同账号**）、核对内容（持仓/资金/盈亏/额度）、核对结论与说明
- **处理规则**：见 `R-SETTLE-4`、`R-SETTLE-11`。**三方角色与职责**（`Q-14`，源自变更 `CH-002`）：**风控岗发起 + 核对、交易岗确认持仓成交、财务岗确认资金账务**，**三方各自电子签署**；**三个参与角色须为不同账号**（岗位分离，`FR-AUTH-8`）；核对记录须含**参与人、时间、核对项、结论**与**签署记录**（账号 / 角色 / 时间 / IP / 核对对象快照哈希）；**不可代签**；**核对记录不得缺失**（缺失或逾期须告警提醒）；核对记录本身即**合规证据**，进入 `AUDIT`
- **输出**：成功 → 月度核对记录生成、三方签署齐备并留痕；失败 → 参与人重复 / 核对项缺失 / 代签时拒绝
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 由三个不同账号完成月度核对并各自电子签署后，记录含三方参与人、时间、结论与三条签署记录。
  2. 参与人中存在同一账号时被拒绝（岗位分离）。
  3. 尝试由他人代为签署时被拒绝（不可代签），且记录越权尝试。
  4. 某月未完成核对或签署逾期时系统给出告警并进入审计报表。
  5. 月度核对记录可在审计中查询与导出。

### FR-SETTLE-14 季度核对与报告（向管理层）

- **描述**：作为风控责任人与交易岗，我希望生成季度报告并向管理层提交，以便落地 8 号文"每季度向管理层报告"要求。
- **输入**：报告季度、风控与交易两方参与人（不同账号）、报告内容（保值规模、盈亏、有效性、违规事项）、提交对象（管理层/审批人角色）
- **处理规则**：见 `R-SETTLE-4`、`R-SETTLE-11`。季度报告须由**风控岗编制 + 交易岗会签 → 管理层签收**（签署人不得为同一账号，`Q-14`，源自变更 `CH-002`）；报告须含**保值规模、实货与衍生品双侧盈亏、套保有效性、违规事项与整改**；**管理层只签收报告、不得操盘**（签署权与交易权互斥，系统须强制）；提交动作留痕并进入 `AUDIT`；**年度全覆盖审计**要求的支撑数据须可从本模块与 `AUDIT` 取得
- **输出**：成功 → 季度报告生成、会签与签收齐备并标记已提交；失败 → 参与人重复 / 管理层操盘越权 / 内容缺失时拒绝

- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 生成季度报告，内容含保值规模、双侧盈亏、有效性与违规事项四部分。

  4. 报告提交动作留痕并可在审计中查询。
  5. 报告可导出（对应 `PROJECT.md` §10 成功标准 17）。

### FR-SETTLE-15 查询历史结算记录

### FR-SETTLE-16 导出结算报表

### FR-SETTLE-17 生成核对任务并管理电子签署

- **描述**：作为风控责任人、交易岗、财务/风控岗与审计/合规岗，我希望系统按周期生成核对任务并管理各角色的电子签署，以便核对责任到人、可追溯、不可代签（源自变更 `CH-002`，`Q-14`）。
- **输入**：核对任务类型（月度三方核对 / 季度核对 / 年度审计覆盖）、所属期间、应签角色清单、核对对象快照
- **处理规则**：见 `R-SETTLE-11`。系统按周期**自动生成核对任务**并指派应签角色——**每月**：风控岗、交易岗、财务岗**三方各自签署**；**每季度**：风控岗编制 + 交易岗会签 + 管理层签收；**每年**：审计岗全覆盖；**签署记录须含账号 / 角色 / 时间 / IP / 核对对象快照哈希**；**不可代签**（签署人须与应签角色账号一致）；**签名对象为核对时点的快照哈希**——签署后快照变更须重新签署；**逾期未签**（签署截止口径：任务所属期间结束后的下一自然月内，配置键 `settle.sign.deadline_days`）→ **告警并进审计报表**；⚠️ **管理层签署权与交易权互斥**——管理层**只能签收报告，不得操盘**
- **输出**：成功 → 核对任务状态流转并生成签署记录；失败 → 角色不符 / 代签 / 快照已变更 / 无权限时拒绝；逾期 → 告警
- **优先级**：P0
- **来源**：变更 `CH-002`
- **状态**：有效
- **验收标准**：
  1. 月度核对任务由系统自动生成，风控岗、交易岗、财务岗三方签署齐备后任务状态为"已完成"。
  2. 任一签署记录含账号、角色、时间、IP 与核对对象快照哈希。
  3. 由非应签角色账号签署或由他人代为签署时被拒绝。
  4. 签署后核对对象快照发生变化时，任务回到"待签署"并要求重新签署。
  5. 逾期未签的任务产生告警，且可在审计报表中查询到逾期清单。
  6. 管理层账号仅能签收报告，尝试下单/操盘被权限拒绝（签署权与交易权互斥）。
