## 1. 模块概述

- **职责**：对历史操作记录做**合规性审计**——全链路追溯（`实货敞口 → 套保计划 → 审批 → 交易 → 结算 → 会计凭证`）、违规事项筛查、季度/年度/重大事项报表导出、不可篡改的操作留痕。
- **解决的业务问题**：不解决则企业**无法向交易所与监管自证**——被问询"为何频繁开平仓"时拿不出证据链；8 号文要求的季度/年度专项报告无系统支撑；内外部审计只能靠人工拼数据，效率低且易被认为不可信。
- **上游模块**：`SPOT`（追溯链起点：实货敞口）、`PLAN`（套保计划与审批链）、`TRADE`（交易与理由）、`SETTLE`（结算与核对记录）、`ACCT`（会计凭证）、`RISK`（违规事项与风险报表）、`FUND`（资金流水与划拨）、`AUTH`（操作留痕与跨子账户权限）、`CONFIG`（配置变更留痕）
- **下游模块**：**无**（审计为终端消费方，仅提供报表与证据链导出；不反向写入任何模块）

> ⚠️ **只读原则**：`AUDIT` 对其它模块的数据**只读**；
> 审计本身的操作（查询、导出）**必须留痕**，且审计日志**不可篡改**。

### 2.1 状态机

**追溯链校验结论**：

```
  待校验 ──遍历──→ 完整（六段齐备 + 子账户维度齐备）
              └──→ 存在断点（列出断点位置与涉及对象）
```

| 状态 | 业务含义 | 可执行操作 | 后续状态 |
|------|---------|-----------|---------|
| **完整** | 六段齐备且子账户维度齐备，链条无断点 | 导出证据链、生成报表 | 终态 |
| **存在断点** | 至少一个环节缺失 | 查看断点清单、导出（须带"不完整"标注） | 终态 |

**重大事项专项报告**：

```
  未触发 ──命中触发条件──→ 已触发待生成 ──生成──→ 已生成
                                                    │
                                              提交/留痕 → 已提交
```

| 状态 | 业务含义 | 可执行操作 | 后续状态 |
|------|---------|-----------|---------|
| **未触发** | 未命中触发条件 | — | 已触发待生成 |
| **已触发待生成** | 命中条件，尚未生成报告 | 生成报告 | 已生成 |
| **已生成** | 报告已生成 | 提交、导出 | 已提交 |
| **已提交** | 已提交并留痕 | 查看 | 终态 |

## 3. 功能性需求

> **编号规范**：`FR-AUDIT-<序号>`，序号在**本模块内**从 1 递增，不复用。

### FR-AUDIT-1 全链路正向追溯（敞口 → 凭证）

- **描述**：作为审计/合规岗，我希望从实货敞口出发正向追溯至会计凭证，以便回答"这笔敞口套保得怎么样"。
- **输入**：起点类型=实货敞口、敞口标识（可多条）、追溯深度（全链/指定段）
- **处理规则**：见 `R-AUDIT-1`。遍历顺序：**实货敞口 → 套保计划 → 审批链 → 交易（指令/委托/成交）→ 结算 → 会计凭证**；每段须展示**子账户标识**；**期权与期货走同一条链**（期权交易同样出现在交易段）；遍历须标记断点（`FR-AUDIT-3`）
- **输出**：正向追溯链（分层展示各段对象及关键属性）；无关联对象时明确标注"该环节无记录"
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 取一条实货敞口正向追溯，链上依次出现套保计划、审批记录、交易记录、结算记录与会计凭证（对应 `PROJECT.md` §10 成功标准 1、16）。
  2. 链上每一段均展示子账户标识。
  3. 若敞口对应的期权交易存在，该交易同样出现在交易段（不旁路）。
  4. 某环节无记录时明确标注，不静默跳过。

### FR-AUDIT-2 全链路反向追溯（凭证 → 敞口）

- **描述**：作为审计/合规岗，我希望从会计凭证反向追溯到实货敞口，以便回答"这笔凭证凭什么入账"（审计问询最常用）。
- **输入**：起点类型=会计凭证，凭证标识（可多条）；或起点类型=交易，交易标识
- **处理规则**：见 `R-AUDIT-1`。遍历顺序：**会计凭证 → 结算 → 交易 → 套保计划 → 审批链 → 实货敞口**（含敞口构成明细）；**任取一笔凭证必须能反查到实货敞口**（对应成功标准 16）；链上每段展示子账户标识
- **输出**：反向追溯链；无关联对象时明确标注
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 任取一笔会计凭证反向追溯，可定位到实货敞口及其构成明细（对应成功标准 16）。
  2. 从交易出发可追溯到套保计划与实货敞口（对应成功标准 2：抽取 10 笔交易逐笔追溯成功率 100%）。
  3. 链上每段展示子账户标识。
  4. 链上各段的对象标识可点击跳转到对应模块详情。

### FR-AUDIT-3 追溯链完整性校验与断点标记

- **描述**：作为审计/合规岗，我希望系统校验追溯链完整性并标记断点，以便判断证据链是否可用。
- **输入**：追溯结果（正向或反向）、必需环节清单
- **处理规则**：见 `R-AUDIT-2`。必需环节：**实货敞口 → 套保计划 → 审批 → 交易 → 结算 → 会计凭证** 六段（对未结算或未出凭证的在途业务，允许标注"在途"而非"断点"，须明示）；**存在断点时不得输出"链条完整"结论**；断点须输出**位置、涉及对象标识、可能原因**
- **输出**：校验结论（完整 / 存在断点 / 含在途）+ 断点清单；失败 → 无法判定时明确说明
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 完整链条结论为"完整"。
  2. 人为移除某环节关联后，结论为"存在断点"并列出该环节与对象标识（对应 `PROJECT.md` §10 成功标准 16 的负向验证）。
  3. 在途业务（已成交未结算）标注为"在途"，**不计为断点**。
  4. 报表或导出中若链条不完整，输出中带"链条不完整"标注。

### FR-AUDIT-4 违规事项筛查

- **描述**：作为审计/合规岗，我希望对历史交易做违规事项筛查，以便发现并记录合规问题。
- **输入**：筛查时间范围、子账户范围（可为全部有权限子账户）、筛查维度（超品种/超规模/超期限/超授权/频繁开平仓/理由缺失/关联对象缺失）
- **处理规则**：见 `R-AUDIT-2`、`R-AUDIT-7`。筛查维度与 `RISK` 的规则口径**一致**（复用规则编号与阈值，避免两套口径）——**频繁开平仓**按 `Q-5` 确认口径（日内开平合计 ≥6 告警 / ≥10 限制、7 日滚动回合 ≥5、平均持仓 <3 个交易日且回合 ≥5）；**理由缺失（`REASON_MISSING`）**与**关联对象缺失（`RELATED_MISSING`）**须作为**两个并列独立**的筛查维度（`R-TRADE-9`，`Q-13`，源自变更 `CH-002`；判定口径澄清见 `CH-004`）——前者 = **无理由记录或理由内容为空**，后者 = **理由已填但关联对象未提供**（带关联对象缺失标记），筛查须能**分别命中两者**；筛查结论须记录**筛查条件、时间、执行人**以便复现；命中项须标注**严重级别**并附**该笔交易的交易理由与关联对象**（供自证或整改）
- **输出**：违规事项清单（类型、严重级别、涉及子账户与交易、发生时间、理由字段、关联对象字段）；无命中时返回空清单并明确"未发现违规"
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 构造一笔超规模交易的历史记录，筛查结果中出现该笔并标注类型"超规模"。
  2. 构造一笔**无理由记录 / 理由内容为空**的记录，筛查结果中出现"理由缺失"，且**不被计为"关联对象缺失"**（源自变更 `CH-004`，`Q-13`）。
  3. 构造一笔**理由已填但关联对象缺失（未关联计划 ID 或实货敞口 ID，带关联对象缺失标记）**的记录，筛查结果中出现"关联对象缺失"，且**该笔不被计为"理由缺失"**（两个维度独立、分别命中）（源自变更 `CH-002`/`CH-004`，`Q-13`）。
  4. 构造同一子账户同一品种日内开平合计 6 次的记录，按 `Q-5` 口径被判为频繁开平仓告警项。
  5. 筛查结论中记录了筛查条件、时间与执行人。
  6. 无命中时明确输出"未发现违规"，而非空白。

### FR-AUDIT-5 生成季度报表

- **描述**：作为审计/合规岗或管理层，我希望一键生成季度报表，以便满足 8 号文报告要求。
- **输入**：报告季度、子账户范围、报表口径
- **处理规则**：见 `R-AUDIT-3`。报表须含**品种、保值规模、盈亏、持仓**（8 号文要求项）；盈亏须**同时含实货盈亏与衍生品盈亏**；须按**子账户与汇总**两个层级展示；生成后留痕；**链条不完整的数据须显式标注**；可一键导出
- **输出**：季度报表；失败 → 数据缺失时明确提示并拒绝生成
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 一键导出季度报表，含品种、保值规模、盈亏、持仓四类内容（对应 `PROJECT.md` §10 成功标准 17）。
  2. 盈亏部分同时含实货盈亏与衍生品盈亏。
  3. 报表按子账户与汇总两层展示，汇总等于明细之和。
  4. 报表可导出且含生成时间与生成人。

### FR-AUDIT-6 生成年度专项报告

- **描述**：作为审计/合规岗或管理层，我希望生成年度专项报告，以便满足 8 号文年度报告与内审全覆盖要求。
- **输入**：报告年度、子账户范围
- **处理规则**：见 `R-AUDIT-3`、`R-AUDIT-11`。内容须含**全年保值规模、双侧盈亏、套保有效性、违规事项与整改、额度使用情况**；须含**年度内审覆盖**所需的记录索引（各季度报告、月度核对记录清单）；**年度审计须覆盖全部核对任务与签署记录**（含逾期未签清单）（`Q-14`，源自变更 `CH-002`）；生成与导出留痕
- **输出**：年度专项报告；失败 → 缺失必要条件时明确提示
- **优先级**：P1
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 生成年度专项报告，含全年保值规模、双侧盈亏、有效性、违规与整改、额度使用五部分。
  2. 报告内附季度报告与月度核对记录清单，并覆盖全部**核对任务与签署记录**（对应 8 号文"内审每年全覆盖"，`Q-14`）。
  3. 报告可导出且含生成时间与生成人。
  4. 缺少某季度数据时明确标注缺口。

### FR-AUDIT-7 生成重大事项专项报告

- **描述**：作为审计/合规岗，我希望在发生重大事项时生成专项报告，以便及时向管理层与监管说明。
- **输入**：重大事项标识、事项类型、事项说明、涉及交易与子账户
- **处理规则**：见 `R-AUDIT-3`、`R-AUDIT-5`。**重大事项触发条件**：① 加总对账不一致且超时未闭环 ② 触及规模红线 ③ 被交易所问询或收到警示 ④ 强制平仓提示未处置 ⑤ 单笔或当日亏损超阈值（阈值可配置）；触发后系统**自动提醒**生成专项报告；报告须含**事项描述、原因分析、影响范围、处置措施与整改计划**；生成、提交与导出均留痕
- **输出**：成功 → 专项报告生成；失败 → 事项类型未提供时拒绝
- **优先级**：P1
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 构造加总对账不一致场景，系统提醒生成重大事项专项报告。
  2. 报告含事项描述、原因分析、影响范围、处置措施与整改计划五节。
  3. 未提供事项类型时拒绝生成。
  4. 报告生成与提交均有留痕。

### FR-AUDIT-8 导出审计证据链

- **描述**：作为审计/合规岗，我希望导出完整证据链，以便向监管或外部审计提交。
- **输入**：追溯起点集合（敞口/交易/凭证）、时间范围、子账户范围、是否含原始单据明细
- **处理规则**：见 `R-AUDIT-4`。导出须含**六段全链对象 + 子账户维度 + 双侧盈亏 + 交易理由**；**链条存在断点时导出文件须显式标注"链条不完整"及断点清单**，**不得**静默输出为完整；导出动作进入审计日志；导出**不改变**任何业务数据
- **输出**：证据链文件；失败 → 审计日志写入失败时**中断本次导出**（`FR-AUDIT-9`）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 导出的证据链含六段全链对象、子账户维度、双侧盈亏与交易理由。
  2. 存在断点时导出文件带"链条不完整"标注与断点清单。
  3. 导出后审计日志中新增一条记录，含导出人、时间、条数与文件标识。
  4. 导出不改变任何业务数据（导出前后数据一致）。

### FR-AUDIT-9 审计日志查询

- **描述**：作为审计/合规岗或内外部审计人员，我希望查询审计日志，以便核实审计操作本身是否被记录。
- **输入**：筛选条件（时间范围、操作人、操作类型、对象类型）
- **处理规则**：见 `R-AUDIT-4`。审计日志须含**查询人、查询条件、时间、结果条数、是否导出及其文件标识**；日志**只增不改不删**；**写入失败须中断被记录的操作**（尤其是导出——见 `FR-AUDIT-8` 异常分支）；日志查询本身也写入日志
- **输出**：审计日志列表；无数据时返回空列表；失败 → 日志写入失败时告警
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 执行一次导出后，审计日志中新增记录，含导出人、时间与文件标识。
  2. 查询审计日志的操作本身也会在日志中留下记录。
  3. 日志记录不存在编辑或删除入口。
  4. 模拟日志写入失败时，被记录的导出操作被中断并告警。

### FR-AUDIT-10 审计日志防篡改校验

- **描述**：作为审计/合规岗，我希望系统能校验审计日志未被篡改，以便证明留痕可信。
- **输入**：校验时间范围、校验动作
- **处理规则**：见 `R-AUDIT-4`。**必须提供**防篡改校验能力（校验和/链式校验等，具体机制由技术负责人确定，本需求只要求**可校验且结论可判定**）；校验未通过须**告警并阻断**后续导出；校验结论（通过/未通过、校验范围、时间）须记录；**不得**提供直接修改历史日志的入口
- **输出**：校验结论（通过 / 未通过）+ 报告；未通过 → 告警并阻断导出
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 正常数据下校验结论为"通过"。
  2. 人为直接修改底层日志数据后校验结论为"未通过"，且后续导出被阻断。
  3. 校验结论含校验范围与时间，并写入审计日志。
  4. 系统内不存在直接编辑历史审计日志的入口。

### FR-AUDIT-11 操作留痕查询

- **描述**：作为审计/合规岗，我希望查询系统内的关键操作留痕，以便还原"谁在什么时候做了什么"。
- **输入**：筛选条件（时间范围、操作人、操作类型、对象类型、子账户）
- **处理规则**：见 `R-AUDIT-3`。留痕范围**至少**覆盖：**计划提交/审批/终止、交易指令提交/人工确认、风控拒绝、资金转账与划拨、权限与授权变更、系统配置变更、结算确认与差异处理、会计凭证审核**；每条含**操作人、时间、对象、动作、结果、子账户**；**只增不改不删**；审计岗可跨子账户查询
- **输出**：操作留痕列表；空结果返回空列表
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 完成"提交计划 → 审批 → 下单 → 确认"后，留痕中可按序查到各操作及其操作人与时间。
  2. 授权变更、配置变更、资金划拨均有留痕。
  3. 留痕记录不存在编辑或删除入口。
  4. 审计岗可跨子账户查询留痕。

### FR-AUDIT-12 导出审计报表

- **描述**：作为审计/合规岗，我希望导出各类审计报表，以便线下归档与提交。
- **输入**：报表类型（季度/年度专项/重大事项）、时间范围、子账户范围
- **处理规则**：见 `R-AUDIT-3`。**仅导出有权限的子账户范围**；导出文件含**报表类型、时间范围、生成时间、生成人、子账户范围**；**含断点或数据缺口的报表须显式标注**；导出动作进入审计日志；无数据时不生成空文件
- **输出**：报表文件；失败 → 明确提示
- **优先级**：P1
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 导出季度报表，文件含报表类型、时间范围、生成时间、生成人与子账户范围。
  2. 报表含数据缺口时显式标注。
  3. 导出动作在审计日志中留痕。
  4. 无数据时不生成文件并给出提示。

### FR-AUDIT-13 查询核对任务与签署记录

- **描述**：作为审计/合规岗，我希望查询各周期核对任务及其电子签署记录，以便核验 8 号文核对要求是否全面落实（源自变更 `CH-002`，`Q-14`）。
- **输入**：筛选条件（时间范围、核对任务类型〔月度/季度/年度〕、子账户、签署角色、任务状态、是否逾期）
- **处理规则**：见 `R-AUDIT-11`。须可查询**核对任务**及其**签署记录**（**账号 / 角色 / 时间 / IP / 核对对象快照哈希**）；**逾期未签**任务须可单独筛出并**进入审计报表**；**年度审计须全覆盖**——可按年度汇总当月度/季度/年度核对任务的完成率与逾期清单；核对任务与签署记录**只读**，**不得**提供修改或删除入口
- **输出**：核对任务列表 + 签署记录明细 + 逾期清单 + 完成率汇总；无数据返回空列表
- **优先级**：P0
- **来源**：变更 `CH-002`
- **状态**：有效
- **验收标准**：
  1. 查询某月核对任务，可见三方签署记录，每条含账号、角色、时间、IP 与核对对象快照哈希。
  2. 逾期未签任务可单独筛出，并出现在审计报表中。
  3. 按年度汇总可见各类核对任务的完成率与逾期清单（年度全覆盖）。
  4. 核对任务与签署记录在审计侧**只读**，不存在修改或删除入口。
  5. 审计岗可跨子账户查询核对任务。

## 4. 模块内规则

| 规则编号 | 规则内容 | 适用 FR | 说明 |
|---------|---------|---------|------|
| `R-AUDIT-1` | **追溯链六段齐备且含子账户维度（⬅ 红线）**：完整链条 = `实货敞口 → 套保计划 → 审批 → 交易 → 结算 → 会计凭证`；**每段均须可展示子账户标识**；正向与反向**必须互通**（从敞口可到凭证，从凭证可到敞口）；**期权与期货走同一条链**，不得旁路 | `FR-AUDIT-1`、`FR-AUDIT-2`、`FR-AUDIT-3` | `PROJECT.md` §4.1 ⑦ + §4.1.C「⑦ 审计：追溯链须包含子账户维度」；对应成功标准 16 |
| `R-AUDIT-2` | **断点必须显式标记，不得粉饰**：追溯链存在缺失环节时**必须**输出"存在断点"并列出位置与对象标识；**任何报表与导出在链条不完整时均须带"链条不完整"标注**；**在途业务**（已成交未结算、未出凭证）标注为"在途"，**不计为断点**；**严禁**在存在断点时输出"链条完整"结论 | `FR-AUDIT-3`、`FR-AUDIT-4`、`FR-AUDIT-8`、`FR-AUDIT-12`、`FR-AUDIT-5` | 审计的诚信底线；有断点却输出完整，等同于伪造证据 |
| `R-AUDIT-3` | **留痕范围与不可篡改**：留痕范围至少覆盖——计划提交/审批/终止、指令提交/人工确认、风控拒绝、资金转账与划拨、权限与授权变更、系统配置变更、结算确认与差异处理、会计凭证审核。每条含**操作人、时间、对象、动作、结果、子账户**；**只增不改不删**；系统**不得**提供修改或删除历史留痕的入口 | `FR-AUDIT-5`、`FR-AUDIT-6`、`FR-AUDIT-7`、`FR-AUDIT-11`、`FR-AUDIT-12`、`FR-AUDIT-9` | `PROJECT.md` §4.1 ⑦「审计日志（不可篡改的操作留痕）」 |
| `R-AUDIT-4` | **审计日志自身可校验且写入失败须中断**：审计日志须**可校验未被篡改**；**校验未通过须告警并阻断**后续导出；**审计日志写入失败时，被记录的导出操作必须中断**（审计行为本身也必须留痕——不记录即不允许发生） | `FR-AUDIT-8`、`FR-AUDIT-9`、`FR-AUDIT-10` | 审计的可信性前提 |
| `R-AUDIT-5` | **重大事项触发条件**：① 加总对账不一致且超时未闭环；② 触及规模红线；③ 被交易所问询或收到警示；④ 强制平仓提示未处置；⑤ 单笔或当日亏损超阈值（可配置）。命中即**自动提醒**生成专项报告 | `FR-AUDIT-7` | 8 号文六「报告制度」 |
| `R-AUDIT-6` | **审计只读，不反向写入**：`AUDIT` **只读**其它模块数据；**不得**通过审计界面修改任何业务数据；审计操作（查询与导出）**只写审计日志**，不写业务数据 | `FR-AUDIT-1`、`FR-AUDIT-2`、`FR-AUDIT-8` | 审计独立性 |
| `R-AUDIT-7` | **筛查口径与 `RISK` / `TRADE` 一致**（源自变更 `CH-002`；判定口径澄清见 `CH-004`）：违规事项筛查复用 `RISK` 的规则编号与阈值口径（超品种/超规模/超期限/超授权/频繁开平仓，其中频繁开平仓按 `Q-5` 的 6/10/5/3 口径），**不得**在审计侧另立一套判定标准；**理由缺失（`REASON_MISSING`）**与**关联对象缺失（`RELATED_MISSING`）**为审计侧**两个并列独立**维度（`Q-13`），**不得合并**——理由缺失 = 无理由记录或理由内容为空；关联对象缺失 = 理由已填但关联对象未提供（带关联对象缺失标记）；筛查须能**分别命中两者** | `FR-AUDIT-4` | 防止两套口径导致结论矛盾 |
| `R-AUDIT-8` | **筛查可复现**：每次筛查须记录**筛查条件、时间、执行人**，使结论可在日后复现；**不得**输出无法复现的筛查结论 | `FR-AUDIT-4` | 审计结论须经得起质证 |
| `R-AUDIT-9` | **软隔离下的审计权限**：审计岗**默认可被授予跨子账户查看权限**（软隔离，`FR-AUTH-13`）；未被授权时**仅可查看授权范围内数据并明示权限边界**，**不得**因权限不足而输出误导性的"无违规"结论 | `FR-AUDIT-1`、`FR-AUDIT-2`、`FR-AUDIT-4`、`FR-AUDIT-8` | `PROJECT.md` §4.1.B「软隔离」 |
| `R-AUDIT-10` | **报告周期可配置**：每日/每月/每季度/每年与重大事项触发的报告节奏由 `CONFIG` 配置（`FR-CONFIG-15`）；**周期到达而未生成时须提醒**（不得静默缺失） | `FR-AUDIT-5`、`FR-AUDIT-6`、`FR-AUDIT-7` | 8 号文报告要求 |
| `R-AUDIT-11` | **年度审计全覆盖核对任务与签署记录**（源自变更 `CH-002`，`Q-14`）：审计须可查询全部**核对任务与签署记录**（账号 / 角色 / 时间 / IP / 核对对象快照哈希）；**逾期未签清单须进审计报表**；**年度审计须覆盖全部月度/季度/年度核对任务**；核对任务与签署记录在审计侧**只读**；**管理层签署权与交易权互斥**须可核验（管理层仅签收、不操盘） | `FR-AUDIT-6`、`FR-AUDIT-13`、`FR-AUDIT-8` | 8 号文核对要求；与 `SETTLE.md` `R-SETTLE-11` 对应 |
