## 1. 模块概述

- **职责**：**完整的资金记账**（期初余额、出入金、调拨、盈亏结转、手续费、保证金占用变动、期末余额，每笔带凭证编号）+ **子账户独立资金** + **子账户间划拨（系统内记账）** + **出入金（经 CTP 由期货公司完成银期划转）** + **资金额度控制** + **保证金占用视图**。
- **解决的业务问题**：不解决则资金**无账可查**——各子账户资金无法独立管理与调拨，保证金占用与可用资金看不见，资金上限失控；同时 8 号文要求的"对保证金等资金账户实行专门管理，规范资金划拨和使用程序，加强日常监控"全部缺失。
- **上游模块**：`TRADE`（成交→手续费与保证金变动）、`SETTLE`（结算盈亏与保证金口径）、`AUTH`（资金岗权限与双人复核、子账户数据权限）、`CONFIG`（子账户定义、资金额度上限参数）、`PLAN`（计划与额度占用关系）
- **下游模块**：`SETTLE`（资金台账是资金核对的输入）、`ACCT`（资金流水用于会计处理）、`AUDIT`（资金流水与划拨记录进入审计）、`RISK`（保证金与风险度）

> ⚠️ **银期转账的关键设计**（`PROJECT.md` §4.1 ⑨-a）：
> **本系统不与企业侧银行直连。** 出入金通过 **CTP 的资金接口**发起，
> 由**期货公司**在银行侧完成划转。银行通道、前置机、三方协议**均由期货公司承担**，不在本项目范围内。
> 系统职责：**发起指令、审批、台账记账**；**通过 CTP 提交划转请求**；**以期货公司回执为准更新台账**。
>
> ⚠️ **与 `SETTLE` 的边界**：`FUND` 管**资金流水的记录与调拨**；
> `SETTLE` 管**与期货公司的每日核对**及**子账户加总校验**。两者**共享资金台账**，职责不重叠。

## 2. 数据字典

> ⚠️ **边界红线**：本节只写**业务概念**——业务名称、业务语义、业务约束、
> 枚举值的**业务含义**。**不写**列名、数据类型、长度、索引、存储格式。

| 数据项 | 业务名称 | 业务语义 | 业务约束 | 枚举值业务含义 |
|--------|---------|---------|---------|--------------|
| 资金台账 | 资金台账 | 记录各子账户资金状况的台账（期初、发生、期末） | **按子账户独立**（`INDEX.md` §2.1「资金类」）；**必须可直接求和**以支持加总对账；与 `SETTLE` **共享同一台账**，不得两处各维护一套余额 | — |
| 期初余额 | 期初余额 | 某子账户在某记账日的起始资金 | 由上日期末余额结转，**不得手工改写**（如与真实账户不一致须通过差异调整并留痕） | — |
| 期末余额 | 期末余额 | 某子账户在某记账日的结余 | **必须满足**：期初余额 + 当日发生额合计 = 期末余额 | — |
| 资金流水 | 资金流水 | 资金台账中的每一笔发生额记录 | **每笔均有凭证编号与操作留痕**；**只增不改不删**；**可按子账户、日期、类型查询与导出对账** | 类型：**入金**／**出金**／**子账户划拨（出）**／**子账户划拨（入）**／**盈亏结转**／**手续费**／**保证金占用变动**／**差异调整** |
| 凭证编号 | 凭证编号（资金） | 每笔资金流水的唯一业务编号 | 全系统唯一；**一经分配不得修改**；被审计追溯引用 | — |
| 出入金申请 | 出入金申请 | 向真实期货账户转入/转出资金的申请 | **须双人复核**（发起人与审批人不得为同一人）；**经 CTP 发起**；**以期货公司回执为准**；**不得**假设同步返回 | 状态见 §2.1 |
| 银期转账 | 银期转账 | 经 CTP 由期货公司完成的银行—期货资金划转 | 银行侧执行**属期货公司职责**，不在本项目范围；系统只负责发起与记账 | — |
| 划拨申请 | 子账户划拨申请 | 子账户 A → 子账户 B 的资金调整申请 | **为系统内记账调整**，真实期货账户资金**不变动**；**须审批与完整留痕**；**划拨后各子账户资金加总须仍等于真实账户可用资金**；**当日加总对账存在未闭环差异时**：**仅差异所属子账户**的划拨被阻断，**不波及其他子账户**（`Q-11`，源自变更 `CH-001`） | 状态见 §2.1 |
| 划拨方向 | 划拨方向 | 划拨在某一子账户上的资金流向 | 一次划拨在**两个子账户**上各生成一条流水（一出一入，金额相等） | **划出**／**划入** |
| 资金额度 | 资金额度 | 按子账户/账户设定的资金上限 | 按**子账户 / 账户**设定；超限**告警**；额度参数可配置（`CONFIG`） | 维度：**子账户**／**账户（全账户）** |
| 保证金占用 | 保证金占用 | 某子账户被合约持仓占用的保证金 | 按子账户计；与 `SETTLE` 口径一致；变动须形成资金流水（`保证金占用变动`） | — |
| 可用资金 | 可用资金 | 某子账户当前可用于新开仓的资金 | 按子账户计；与 `SETTLE` 的可用资金口径一致 | — |
| 风险度 | 风险度 | 保证金占用与权益的比例 | 用于资金风险评估；阈值超限告警 | — |
| 回执 | 回执 | 期货公司经 CTP 返回的资金划转结果 | **唯一到账依据**；网络超时**不代表未到账**；**不得**以本地乐观状态替代回执 | 结果：**成功**／**失败**／**处理中**／**未知（超时待查）** |
| 幂等标识 | 幂等标识 | 用于防止重复提交导致重复划转的业务标识 | 每次提交须携带；**同一幂等标识重复提交不得产生第二笔划转** | — |
| 资金密码 | 资金密码 | CTP 资金接口所需的敏感凭证 | **零落盘**——不落配置文件、不入库、不写日志；**仅内存持有**，每次启动手工填写（`NFR-SEC-1`） | — |

### 2.1 状态机

**出入金申请**：

```
  待提交 ──提交──→ 待复核 ──复核通过──→ 已提交（等待 CTP 回执）
                     │                       │
                 驳回│              ┌────────┼────────┐
                     ↓              ↓        ↓        ↓
                  已驳回         已成功    已失败   超时待查
                                            │        │
                                       重试/冲正    查询确认
```

| 状态 | 业务含义 | 可执行操作 | 后续状态 |
|------|---------|-----------|---------|
| **待提交** | 申请已录入，未提交 | 修改、删除、提交 | 待复核 |
| **待复核** | 已提交，等待审批人复核（**不得为发起人**） | 复核（通过/驳回）、撤回 | 已提交 / 已驳回 |
| **已提交** | 已复核通过，经 CTP 发出，等待回执 | 查询回执 | 已成功 / 已失败 / 超时待查 |
| **已成功** | 收到成功回执，台账已更新 | 查看 | 终态 |
| **已失败** | 收到失败回执 | 查看、重试（新申请） | 终态 |
| **超时待查** | 未收到回执 | **主动查询确认**；**不得**假设失败或成功 | 已成功 / 已失败（以查询结果为准） |
| **已驳回** | 复核未通过 | 查看、修改后重新提交 | 终态 |

**子账户划拨申请**：

```
  待提交 ──提交──→ 待审批 ──审批通过──→ 已记账（记账完成 + 加总校验通过）
                     │                      │
                 驳回│                 加总不通过 → 已回滚
                     ↓
                  已驳回
```

| 状态 | 业务含义 | 可执行操作 | 后续状态 |
|------|---------|-----------|---------|
| **待提交** | 申请已录入 | 修改、删除、提交 | 待审批 |
| **待审批** | 已提交，等待审批（**不得为发起人**） | 审批（通过/驳回）、撤回 | 待记账 / 已驳回 |
| **待记账** | 审批通过，尚未记账 | 执行记账（同步更新两个子账户） | 已记账 / 已回滚 |
| **已记账** | 记账完成且加总校验通过 | 查看 | 终态 |
| **已回滚** | 加总校验不通过，已回滚本次记账 | 查看、重新发起 | 终态 |
| **已驳回** | 审批未通过 | 查看 | 终态 |

**状态流转规则**：见 §4 `R-FUND-1`、`R-FUND-3`、`R-FUND-5`。

## 3. 功能性需求

> **编号规范**：`FR-FUND-<序号>`，序号在**本模块内**从 1 递增，不复用。

### FR-FUND-1 建立子账户资金台账

- **描述**：作为资金岗，我希望为每个子账户建立独立的资金台账，以便各业务线的资金各自清晰。
- **输入**：子账户标识、初始资金、记账起始日、初始凭证编号
- **处理规则**：见 `R-FUND-1`。**每个子账户一份台账**且**必须显式携带子账户标识**；台账**必须可直接求和**以支持 `FR-SETTLE-3` 与 `FR-SETTLE-8`；初始资金的建立须**双人复核**并留痕；台账与 `SETTLE` **共享同一数据源**，**不得**两处各维护一套余额
- **输出**：成功 → 台账建立，期初余额设定；失败 → 明确错误（子账户不存在/未启用 / 初始资金非法 / 复核人缺失）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 为子账户 A、B 分别建立台账，各自期初余额正确。
  2. 两个子账户期初余额之和等于真实账户初始资金。
  3. 台账记录**显式携带子账户标识**（`INDEX.md` §2.1「资金类」）。
  4. 建立台账操作有双人复核留痕。

### FR-FUND-2 记录资金流水

- **描述**：作为资金岗，我希望系统记录每一笔资金发生额，以便资金账实相符、可导出对账。
- **输入**：子账户、流水类型（入金/出金/划拨出/划拨入/盈亏结转/手续费/保证金占用变动/差异调整）、金额、发生日期、关联对象标识（交易/结算/划拨单）、凭证编号
- **处理规则**：见 `R-FUND-2`。**每笔流水必须带凭证编号与操作留痕**；**必须满足期初 + 发生额 = 期末**；流水**只增不改不删**；**差异调整类流水须双人复核**；流水须可**按子账户、日期、类型查询与导出对账**
- **输出**：成功 → 流水创建并更新台账期末余额；失败 → 明确错误（金额非法 / 类型缺失 / 子账户缺失 / 凭证编号重复）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 录入一组完整资金流水（期初、出入金、调拨、盈亏结转、手续费、保证金变动），核对**期初 + 发生额 = 期末**（对应 `PROJECT.md` §10 成功标准 19）。
  2. 每笔流水均含凭证编号与操作人。
  3. 流水不存在编辑或删除入口。
  4. 流水可导出且与台账期末余额一致。

### FR-FUND-3 查询资金流水台账

- **描述**：作为资金岗、结算岗或审计/合规岗，我希望按条件查询资金流水与台账，以便核对资金变动。
- **输入**：筛选条件（子账户、日期范围、流水类型、金额区间、凭证编号、关联交易）、排序、分页；是否展示期初/期末
- **处理规则**：默认按发生日期与凭证编号升序（便于对账）；**仅返回有权限的子账户范围**（审计岗可跨子账户，`FR-AUTH-13`）；展示时须含**期初余额、发生额明细、期末余额**三部分；**同时提供汇总视图**（汇总 = 各子账户之和，用于加总对账）
- **输出**：资金流水台账视图；空结果返回空列表
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 按日期范围 + 子账户查询，结果按期排序且含期初、明细、期末。
  2. 汇总视图的期末余额等于各子账户期末余额之和。
  3. 子账户 A 用户看不到子账户 B 的流水。
  4. 审计岗可跨子账户查询。

### FR-FUND-4 导出资金对账

- **描述**：作为资金岗或结算岗，我希望导出资金对账表，以便与期货公司对账及归档。
- **输入**：导出口径（日期范围、子账户）、是否含凭证编号
- **处理规则**：**仅导出有权限的子账户范围**；导出须含**期初余额、各类型发生额小计、期末余额、凭证编号**；须含**子账户小计与全账户合计**（便于加总对账）；文件含导出时间与导出人；无数据时不生成空文件
- **输出**：CSV 对账表；失败 → 明确提示
- **优先级**：P1
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 导出的对账表中，期初 + 发生额小计 = 期末，且与界面一致（对应 `PROJECT.md` §10 成功标准 19）。
  2. 导出含子账户小计与全账户合计。
  3. 每笔流水带凭证编号。
  4. 无数据时不生成文件并给出提示。

### FR-FUND-5 发起入金申请（经 CTP）

- **描述**：作为资金岗，我希望发起向真实期货账户转入资金的申请，以便补充可用资金。
- **输入**：入金金额、目标子账户（用于记账归属）、资金来源说明、幂等标识
- **处理规则**：见 `R-FUND-4`、`R-FUND-5`。**须经双人复核**后方可经 CTP 发起；**必须携带幂等标识**，同一标识重复提交**不得产生第二笔划转**；**不得假设同步返回**——按 CTP **异步回调模型**处理；**收到回执后方可记账**；入金回执成功后按目标子账户记账
- **输出**：成功 → 申请进入待复核，复核后经 CTP 提交；失败 → 明确错误（金额非法 / 缺少复核 / 幂等标识重复 / CTP 不可用）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 发起入金并复核后经 CTP 提交，在 CTP 模拟环境收到回执，台账自动更新（对应 `PROJECT.md` §10 成功标准 21）。
  2. 发起人与复核人为同一人时被拒绝（`FR-FUND-7`）。
  3. 使用相同幂等标识重复提交，**不产生**第二笔划转。
  4. 提交后系统**不阻塞等待**同步返回，状态为"等待回执"。

### FR-FUND-6 发起出金申请（经 CTP）

- **描述**：作为资金岗，我希望发起从真实期货账户转出资金的申请，以便调回富余资金。
- **输入**：出金金额、来源子账户（用于记账归属）、用途说明、幂等标识
- **处理规则**：见 `R-FUND-4`、`R-FUND-5`。**须经双人复核**；**出金前须校验来源子账户可用资金充足**；**必须携带幂等标识**；按 **CTP 异步回调模型**处理，**以回执为准**；**出金不得使子账户资金为负**
- **输出**：成功 → 申请进入待复核并可在复核后提交；失败 → 明确错误（可用资金不足 / 缺少复核 / 幂等标识重复 / 会使资金为负）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 发起出金并复核后经 CTP 提交，收到回执后端到端反向链路跑通（对应 `PROJECT.md` §10 成功标准 21）。
  2. 出金金额超过来源子账户可用资金时被拒绝。
  3. 发起人与复核人为同一人时被拒绝。
  4. 相同幂等标识重复提交不产生第二笔划转。

### FR-FUND-7 出入金双人复核

- **描述**：作为资金岗与审批人，我希望出入金与划拨须经双人复核，以便满足 8 号文与前中后台分离要求。
- **输入**：申请标识、复核结论（通过/驳回）、复核意见
- **处理规则**：见 `R-FUND-3`。**发起人与复核人不得为同一人**（系统级强制，不得仅靠制度）；**复核通过后方可经 CTP 提交**；**驳回须填写原因**；**复核记录（人、时间、结论、意见）永久留痕**；尝试用同一账号复核时**系统拒绝并记录越权尝试**（进入审计）
- **输出**：成功 → 状态流转并留痕；失败 → 明确错误（发起人=复核人 / 原因缺失 / 状态不允许 / 无权限）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 用同一账号发起并复核被系统拒绝（对应 `PROJECT.md` §10 成功标准 22）。
  2. 越权尝试被记录到审计日志。
  3. 驳回未填原因时被拒绝。
  4. 复核记录可在审计中查询到复核人、时间与意见。

### FR-FUND-8 处理 CTP 资金划转回执与异步回调

- **描述**：作为资金岗，我希望系统按 CTP 异步回调处理回执，以便台账与真实资金状态一致。
- **输入**：CTP 资金划转回执（成功/失败/处理中）、申请标识、幂等标识
- **处理规则**：见 `R-FUND-5`。**收到回执后方可更新台账**；**网络超时不代表未到账**——状态置为"超时待查"，须**主动查询确认**；重复回执须**幂等处理**（不得重复记账）；**失败回执时不得记账**（须记录失败原因）；回执须完整留痕并进入审计
- **输出**：成功 → 台账更新并生成资金流水（带凭证编号）；失败 → 状态"已失败"并记录原因；未知 → 状态"超时待查"并触发查询
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 收到成功回执后台账自动更新并生成带凭证编号的流水。
  2. 重复推送同一回执**不产生**重复流水（幂等）。
  3. 未收到回执时状态为"超时待查"，系统可通过查询接口确认最终结果。
  4. 失败回执不产生记账，且失败原因被记录。

### FR-FUND-9 出入金失败重试与幂等处理

- **描述**：作为资金岗，我希望系统对失败与超时的出入金做可追溯的重试与幂等处理，以便避免重复划转或资金悬空。
- **输入**：失败/超时的申请标识、重试动作、幂等标识
- **处理规则**：见 `R-FUND-5`。重试**必须复用或明确更换幂等标识**（更换须记录理由），**不得**因重试产生重复划转；**超时待查必须先查询确认原请求的真实结果**，确认未到账后方可重试；**重试与确认动作须留痕**；**系统不得自动重试**造成重复（须由资金岗确认）
- **输出**：成功 → 状态明确（已成功/已失败/继续待查）；失败 → 明确错误（未确认原请求结果 / 幂等冲突）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 对"超时待查"申请先执行查询确认，确认未到账后方可重试。
  2. 未确认原请求结果直接重试时被拒绝。
  3. 重试流程中不产生重复划转与重复流水。
  4. 查询确认与重试动作均有留痕。

### FR-FUND-10 发起子账户间资金划拨

- **描述**：作为资金岗，我希望发起子账户 A → 子账户 B 的资金划拨，以便在业务线之间调配资金（系统内记账，真实账户不变动）。
- **输入**：划出子账户、划入子账户、金额、划拨理由（**必填**）、期望生效日、幂等标识
- **处理规则**：见 `R-FUND-4`、`R-FUND-6`。**为系统内记账调整**，**真实期货账户资金不变动**；**划拨后各子账户资金加总须仍等于真实账户可用资金**；发起前须校验**划出子账户可用资金充足**且**划出/划入子账户当日加总对账无未闭环差异**——**仅阻断差异所属子账户**，**不波及其他子账户**（`Q-11`，源自变更 `CH-001`）；划出与划入**不得为同一子账户**；**不得**通过划拨绕过额度或风控限制
- **输出**：成功 → 申请创建为待提交（提交后进入待审批）；失败 → 明确错误（可用资金不足 / 同一子账户 / 理由缺失 / 存在未闭环差异）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 发起子账户 A→B 划拨后，A 减少、B 增加（对应 `PROJECT.md` §10 成功标准 37）。
  2. 划拨前后**加总金额不变**（对应成功标准 37）。
  3. 划出子账户可用资金不足时被拒绝。
  4. 划出与划入为同一子账户时被拒绝。

### FR-FUND-11 子账户划拨审批与留痕

- **描述**：作为审批人，我希望审批划拨申请并全程留痕，以便满足双人复核与审计要求。
- **输入**：划拨申请标识、审批结论（通过/驳回）、审批意见
- **处理规则**：见 `R-FUND-3`。**发起人与审批人不得为同一人**；审批通过后状态→待记账；**驳回须填原因**；审批记录永久留痕；划拨**审批人不得为交易岗**（岗位分离）；审批通过后须**生成资金流水（两条：一出、一入，金额相等，同一划拨单号关联）**
- **输出**：成功 → 状态流转并生成流水；失败 → 明确错误（发起人=审批人 / 原因缺失 / 岗位冲突 / 无权限）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 审批通过后生成两条关联的资金流水，金额相等、方向相反（对应 `PROJECT.md` §10 成功标准 37 的留痕要求）。
  2. 发起人尝试审批自己提交的划拨被拒绝。
  3. 驳回原因必填。
  4. 划拨全过程（申请、审批、记账、校验）在审计中可完整查询。

### FR-FUND-12 子账户划拨加总校验

- **描述**：作为资金岗与结算岗，我希望划拨后系统自动校验加总不变，以便证明划拨未改变真实资金。
- **输入**：划拨记账结果、划拨前后各子账户余额、真实账户可用资金
- **处理规则**：见 `R-FUND-6`。校验 **划拨后 Σ 子账户可用资金 = 真实账户可用资金** 且 **划拨前后加总金额相等**；**校验不通过须回滚本次记账并告警**（**不得**留下半完成的划拨）；校验结果须留痕并进入 `SETTLE` 的加总对账口径
- **输出**：通过 → 状态"已记账"；不通过 → 状态"已回滚" + 告警 + 差额明细
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 正常划拨后校验通过，状态为"已记账"。
  2. 人为构造使加总变化的场景，系统**回滚**本次记账并告警。
  3. 回滚后两个子账户余额恢复到划拨前。
  4. 校验结果可在 `FR-SETTLE-8` 的加总对账中查询到。

### FR-FUND-13 资金额度设定

- **描述**：作为资金岗或系统管理员，我希望按子账户与账户设定资金上限，以便控制资金占用规模。
- **输入**：额度维度（子账户/账户）、额度值、生效期
- **处理规则**：见 `R-FUND-7`。额度按**子账户 / 账户**两级设定；**不得**跨子账户挪用额度；额度是 `RISK` 与视图的输入；额度变更须留痕；**账户级额度不得超过真实账户可用资金上限**
- **输出**：成功 → 额度生效；失败 → 明确错误（额度为负 / 超过账户上限 / 无权限）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 为子账户 A 设定资金额度后，额度在该子账户视图可见。
  2. 账户级额度超过真实账户可用资金上限时被拒绝。
  3. 额度变更留痕含操作人、时间与前后值。
  4. 子账户额度与账户额度可分别查询。

### FR-FUND-14 资金额度超限告警

- **描述**：作为资金岗与风控责任人，我希望资金触及上限时告警，以便及时调整资金分布。
- **输入**：各子账户/账户资金占用、资金额度、告警阈值
- **处理规则**：见 `R-FUND-7`。资金占用**触及或超过额度上限**时**告警**（含子账户、当前占用、上限、告警级别）；告警须留痕并可查询；告警**不阻断**减仓与出金（`R-RISK-5` 原则）；告警级别（提示/警告/严重）按配置
- **输出**：告警记录；未超限时无告警
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 设定资金额度上限后，构造超限场景，验证告警触发（对应 `PROJECT.md` §10 成功标准 20）。
  2. 告警含子账户、当前占用、上限与级别。
  3. 告警不阻断出金与减仓。
  4. 告警记录可查询且无删除入口。

### FR-FUND-15 保证金占用视图（子账户 / 汇总）

- **描述**：作为资金岗、结算岗或风控责任人，我希望实时查看保证金占用、可用资金与风险度，以便掌握资金状况。
- **输入**：各子账户保证金占用、权益、可用资金、风险度、是否按品种细分
- **处理规则**：见 `R-FUND-8`。**可切换子账户 / 汇总视图**；**汇总 = 各子账户之和**；**实时展示**已占用保证金、可用资金、风险度；须与 `SETTLE` 的保证金口径**一致**（同一数据源）；风险度超阈值时与 `RISK` 的事中风控告警联动
- **输出**：保证金占用视图（子账户/汇总，按品种可细分）；失败 → 数据未就绪时明确提示
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 视图可切换子账户与汇总，汇总等于明细之和。
  2. 实时展示已占用保证金、可用资金与风险度。
  3. 与 `FR-SETTLE-11` 的保证金数据一致。
  4. 风险度超阈值时出现告警。

### FR-FUND-16 资金流向与划拨记录查询

- **描述**：作为资金岗或审计/合规岗，我希望查询资金流向与划拨记录，以便核对与审计。
- **输入**：筛选条件（时间范围、子账户、流水类型、划拨单号）、排序、分页
- **处理规则**：**仅返回有权限的子账户范围**（审计岗可跨子账户）；划拨记录须**成对展示**（一出一入、同一划拨单号、金额相等）；须展示**划拨的申请人与审批人**（证明双人复核）；记录只读
- **输出**：资金流向与划拨记录列表；空结果返回空列表
- **优先级**：P1
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 查询某划拨单号，返回成对的两条记录，金额相等、方向相反。
  2. 每条划拨记录显示申请人与审批人且两者不同。
  3. 记录不存在编辑或删除入口。
  4. 审计岗可跨子账户查询。

### FR-FUND-17 每日资金对账

- **描述**：作为资金岗与结算岗，我希望每日完成资金对账，以便与 `SETTLE` 的资金核对衔接。
- **输入**：当日资金流水、期初/期末余额、真实账户资金明细、`SETTLE` 的资金核对结果
- **处理规则**：见 `R-FUND-8`。对账须校验 **期初 + 发生额 = 期末**（按子账户）与 **Σ 子账户 = 真实账户**（与 `FR-SETTLE-8` **同口径、同结果**，不得出现两处结论不同）；对账结论须留痕并进入每日结算报告；**存在未闭环差异时不得标记对账完成**
- **输出**：成功 → 对账结论并留痕；不一致 → 差异清单且**不得标记完成**
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 正常跑完一日，资金对账结论为"一致"，且与 `FR-SETTLE-8` 结论相同。
  2. 构造差额时对账结论为"不一致"并输出差异清单。
  3. 存在未闭环差异时不得标记对账完成。
  4. 对账结论可在审计中查询。
