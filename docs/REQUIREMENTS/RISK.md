## 1. 模块概述

- **职责**：以**三级风控**（事前 / 事中 / 事后）承载 **6 类风险的 6 套机制**，并落实 8 号文的合规红线（90%/80% 规模红线、时点净持仓红线、12 个月期限红线、品种额度不得串用、超授权阻断）。
- **解决的业务问题**：不解决则交易**不受约束**——超额套保、品种错配、期限错配、频繁开平仓、会计文档缺失、敏感信息泄露六类风险全部敞口；交易所额度可能被调整或取消，乃至被强行平仓——**后果比不做套保更糟**。
- **上游模块**：`PRODUCT`（品种白名单与额度指标）、`SPOT`（实货敞口——规模红线与时点净持仓校验的实货口径）、`PLAN`（计划占用额度与期限）、`TRADE`（事件流——事中风控的镜像状态来源）、`SETTLE`（结算数据——事后风控输入）、`AUTH`（交易权限与授权）、`CONFIG`（风控参数与下发通道）
- **下游模块**：`TRADE`（事前风控阻断下单）、`PLAN`（提交前合规预校验引用本模块规则）、`AUDIT`（风险报表、违规事项、拒绝记录进入审计）、`ACCT`（违规事项影响会计处理）

> ⚠️ **架构硬约束**（`PROJECT.md` §4.1 ⑥ / §6）：
> **事前风控在 C++ 交易组件内全内存执行**，指令路径**零数据库 I/O**，不得引入同步 I/O、锁竞争或阻塞调用；
> **事中与事后风控在 Java 业务组件内**，可访问数据库。
> 事前风控所需数据（品种、额度、持仓、参数）**必须常驻 C++ 内存**，由 Java 侧经**控制指令**显式下发，
> **不得依赖定时轮询**。

### 2.1 状态机

**事前风控校验**：

```
  待校验 ──→ 通过 ──→ （指令进入待人工确认）
        └──→ 拒绝 ──→ （拒绝记录落库，指令终止）
        └──→ 系统未就绪 ──→ （C++ 重放未完成，拒绝新指令）
```

| 状态 | 业务含义 | 可执行操作 | 后续状态 |
|------|---------|-----------|---------|
| **通过** | 全部规则校验通过，允许进入人工确认 | — | 终态（交 `TRADE` 流程） |
| **拒绝** | 至少一条规则不通过，**不发往 CTP** | 查看规则编号与原因 | 终态 |
| **系统未就绪** | C++ 组件重启后重放未完成，**拒绝一切新指令** | 查看重放进度 | 终态（重放完成后需重新提交） |

**事中风控告警**：

```
  正常 ──指标超阈值──→ 已告警 ──人工/系统处置──→ 处置中 ──→ 已恢复
                        │                                  │
                        └────指标持续恶化────→ 已限制开仓 ──┘
```

| 状态 | 业务含义 | 可执行操作 | 后续状态 |
|------|---------|-----------|---------|
| **正常** | 全部指标在阈值内 | — | 已告警 |
| **已告警** | 至少一项指标超阈值 | 处置（限制开仓等）、查看 | 处置中 |
| **已限制开仓** | 已限制新开仓（平仓不受限） | 处置、查看 | 已恢复 |
| **已恢复** | 指标回到阈值内且处置完成 | 查看 | 终态 |

**状态流转规则**：见 §4 `R-RISK-3`、`R-RISK-5`。（⚠️ **待确认**：`R-RISK-3`（空间甲＝「事前风控全内存 · 零 DB 访问」）与本节两条状态机**无显式对应**，**原意待确认、本轮未改动此引用**；`R-RISK-5` 对应事中「已限制开仓（平仓不受限）」态。）

## 3. 功能性需求

> **编号规范**：`FR-RISK-<序号>`，序号在**本模块内**从 1 递增，不复用。

### FR-RISK-1 事前风控：品种白名单校验

- **描述**：作为风控责任人，我希望下单前校验品种是否在子账户白名单内，以便防止**品种错配**风险。
- **输入**：指令的品种、合约、子账户标识、C++ 内存中的该子账户白名单
- **处理规则**：见 `R-RISK-1 @ ARCHITECTURE.md §3.3`、`R-PRODUCT-5`。校验**按子账户**取白名单；品种不在白名单 → **拒绝**；合约不属于该品种或为境外/场外 → **拒绝**；**纯内存判断，零数据库 I/O**
- **输出**：通过 / 拒绝（输出规则编号 `R-RISK-1 @ ARCHITECTURE.md §3.3` + 原因：品种未在子账户白名单内 / 合约与品种不符 / 非境内场内合约）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 用未列入子账户 A 白名单的品种下单，事前风控拒绝且**未发往 CTP**。
  2. 用该品种在已列入白名单的子账户 B 下单，校验通过。
  3. 拒绝记录含规则编号与原因，并可在 `FR-TRADE-17` 中查询到。
  4. 校验过程不产生数据库 I/O。

### FR-RISK-2 事前风控：额度校验（三层限额）

- **描述**：作为风控责任人，我希望下单前按子账户与总账户两个维度校验可用额度，以便防止**超额套保**与额度串用。
- **输入**：指令的子账户、品种、计划 ID、数量、价格、C++ 内存中的子账户额度与总账户额度
- **处理规则**：见 `R-RISK-2`。**三层限额校验**（源自变更 `CH-002`，`Q-16`）：① **子账户 + 品种**（主维度）② **子账户 + 合约**（可选）③ **账户 + 品种**（总账户，防串用）。**单笔按最细命中者校验**；**累计三层同时校验，任一超限即拒绝**。**额度不得跨品种、跨子账户借用或串用**；占用口径为**下单冻结**（`R-TRADE-10`）；**纯内存判断**
- **输出**：通过 / 拒绝（**必须区分**命中的限额层级，并给出规则编号、当前值、阈值）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 构造"**子账户 + 品种维度超限但总账户未超**"场景，阻断生效（对应 `PROJECT.md` §10 成功标准 35）。
  2. 构造"**账户 + 品种维度超限**"场景，阻断生效（对应成功标准 35）。
  3. 构造"**子账户 + 合约**"更细维度超限场景，单笔按最细命中者阻断。
  4. 尝试用品种 A 的额度为品种 B 下单，被拒绝（额度不得串用）。
  5. 拒绝信息中区分命中的限额层级，并给出当前值与阈值。

### FR-RISK-3 事前风控：持仓上限校验

- **描述**：作为风控责任人，我希望下单前校验持仓上限，以便防止单一子账户或合约持仓过度集中。
- **输入**：指令的子账户、品种、合约、方向、数量、C++ 内存中的当前持仓与持仓上限
- **处理规则**：见 `R-RISK-3 @ ARCHITECTURE.md §3.3`。**按子账户 + 品种（或合约）**校验持仓上限；平仓指令**不受持仓上限限制**（防止无法减仓）；上限可配置（`FR-CONFIG-5`）；**纯内存判断**
- **输出**：通过 / 拒绝（规则编号 + 预计持仓、上限、超出量）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 开仓使预计持仓超过上限时被拒绝，提示预计持仓与上限。
  2. 平仓指令在持仓达上限时**仍可提交**（不被上限阻断）。
  3. 上限参数变更并经控制指令下发后，新上限立即生效。
  4. 校验过程不产生数据库 I/O。

### FR-RISK-4 事前风控：规模红线校验（90% / 80%）

- **描述**：作为风控责任人，我希望下单前校验年度保值规模是否触及规模红线，以便落实 8 号文硬指标。
- **输入**：品种（分类决定比例）、子账户、指令数量、C++ 内存中的**年度累计保值规模**与**实货经营规模**
- **处理规则**：见 `R-RISK-4`。**商品类 ≤ 实货经营规模 90%**；**贸易类 ≤ 80%**；比例为**该子账户分类**所决定（默认商品类，允许**品种级覆盖**，`R-PRODUCT-4`）；**触及红线即阻断新开仓**（平仓不受限）；**基数 = 年度现货敞口累计量（实物量口径）**——分子 = 年度累计新开仓保值数量（手数 × 合约乘数折算实物量），分母 = 该品种年度预计实物经营量（按品种 + 年度维护）；**按子账户与全账户双算、取严者**（源自变更 `CH-001`，`Q-1`）；拒绝时须给出**当前规模、基数、比例与红线值**
- **输出**：通过 / 拒绝（规则编号 + 当前使用率、红线比例、涉及品种与子账户）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 构造商品类年度保值规模触及实货经营规模 **90%**，系统在**下单前阻断**并给出明确提示（对应 `PROJECT.md` §10 成功标准 12）。
  2. 构造贸易类触及 **80%** 场景，同样阻断。
  3. 同一次校验中，商品类品种按 90%、贸易类按 80% 取值，**不得混用**。
  4. 拒绝信息中包含当前使用率与红线比例。

### FR-RISK-5 事前风控：时点净持仓校验

- **描述**：作为风控责任人，我希望校验时点净持仓不超过对应实货风险敞口，以便防止无实货支撑的持仓。
- **输入**：子账户、品种、方向、数量、C++ 内存中的当前净持仓与**该子账户该品种的实货风险敞口**
- **处理规则**：见 `R-RISK-5 @ ARCHITECTURE.md §3.3`。校验 **时点净持仓 ≤ 对应实货风险敞口**；**必须先按 `FR-PRODUCT-13` 换算到同口径**再比较；校验时点 = **下单瞬间**（事前，C++ 内存，**硬阻断**）+ **日终复核**（事后，告警并**次日限制新开仓**），**不做盘中逐笔重算**；敞口取**当日最新实货敞口快照**，校验记录须标注所用**快照时点**（源自变更 `CH-001`，`Q-3`）；**平仓方向（减少净持仓）不受限**；**纯内存判断**（实货敞口由 Java 侧经控制指令下发至 C++ 内存）
- **输出**：通过 / 拒绝（规则编号 + 当前净持仓、实货敞口、超出量）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 构造"计划已用满再下单"场景，系统在**下单前阻断**（对应 `PROJECT.md` §10 成功标准 13）。
  2. 敞口数量与持仓数量口径不一致时先换算再比较，结果与手工计算一致。
  3. 减少净持仓（平仓）方向的指令不被阻断。
  4. 拒绝信息含当前净持仓与实货敞口数值。

- **输入**：筛选条件（子账户、时间范围、指标类型、告警级别、处置状态）、排序、分页
- **处理规则**：默认按时间倒序；**仅返回有权限的子账户范围**（审计岗可跨子账户）；须展示**指标值、阈值、告警级别、处置动作与处置人**；历史记录只读；**不得**提供删除告警记录的入口
- **输出**：风险指标与告警历史列表；空结果返回空列表
- **优先级**：P1
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 按告警级别筛选结果正确。
  2. 每条告警可见其处置动作与处置人（未处置的显式标注"未处置"）。
  3. 历史记录不存在编辑或删除入口。
  4. 审计岗可跨子账户查询。
