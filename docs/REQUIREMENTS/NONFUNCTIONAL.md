## 1. 性能 NFR-PERF

- **`NFR-PERF-1`**：**事前风控单笔判定耗时 P99 ≤ 5 ms，上限 ≤ 10 ms**；判定路径中**数据库 I/O 次数 = 0**；**不得**出现同步 I/O、锁竞争或阻塞调用。
  - 适用范围：全局（核心架构约束，`RISK` `FR-RISK-1`～`FR-RISK-8`；`TRADE` `FR-TRADE-3`）
  - 验证方式：在 C++ 组件中对判定函数做基准测试（≥ 10 万次调用）统计 P99；用 DB 层全量语句审计跑 100 笔下单，交易路径对应 SQL 记录数须为 **0**（对应 `PROJECT.md` §10 成功标准 23、24）

- **`NFR-PERF-2`**：**交易岗人工确认后，指令发出至到达 CTP 的耗时 P95 ≤ 50 ms**。
  - 适用范围：`TRADE` `FR-TRADE-2`
  - 验证方式：在 CTP 模拟环境压测 100 笔指令，统计确认到发往柜台的时间差

- **`NFR-PERF-3`**：**资金台账与会计凭证查询 P95 < 2 s**（秒级响应），数据量 1 万条流水 / 1 万条凭证下成立。
  - 适用范围：`FUND` `FR-FUND-3`、`ACCT` `FR-ACCT-8`
  - 验证方式：造 1 万条流水与 1 万条凭证数据，执行典型查询并统计 P95（对应 `PROJECT.md` §6「性能要求」）

- **`NFR-PERF-4`**：**业务列表查询（含筛选、排序、分页）在 1 万条数据下 P95 < 2 s**。
  - 适用范围：`PRODUCT` `FR-PRODUCT-5`、`SPOT` `FR-SPOT-4`/`FR-SPOT-7`/`FR-SPOT-15`、`PLAN` `FR-PLAN-4`、`TRADE` `FR-TRADE-7`/`FR-TRADE-8`、`SETTLE` `FR-SETTLE-15`、`RISK` `FR-RISK-19`、`AUDIT` `FR-AUDIT-11`
  - 验证方式：造 1 万条数据后按典型筛选条件执行查询，统计 P95；关键字段须有索引（索引设计属 S2）

- **`NFR-PERF-5`**：**行情端到端推送延迟 P95 ≤ 200 ms**（CTP 行情 → 前端展示）。
  - 适用范围：`TRADE` `FR-TRADE-12`
  - 验证方式：在行情活跃时段对比柜台时间戳与前端渲染时间戳，采样 ≥ 1000 次统计 P95

- **`NFR-PERF-6`**：**事件流吞吐 ≥ 1000 事件/秒，且不丢、不乱序**。
  - 适用范围：`TRADE` `FR-TRADE-14`、`RISK` `FR-RISK-11`
  - 验证方式：连续产生 1000 笔事件，核对 Java 侧接收数量与顺序与 C++ 发出**完全一致**（对应 `PROJECT.md` §10 成功标准 31）

- **`NFR-PERF-7`**：**日终结算（单日 1 万笔成交、10 个子账户）≤ 10 分钟**完成，含三类核对与加总对账。
  - 适用范围：`SETTLE` `FR-SETTLE-1`～`FR-SETTLE-8`
  - 验证方式：造 1 万笔成交与 10 个子账户数据，跑完整日终结算并计时

## 2. 可靠性 NFR-REL

- **`NFR-REL-1`**：**C++ 组件崩溃恢复——重启后 ≤ 60 秒完成指令流水重放**；**重放期间拒绝一切新指令**；重启后额度与持仓状态**无重复计入、无遗漏**。
  - 适用范围：`TRADE` `FR-TRADE-15`、`RISK` `FR-RISK-9`
  - 验证方式：在"已发 CTP 未收回报"场景强杀进程 → 重启 → 计时并核对额度与持仓（对应 `PROJECT.md` §10 成功标准 27）

- **`NFR-REL-2`**：**组件通信断连检测 ≤ 5 秒，重连后 ≤ 30 秒两侧状态最终一致**；**关键事件（成交、持仓、风控拒绝）零丢失**。
  - 适用范围：`TRADE` `FR-TRADE-14`、`CONFIG` `FR-CONFIG-9`
  - 验证方式：模拟 Socket 断开，测量检测与恢复时间，比对两侧状态（对应 `PROJECT.md` §10 成功标准 32）

- **`NFR-REL-3`**：**已确认的业务数据必须持久化且不丢失**——成交记录、资金流水、会计凭证、结算记录在系统重启与异常中断后完整可查；写入须**事务性**（部分失败不得留下半条记录）。
  - 适用范围：`TRADE` `FR-TRADE-5`、`FUND` `FR-FUND-2`、`ACCT` `FR-ACCT-6`、`SETTLE` `FR-SETTLE-4`
  - 验证方式：写入过程中模拟异常中断，重启后核对无半条记录、无丢失

- **`NFR-REL-4`**：**交易日（09:00–15:30）系统可用性 ≥ 99.5%**（不含计划内维护窗口）；**计划内维护须避开交易时段**。
  - 适用范围：全局
  - 验证方式：连续运行记录 + 维护窗口登记；可用性按"交易时段可用分钟数 / 交易时段总分钟数"计算

- **`NFR-REL-5`**：**全部外部回报与指令须幂等**——成交回报、委托回报、资金回执、结算数据重复推送时，**不得产生重复数据或重复记账**。
  - 适用范围：`TRADE` `FR-TRADE-4`/`FR-TRADE-5`、`FUND` `FR-FUND-8`、`SETTLE` `FR-SETTLE-1`
  - 验证方式：对同类回报重复推送 ≥ 3 次，核对数据条数与金额不变

- **`NFR-REL-6`**：**加总对账不一致时须在阻断生效前完成告警**——从检出不一致到告警可见**≤ 60 秒**，且**阻断立即生效**（不等待人工确认）。
  - 适用范围：`SETTLE` `FR-SETTLE-8`、`FUND` `FR-FUND-12`
  - 验证方式：构造不一致数据，计时告警可见时间，并验证后续操作被阻断（对应 `PROJECT.md` §10 成功标准 36）

## 3. 安全 NFR-SEC

- **`NFR-SEC-1`**：🔴 **零落盘红线（⬅ 硬约束）**——**密码、期货认证码（AuthCode）、资金密码**严禁写入**任何**持久化介质：**配置文件、数据库、日志、核心转储**。**仅内存持有**；**每次启动由用户手工填写**；**重启后须重新输入**。
  - 适用范围：全局（`CONFIG` `FR-CONFIG-1`/`FR-CONFIG-2`、`AUTH` `FR-AUTH-16`、`FUND` `FR-FUND-5`/`FR-FUND-6`）
  - 验证方式：**全库 grep + 日志 grep + 配置文件审计**三项零命中；重启后须重新输入（`PROJECT.md` §10 成功标准 4）。**验证时须包含核心转储文件与临时文件目录**

- **`NFR-SEC-2`**：**用户口令以加盐哈希存储**；**明文口令不得出现在任何日志与持久化文件中**；口令强度默认 **长度 ≥ 12 且含大小写字母、数字、符号**；**不得与最近 5 次相同**。
  - 适用范围：`AUTH` `FR-AUTH-16`、`FR-AUTH-14`
  - 验证方式：检查存储形式为加盐哈希；以弱口令与历史口令注册/修改均被拒；日志 grep 无明文

- **`NFR-SEC-3`**：**组件间 TCP 通信仅监听 `127.0.0.1`**，**不得**监听 `0.0.0.0` 或对外暴露端口；**必须启用连接鉴权**；**不得**以无鉴权的裸 TCP 通信；鉴权凭据**零落盘**。
  - 适用范围：`CONFIG` `FR-CONFIG-9`、`TRADE` `FR-TRADE-14`
  - 验证方式：`ss -lntp` 检查绑定地址为回环；尝试配置非回环地址被拒；关闭鉴权尝试被拒；鉴权失败产生告警

- **`NFR-SEC-4`**：**资金转账与子账户划拨必须双人复核**——**发起人与复核/审批人不得为同一人，系统级强制**；**审批人不得为交易岗**；越权尝试**系统拒绝并留痕**。
  - 适用范围：`FUND` `FR-FUND-7`/`FR-FUND-11`、`AUTH` `FR-AUTH-3`
  - 验证方式：同一账号发起并审批被拒（`PROJECT.md` §10 成功标准 22）；越权尝试在审计中可查

- **`NFR-SEC-5`**：**前中后台岗位分离系统级强制**——**交易岗、风控岗、结算岗三者两两互斥**（不得由同一人担任）；**资金岗与交易岗互斥**；**严禁企业负责人直接操盘**；**不得提供"超级管理员一键通办"的便利后门**；**系统不提供关闭互斥的配置项**。
  - 适用范围：`AUTH` `FR-AUTH-7`/`FR-AUTH-8`/`FR-AUTH-9`、`RISK` `FR-RISK-7`
  - 验证方式：尝试配置越权角色组合被拒；企业负责人尝试下单被拒；授权变更写入审计日志（`PROJECT.md` §10 成功标准 15）

- **`NFR-SEC-6`**：**审计日志与操作留痕不可篡改**——**只增不改不删**；**须提供防篡改校验能力**；**校验未通过须告警并阻断导出**；系统**不得提供**修改或删除历史日志的入口。
  - 适用范围：`AUDIT` `FR-AUDIT-10`/`FR-AUDIT-11`、`CONFIG` `FR-CONFIG-12`、`AUTH` `FR-AUTH-11`
  - 验证方式：人为修改底层日志数据后校验结论为"未通过"且导出被阻断；界面无删除入口

- **`NFR-SEC-7`**：**子账户数据软隔离**——**用户未被授权子账户时默认看不到任何子账户数据**（安全默认，**严禁默认全可见**）；**跨子账户查看权限仅管理层与审计岗可得且默认只读**；**数据权限与功能权限独立生效**。
  - 适用范围：`AUTH` `FR-AUTH-12`/`FR-AUTH-13`、全部业务模块的查询类 FR
  - 验证方式：以子账户 A 用户登录验证看不到 B 的数据；审计岗可跨账户查看；交易岗申请跨账户权限被拒（`PROJECT.md` §10 成功标准 34）

- **`NFR-SEC-8`**：**数据库访问账户遵循最小权限原则**——应用账户**不得具备建库、删库、授权等高危权限**；**禁止使用数据库超级账号连接**。
  - 适用范围：全局（Java 业务组件数据访问层）
  - 验证方式：以应用账户尝试 DDL/授权操作应失败；部署文档记录账户权限清单

- **`NFR-SEC-9`**：**C++ 交易组件中不得存在任何数据库访问代码**，**不得链接任何 DB 客户端库**，**静态扫描无 SQL 语句**。
  - 适用范围：`TRADE`、`RISK`（事前）、`FUND`（CTP 资金接口侧）
  - 验证方式：代码审查 + 链接检查 + 静态扫描（`PROJECT.md` §10 成功标准 29）

## 4. 兼容性 NFR-COMPAT

- **`NFR-COMPAT-1`**：**C++ 编译标准严格 C++11**（`CMAKE_CXX_STANDARD 11`）；**C++11 下零编译警告、零错误**；**不得使用** `std::make_unique`（C++14）、`std::optional` / `std::string_view` / 结构化绑定 / `if constexpr`（C++17+）；替代方案：`std::pair<T, bool>`、裸指针 + 显式生命周期管理、传统 SFINAE。
  - 适用范围：C++ 交易组件全部代码
  - 验证方式：以 `-std=c++11 -Wall -Wextra -Werror` 编译零警告；代码扫描无 C++14+ 特性（`PROJECT.md` §10 成功标准 6）

- **`NFR-COMPAT-2`**：**JDK 11 编译目标**；**不得使用 JDK 17+ 特性**（sealed classes、record 的部分用法、`switch` 模式匹配等）；可用 `var`、`HttpClient` 等 11 特性。
  - 适用范围：Java 业务组件全部代码
  - 验证方式：`maven-compiler-plugin` 设 `source/target=11` 编译通过；代码扫描无 17+ 特性

- **`NFR-COMPAT-3`**：**前端支持 Chromium 内核浏览器**（Chrome / Edge 最近两个大版本）；**不支持移动端浏览器**（本期不含移动端，`PROJECT.md` §4.2）。
  - 适用范围：前端全部页面
  - 验证方式：在 Chrome 与 Edge 最近两个大版本上完成全流程冒烟

- **`NFR-COMPAT-4`**：**运行环境为 Ubuntu 22.04 LTS**；双组件**同机双进程**部署（**非 JNI 同进程**）。
  - 适用范围：全局部署
  - 验证方式：在 Ubuntu 22.04 上完成部署与全流程验证；架构审查确认非 JNI

- **`NFR-COMPAT-5`**：**数据库为达梦 DM8，经标准 JDBC 访问**；**不得**使用 SQLite/MySQL/PostgreSQL；**禁止**存储过程、触发器、自定义函数；SQL 尽量使用标准语法，**使用 DM 特有语法须在代码注释中标注**；**DAO 层是唯一接触 SQL 的地方**。
  - 适用范围：Java 业务组件数据访问层
  - 验证方式：在 DM8 上完成建表、读写、查询；SQL 语法检查无 MySQL 方言残留；检查无存储过程/触发器/自定义函数依赖（`PROJECT.md` §10 成功标准 28、33）

- **`NFR-COMPAT-6`**：**对接 CTP 柜台**（期货与期权），采用 **CTP 官方 SDK（分离式：交易 / 资金 `ThostFtdcTraderApi` + 行情 `ThostFtdcMdApi`，同一 SDK）**；**按 CTP 异步 SPI 回调模型设计**，**不得假设同步返回**；**不得引入新依赖**。
  - **〔勘误 2026-09-22 · 免 `CH`〕**：原「采用 CTP 合并版 UserApi（行情 + 交易 + 资金划转同一 SDK）」→ **官方 CTP 分离式**（`TraderApi` + `MdApi`，「同一 SDK」语义保留）；动因＝交付基线经 `CH-015` 迁至官方 CTP v6.7.13；授权链＝实施方 `be-t033port` 移交 + 编排者派发（2026-09-22 批准）
  - 适用范围：`TRADE`、`FUND`、`RISK`（事前）
  - 验证方式：在 CTP 模拟环境完成期货开平与期权策略各一笔，并完成一笔模拟出入金（`PROJECT.md` §10 成功标准 10、21）

- **`NFR-COMPAT-7`**：**系统零外部数据依赖**——断开外网后（**保留 CTP 柜台连通**），**全部功能正常**；系统**不抓取、不订阅**任何第三方现货资讯源、不调用任何非 CTP 的外部服务。
  - 适用范围：全局
  - 验证方式：网络策略中封禁所有非 CTP 目标地址，跑通 M1–M4 全流程（`PROJECT.md` §10 成功标准 11）

## 5. 可维护性 NFR-MAINT

- **`NFR-MAINT-1`**：**前端零构建链**——代码库中**不存在** `package.json`、`node_modules`、打包产物；前端改动 = 直接编辑 `.html` / `.js` 源文件即可生效；**不得**引入 npm / Vite / React 等构建工具。
  - 适用范围：前端全部代码
  - 验证方式：全库搜索 `package.json` 与 `node_modules` **零命中**；修改源文件后刷新页面即生效（`PROJECT.md` §10 成功标准 7）

- **`NFR-MAINT-2`**：**最小依赖**——C++ 侧仅 `Boost::system`（websocketpp 必需）；Java 侧优先标准库；**引入新依赖须在架构文档中论证**。
  - 适用范围：双组件
  - 验证方式：审查构建文件的依赖清单，新依赖有对应论证记录

- **`NFR-MAINT-3`**：**数据访问分层**——**DAO 层是唯一接触 SQL 的地方**；业务逻辑**不得**内嵌 SQL；**表结构变更须先改 `docs/DATA_MODEL.md` 再改代码**，不得反向。
  - 适用范围：Java 业务组件
  - 验证方式：检查 DAO 层之外无 SQL 语句；抽查变更记录确认"文档先行"（`PROJECT.md` §5.2 / §10 成功标准 33）

- **`NFR-MAINT-4`**：**组件边界不可越界**——**C++ 组件不得访问数据库、不得承载业务逻辑**；**事前风控不得搬到 Java**；**Java 组件不得替代 C++ 的下单职责**。
  - 适用范围：双组件
  - 验证方式：代码审查 + 链接检查（对应 `PROJECT.md` §10 成功标准 29）

- **`NFR-MAINT-5`**：**前端与其它模块有效隔离**——前端**不得**直接访问数据库或 C++ 组件；前端只经 Java 业务组件内置 HTTP Server 提供的接口通信；**前端升级与后端互不影响**。
  - 适用范围：前端与 Java 业务组件
  - 验证方式：架构审查 + 前端代码中无直连数据库/组件的调用

- **`NFR-MAINT-6`**：**模块化与单一写库入口**——**只有 Java 写库**；C++ 经事件流交 Java 落库；**不得**出现第二个写库入口。
  - 适用范围：双组件
  - 验证方式：代码审查确认写库入口唯一；C++ 侧无 DB 客户端库链接

## 6. 可测试性 NFR-TEST

- **`NFR-TEST-1`**：**核心模块（方案计算、额度校验、会计生成）单元测试覆盖率 ≥ 80%**。
  - 适用范围：`PLAN`（套保比率三档计算）、`RISK`（额度与红线校验）、`ACCT`（凭证与文档生成）
  - 验证方式：以覆盖率工具统计，三类模块行覆盖率均 ≥ 80%（`PROJECT.md` §10 成功标准 8）

- **`NFR-TEST-2`**：**C++ 侧 `ctest` 全部通过；Java 侧 JUnit 5 全部通过**；测试可在**无 CTP 实盘环境**下运行（CTP 依赖可注入或打桩）。
  - 适用范围：双组件
  - 验证方式：CI 或本地执行 `ctest` 与 `mvn test`，全部用例通过

- **`NFR-TEST-3`**：**端到端冒烟可重复执行**——提供从"录入现货敞口 → 套保计划 → 下单 → 成交 → 结算 → 会计凭证"的可重复冒烟脚本；在 **CTP 模拟盘**环境下可一键跑通。
  - 适用范围：全局
  - 验证方式：连续执行冒烟 ≥ 3 次，每次结果一致且证据链完整（`PROJECT.md` §10 成功标准 1）

- **`NFR-TEST-4`**：**关键外部依赖可注入/可打桩**——**时钟、CTP 连接、数据库访问、组件通信**须有可替换的测试实现；**不得**把时间硬编码为系统当前时间而导致用例不可重复。
  - 适用范围：`TRADE`、`RISK`、`SETTLE`、`FUND`
  - 验证方式：审查代码中外部依赖的注入方式；验证同一用例在固定时钟下结果稳定

- **`NFR-TEST-5`**：**通信协议有专项测试**——覆盖**不丢、不乱序、断连重连、心跳、错误码**三类边界（对应 `PROJECT.md` §10 成功标准 31、32）。
  - 适用范围：`TRADE` `FR-TRADE-14`、`CONFIG` `FR-CONFIG-9`
  - 验证方式：提供协议专项测试用例集，1000 条消息比对数量与顺序

## 7. 易用性 NFR-USE

- **`NFR-USE-1`**：**新用户在不看文档的情况下，30 分钟内完成"录入现货 → 计算实货敞口"**。
  - 适用范围：`SPOT` `FR-SPOT-1`～`FR-SPOT-16`
  - 验证方式：选取 ≥ 3 名未受训的业务人员实测，成功率 100% 且平均耗时 ≤ 30 分钟

- **`NFR-USE-2`**：**交易岗从"查看交易计划"到"提交交易指令"的操作步数 ≤ 5 步**（不含人工确认）。
  - 适用范围：`TRADE` `FR-TRADE-1`
  - 验证方式：界面路径清点，操作步数 ≤ 5

- **`NFR-USE-3`**：**风控阻断类错误提示必须含"规则编号 + 当前值 + 阈值"三项**，且**不得**只给笼统提示（如"操作不允许"）。
  - 适用范围：`RISK` 全部事前校验、`PLAN` `FR-PLAN-10`、`SETTLE` `FR-SETTLE-8`、`FUND` `FR-FUND-10`
  - 验证方式：逐条构造阻断场景（≥ 8 类），检查提示中三项是否齐备（对应 `PROJECT.md` §10 成功标准 12、13、14）

- **`NFR-USE-4`**：**被阻断的操作须给出可执行的下一步提示**（如"请先建立品种映射""请先完成差异处理"），**不得**只报错不给路径。
  - 适用范围：全部阻断类 FR
  - 验证方式：随机抽取 10 个阻断场景，检查是否有明确的下一步提示

- **`NFR-USE-5`**：**子账户与汇总视图切换 ≤ 2 次点击**；**套保效果页须同屏展示实货盈亏与衍生品盈亏**（不得分页或跳转）。
  - 适用范围：`FUND` `FR-FUND-15`、`SETTLE` `FR-SETTLE-11`、`ACCT` `FR-ACCT-5`
  - 验证方式：界面操作清点；检查套保效果页两栏同屏（`PROJECT.md` §10 成功标准 18）

## 8. 可部署性 NFR-DEPLOY

- **`NFR-DEPLOY-1`**：**同机双进程部署**（C++ 交易组件进程 + Java 业务组件进程），**非 JNI 同进程**；**不得**部署到不同主机；**不得**依赖云服务、K8s 或外网中间件。
  - 适用范围：全局部署
  - 验证方式：部署拓扑审查 + 实际部署验证（`PROJECT.md` §5.3 第 5 项 / §6「部署环境」）

- **`NFR-DEPLOY-2`**：**部署时长 ≤ 30 分钟**（不含 DM8 数据库安装与操作系统准备）；提供**部署步骤清单**且可照做无歧义。
  - 适用范围：全局
  - 验证方式：在干净 Ubuntu 22.04 上按清单部署并计时

- **`NFR-DEPLOY-3`**：**构建可复现**——C++ 侧 **CMake ≥ 3.16 + FetchContent**（依赖随构建拉取），支持 `CTP_FOUND` / `CTP_USE_FETCH_DEPS` 条件宏双轨构建；Java 侧 **Maven** 构建；**构建须零警告零错误**。
  - 适用范围：双组件
  - 验证方式：在干净环境执行完整构建并计时；验证双轨构建两种路径均可用

- **`NFR-DEPLOY-4`**：**配置管理明确分级**——**本地 admin 配置可持久化**；**API 下发配置不落盘**；**敏感字段零落盘、启动手工录入**；**配置项清单须随部署文档交付**（含默认值、取值范围、是否可持久化）。
  - 适用范围：`CONFIG` 全部 FR
  - 验证方式：检查部署文档含配置清单；重启后非敏感配置保留、敏感字段须重新录入

- **`NFR-DEPLOY-5`**：**环境依赖须文档化**——包括 **DM JDBC 驱动的实测版本**（与客户 DM8 实例版本匹配）、CTP SDK 版本、JDK 11 版本、CMake 版本、浏览器要求；**须确认驱动在目标环境的可用性**。
  - 适用范围：全局
  - 验证方式：检查部署文档中的依赖清单含实测版本号（`PROJECT.md` §5.3 第 4 项要求"须在部署文档中记录实测版本"）
