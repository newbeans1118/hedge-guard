## 1. 模块概述

- **职责**：维护企业**可套保品种**的白名单、额度指标、分类管理标记，以及品种与期货合约、现货品类、计量单位的映射关系。
- **解决的业务问题**：不解决则交易端**无白名单可校验**——任何品种都可下单，直接违反 8 号文"交易品种应当与主业经营密切相关"与"品种分类管理，不同品种的规模指标不得相互借用、串用"；同时套保比率与敞口计算**缺少标的定义与单位口径**，无法与现货数据对齐。
- **上游模块**：`CONFIG`（子账户定义、系统参数）、`AUTH`（操作人授权范围：人员名单、品种、额度）
- **下游模块**：`SPOT`（品种与现货品类映射、计量单位）、`PLAN`（可用品种与额度指标）、`RISK`（品种白名单与额度指标是事前风控输入）、`TRADE`（下单品种校验）、`SETTLE`、`ACCT`、`AUDIT`

## 2. 数据字典

> ⚠️ **边界红线**：本节只写**业务概念**——业务名称、业务语义、业务约束、
> 枚举值的**业务含义**。
>
> **不写**：列名、数据类型、长度、索引、存储格式、是否为空的技术约束。
> 那些属于**技术实现**，由技术负责人在 S2 的 `DATA_MODEL.md` 中定义。

| 数据项 | 业务名称 | 业务语义 | 业务约束 | 枚举值业务含义 |
|--------|---------|---------|---------|--------------|
| 品种 | 品种 | 企业运营中可进行期货/期权套保的标的物。**一般是国内期货交易品种的子集**，非全市场品种 | 品种编码在**全系统唯一**；一经被套保计划或交易引用**不得删除**，只能停用 | — |
| 品种编码 | 品种编码 | 品种在全系统内的唯一业务标识 | 全系统唯一；**一旦使用不得修改** | — |
| 品种名称 | 品种名称 | 业务人员阅读使用的品种名称 | 不得为空；同一子账户内不得重复 | — |
| 品种状态 | 品种状态 | 品种是否可用于新编计划与下单 | 停用后**不得**用于新建套保计划与下单；已存在的历史数据保留 | **启用**＝可用于新建计划、下单与事前风控白名单；**停用**＝不可新建，历史数据只读 |
| 品种分类 | 品种分类 | 8 号文要求的分类管理标记，决定适用的规模红线比例 | 分类**默认挂在子账户上**（`sub_account.category=COMMODITY(90)/TRADE(80)`，默认商品类），**允许品种级覆盖**；分类**决定红线比例**（90% 或 80%），**不同分类的规模指标不得相互借用、串用**；分类变更由**风控岗发起、财务负责人审批**并留痕（`Q-2`，源自变更 `CH-001`） | **商品类**＝年度保值规模 ≤ 实货经营规模 90%；**贸易类**＝≤ 80%；90/80 两个比例本身**可配置** |
| 额度指标 | 额度指标 | 该品种在指定子账户下允许占用的套保规模上限 | **按品种 + 子账户**分别设定（三层限额之①，主维度）；**不得跨品种挪用**；不得跨子账户挪用（子账户维度为贯穿性要求）；三层限额（子账户 + 品种 / 子账户 + 合约 / 账户 + 品种）须同时校验，任一超限即拒绝（`Q-16`，源自变更 `CH-002`） | — |
| 品种分类管理标记 | 分类管理标记 | 标识该品种是否纳入分类管理（8 号文） | 启用分类管理后，该品种必须归入且仅归入一个分类（默认继承所属子账户分类，可品种级覆盖） | **是**＝该品种受分类管理，额度不得串用；**否**＝暂未分类 |
| 期货合约关联 | 期货合约关联 | 品种与其在交易所挂牌的具体合约（期货/期权）的对应关系 | 一个品种可关联多个合约；合约须属于该品种；期权合约同样受关联管理 | 合约类型：**期货**／**期权**（两者共用同一追溯链） |
| 现货品类映射 | 现货品类映射 | 品种与现货管理中的现货品类的对应关系，用于由实货敞口匹配衍生品 | **17 号文「期现一体」的前置**：无映射则实货敞口无法匹配到品种，计划编制无法开始 | — |
| 计量单位 | 计量单位 | 品种在现货侧使用的计量单位及与期货合约交易单位的换算关系 | 换算关系必须明确；现货数量与期货数量口径不一致时**必须换算后比较**，不得直接相加 | **吨**／**千克**／**手**／**张**（自定义单位含义由录入人标注） |
| 子账户白名单 | 子账户品种白名单 | 指定子账户允许交易的品种集合 | **每个子账户可各自配置**；未列入白名单的品种在该子账户下**不得下单** | — |
| 变更历史 | 品种变更历史 | 品种关键属性的变更留痕（含操作人、时间、变更前后值） | 不得删除、不得覆盖；进入 `AUDIT` 范围 | 变更类型：**新建**／**修改**／**启用**／**停用** |

**填写要求**：

- **业务约束写"业务规则"，不写"技术规则"**：✅"同一品种代码在全系统唯一" / ❌"code 字段加唯一索引"
- **枚举值必须列全**，并说明每个取值的业务含义（不是列值本身）
- **不确定的项**：无（`Q-1` / `Q-2` / `Q-16` 已于 2026-09-20 用户确认，口径见 `INDEX.md` §9.1，
  已回写至本文件 `R-PRODUCT-4`、`FR-PRODUCT-1`、`FR-PRODUCT-11` 等条目，标注 `源自变更 CH-001` / `CH-002`）。

### 2.1 状态机

```
     新建
      │
      ▼
  ┌────────┐   停用   ┌────────┐
  │  启用  │ ───────→ │  停用  │
  │        │ ←─────── │        │
  └────────┘   启用   └────────┘
```

| 状态 | 业务含义 | 可执行操作 | 后续状态 |
|------|---------|-----------|---------|
| **启用** | 该品种在该子账户下可用于新建套保计划与下单，且在事前风控白名单内 | 修改（非编码项）、停用、配置白名单、维护合约关联与现货映射、维护计量单位 | 停用 |
| **停用** | 该品种不可用于新建计划与下单；历史计划、交易、结算数据只读保留 | 启用、查看详情、查看变更历史 | 启用 |

**状态流转规则**：见 §4 `R-PRODUCT-1`、`R-PRODUCT-2`。

## 3. 功能性需求

> **编号规范**：`FR-PRODUCT-<序号>`，序号在**本模块内**从 1 递增，不复用。
>
> **粒度标准**：一条 FR = **一个可独立验收的「操作」或「业务能力」**。

### FR-PRODUCT-1 新增品种

- **描述**：作为财务/风控岗或系统管理员，我希望新增品种并录入其编码、名称、分类与计量单位，以便把企业实际经营涉及的标的纳入套保白名单。
- **输入**：品种编码（全系统唯一，边界值：最大长度与合法字符集按`DATA_MODEL.md`约束，**重复即拒绝**）、品种名称、品种分类（商品类/贸易类）、计量单位与换算关系、是否启用分类管理；子账户标识（归属配置）
- **处理规则**：见 `R-PRODUCT-3`（编码唯一性）、`R-PRODUCT-4`（分类与其红线比例联动）。分类**默认继承所属子账户的分类**（子账户默认商品类 90%），**允许品种级覆盖**（`Q-2`，源自变更 `CH-001`）。分类为商品类时该品种适用 **90%** 红线；贸易类适用 **80%** 红线。新增成功后自动记录品种变更历史（`FR-PRODUCT-14`），**变更类型=新建**
- **输出**：成功 → 品种创建为**启用**状态并可在该子账户下使用；失败 → 明确错误（编码重复 / 分类缺失 / 计量单位换算关系缺失）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 提交一个编码在全系统不存在的品种，创建成功且状态为"启用"，列表可见。
  2. 用已存在的品种编码再次提交，系统拒绝并提示"品种编码已存在"，不产生第二条记录。
  3. 未选择品种分类时提交被拒绝，提示该项必填。
  4. 创建成功后，`FR-PRODUCT-14` 的变更历史中出现一条"新建"记录，含操作人与时间。

### FR-PRODUCT-2 修改品种

- **描述**：作为财务/风控岗或系统管理员，我希望修改品种的非编码属性，以便在业务口径变化时保持品种档案准确。
- **输入**：品种标识、可修改属性（名称、分类、计量单位与换算关系、分类管理标记）；**品种编码不可修改**
- **处理规则**：修改**已启用**的品种时，若涉及**分类变更**（商品类 ⇄ 贸易类），须由**风控岗发起、财务负责人审批**并留痕，且须校验该品种下**是否存在未结束的套保计划或持仓**——存在则**拒绝**（防止红线比例在中途改变造成合规口径漂移）（`Q-2`，源自变更 `CH-001`）；修改后记录变更历史（`FR-PRODUCT-14`），变更类型=修改，且记录前后值
- **输出**：成功 → 属性更新并留痕；失败 → 明确错误（不存在 / 分类变更未审批 / 分类变更被拒 / 必填项缺失）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 修改品种名称后，列表与详情同步更新，变更历史中记录变更前后值。
  2. 尝试修改品种编码时，系统**不提供**该入口或拒绝修改。
  3. 对存在未结束套保计划的品种修改其分类，系统拒绝并说明原因。
  4. 校验必填项：名称置空提交被拒绝。

### FR-PRODUCT-3 停用品种

- **描述**：作为财务/风控岗或系统管理员，我希望停用不再套保的品种，以便阻止其被用于新建计划与下单，同时保留历史数据。
- **输入**：品种标识、停用原因（必填）
- **处理规则**：见 `R-PRODUCT-2`（停用前置校验）。停用后该品种**立即从该子账户的事前风控白名单中移除**，并**下发控制指令到 C++ 组件内存**（`FR-CONFIG-6`）；已有历史计划、交易、结算、凭证数据**只读保留**；停用操作记录变更历史
- **输出**：成功 → 状态变为"停用"，新计划/新下单不可用；失败 → 明确错误（该品种存在未平仓持仓 / 存在未结束计划 / 无权限）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 停用一个无未平仓持仓、无未结束计划的品种，状态变为"停用"。
  2. 停用后尝试用该品种新建套保计划，系统拒绝并提示品种已停用。
  3. 停用后尝试用该品种在下单界面下单，事前风控拒绝（`FR-RISK-1`）。
  4. 停用品种的历史交易记录仍可查询，数据未被删除。

### FR-PRODUCT-4 启用品种

- **描述**：作为财务/风控岗或系统管理员，我希望重新启用已停用的品种，以便恢复其套保能力（**反向操作，不得遗漏**）。
- **输入**：品种标识
- **处理规则**：启用前校验品种的**分类与计量单位换算关系齐备**，否则拒绝；启用后该品种**加入该子账户的事前风控白名单**并下发 C++ 内存；记录变更历史
- **输出**：成功 → 状态变为"启用"；失败 → 明确错误（分类缺失 / 换算关系缺失 / 无权限）
- **优先级**：P1
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 启用一个已停用且分类齐备的品种，状态变为"启用"。
  2. 启用后该品种可被用于新建套保计划与下单。
  3. 对缺少计量单位换算关系的停用品种执行启用，系统拒绝并说明原因。

### FR-PRODUCT-5 查询品种列表（含筛选、排序、分页）

- **描述**：作为财务/风控岗或系统管理员，我希望按条件查询品种列表，以便快速定位管理对象。
- **输入**：筛选条件（品种编码/名称关键字、状态、分类、子账户）、排序字段与方向、分页参数（页码、每页条数）；边界值：空结果、超大页码
- **处理规则**：默认按创建时间倒序；分页默认每页 20 条、可选 10/20/50/100；**仅返回当前用户有权限查看的子账户范围内的品种**（`FR-AUTH-12`、`FR-AUTH-13`）
- **输出**：品种列表（含状态、分类、子账户、最近变更时间）；空结果返回空列表而非报错；页码超范围返回空页
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 按状态筛选"停用"，结果中所有记录状态均为"停用"。
  2. 以子账户 A 用户登录查询，结果中**不出现**子账户 B 的品种白名单配置。
  3. 每页 20 条、共 45 条数据时，第 1 页返回 20 条、第 3 页返回 5 条。
  4. 无匹配条件时返回空列表且界面提示"无数据"，不报错。

### FR-PRODUCT-6 查看品种详情

- **描述**：作为财务/风控岗或系统管理员，我希望查看单个品种的完整档案，以便核对分类、额度指标与关联关系。
- **输入**：品种标识
- **处理规则**：详情含基础属性、额度指标、期货合约关联、现货品类映射、计量单位、所属子账户白名单、最近变更历史摘要；**无权限或不存在时返回统一错误**，不泄露是否存在
- **输出**：品种详情；失败 → 统一错误提示
- **优先级**：P1
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 打开已存在品种详情，页面展示分类、额度指标、合约关联与现货映射。
  2. 查询不存在的品种，返回统一错误提示且不暴露内部信息。
  3. 查询无权限子账户的品种，返回无权限提示。

### FR-PRODUCT-7 导入品种

- **描述**：作为系统管理员，我希望通过 CSV 批量导入品种，以便在初始化阶段快速建立品种档案。
- **输入**：CSV 文件（列：品种编码、品种名称、分类、计量单位、换算关系）；边界值：空文件、缺列、超量行、重复编码
- **处理规则**：导入前**校验表头列完整性**；逐行校验（编码唯一、分类合法、换算关系可解析）；**采用全量预校验后一次性提交**策略——任一行不合法则整体不导入，并返回逐行错误清单（行号 + 原因），**不得部分导入而不告知**；导入成功后为每行记录变更历史（类型=新建）
- **输出**：成功 → 导入条数汇总；失败 → 逐行错误清单，库内数据不变
- **优先级**：P1
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 导入含 10 条合法数据的 CSV，返回"成功导入 10 条"，列表出现这 10 条。
  2. CSV 缺少"品种分类"列时，导入被拒绝并提示缺失列名。
  3. CSV 中第 5 行编码与库内重复时，整体不导入且错误清单定位到第 5 行。
  4. 导入空文件时给出明确提示，不产生错误记录。

### FR-PRODUCT-8 导出品种

- **描述**：作为财务/风控岗或系统管理员，我希望导出品种档案，以便线下核对或作为合规材料附件。
- **输入**：导出口径（当前筛选结果 / 全部有权限品种）
- **处理规则**：导出内容与 `FR-PRODUCT-5` 的当前筛选条件一致；**仅导出当前用户有权限的子账户范围**；导出字段与列表列一致并附导出时间与导出人
- **输出**：CSV 文件；无数据时提示"无可导出数据"
- **优先级**：P2
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 在"状态=启用"筛选下导出，文件仅含启用品种，条数与列表一致。
  2. 导出文件中包含导出时间与导出人列。
  3. 无数据时导出被拦截并提示，不生成空文件。

### FR-PRODUCT-9 维护品种与期货合约的关联

- **描述**：作为财务/风控岗，我希望维护品种与其在交易所挂牌合约的关联，以便下单时只能选择该品种下的合法合约。
- **输入**：品种标识、合约标识、合约类型（期货/期权）、交易所
- **处理规则**：同一品种下可关联多个合约；**合约类型必须显式标注**且期权合约与期货合约**共用同一追溯链与同一套保额度**（`PROJECT.md` §6 期权附加约束）；重复关联同一合约须拒绝；**本次选择范围为境内场内**（`PROJECT.md` §4.2 排除境外/场外）
- **输出**：成功 → 关联建立并在下单合约下拉中可见；失败 → 明确错误（重复关联 / 合约与品种不匹配 / 境外或场外合约被拒）
- **优先级**：P1
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 为某品种关联两个期货合约，下单时该品种下的合约下拉出现这两项。
  2. 重复关联同一合约被拒绝并提示。
  3. 同一合约同时存在于期货与期权列表时，两者均可关联且分别标注类型。
  4. 尝试关联一个标记为境外/场外的合约，系统拒绝。

### FR-PRODUCT-10 维护品种与现货品类的映射

- **描述**：作为财务/风控岗，我希望建立品种与现货品类的对应关系，以便实货敞口能够匹配到可套保的品种（17 号文「期现一体」的前置）。
- **输入**：品种标识、现货品类标识、映射方向（采购侧/销售侧/通用）
- **处理规则**：**映射是实货敞口匹配衍生品的唯一入口**——无映射的现货品类**不得**参与套保计划编制，系统须在计划编制时明确提示缺失映射；一个现货品类可映射到多个品种时须标注**主映射**；映射变更须留痕并**不得影响已成立的套保计划**
- **输出**：成功 → 映射建立；失败 → 明确错误（重复映射 / 现货品类不存在 / 未指定主映射）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 为一个现货品类建立到某品种的映射后，在计划编制界面的"可套保品种"中出现该品种。
  2. 未建立映射的现货品类，其实货敞口在计划编制时被标记为"无可匹配品种"并提示先建立映射。
  3. 一个现货品类映射到两个品种时，系统要求指定主映射。
  4. 删除映射时，系统提示受影响的未结束计划清单。

### FR-PRODUCT-11 配置品种的额度指标与分类管理标记

- **描述**：作为财务/风控岗或系统管理员，我希望为品种（按子账户）配置套保额度指标与分类管理标记，以便事前风控有明确的额度依据。
- **输入**：品种标识、子账户标识、额度指标数值与单位、分类管理标记、有效期
- **处理规则**：额度指标**按品种 + 子账户**分别设定（**三层限额之①主维度**），**严禁跨品种、跨子账户借用或串用**（8 号文红线）；**三层限额须同时校验、任一超限即拒绝**（`Q-16`，源自变更 `CH-002`）；额度指标是 `RISK` 事前风控的输入，变更后须**下发控制指令至 C++ 组件内存**（`FR-CONFIG-6`）；分类管理标记启用时该品种必须且仅归入一个分类（默认继承子账户分类，可品种级覆盖）。**账户级（层③）配置权的授权口径（`CH-012`，澄清性 / L2）**：品种额度分三层（`Q-16`）——层①（子账户＋品种）、层②（子账户＋合约）、**层③（账户＋品种，落库为账户哨兵 `0` 的账户级额度行，影响全体子账户加总口径）**。**权限维度**：层③**不适用**子账户数据权限 / 可见性写面断言（层③目标为哨兵 `0`、**非子账户行级归属**；套用「授权集合须含目标子账户」的写面断言会使 `target=0` **全拒即误拒**），归 `AUTH.md` §2 三类权限之**「功能权限」维度**（`FR-AUTH-12`「数据权限与功能权限独立」）。**可执行主体**＝**财务/风控岗 或 系统管理员**（依本 FR 描述 actor 表述 + 账户级资金额度先例 `FR-FUND-13`「资金岗或系统管理员」；**该主体范围结论已由用户确认（2026-09-21）**）。**与子账户级授权的区别**：层① / 层②为**子账户级配置**，写面强制**子账户限定（`LIMITED`）写授权**（`NFR-SEC-7`、`FR-AUTH-13` 验收 3），**不得**以层③功能权限规则放行层① / 层②；层③为**账户级配置**，按**功能权限**判定。**失败码**：功能权限不足 → `10003`（越权尝试按 `R-AUTH-8` 留痕）。**落地硬前置**：`t_role`/`t_user_role` 的功能权限播种须与实现**同批**（否则全拒＝**误拒**）。**里程碑**：M1＝**角色近似**（财务/风控岗 / 系统管理员）；M2＝收敛为**功能权限编码**（`t_role_permission.perm_code`，`AUTH.md` / `DATA_MODEL TB-AUTH-3`）
- **输出**：成功 → 额度指标生效并下发；失败 → 明确错误（额度非法：负数或超出该子账户总额度 / 分类缺失 / 无权限）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 为子账户 A 的品种配置额度指标后，该额度在事中/事后风控的限额使用情况中可见。
  2. 尝试为品种 A 使用品种 B 的额度下单，事前风控拒绝并提示额度不属于该品种。
  3. 额度指标配置变更后，C++ 组件在收到控制指令后按新额度生效（构造一笔在新额度下应被拒绝的指令验证，对应 `PROJECT.md` §10 成功标准 30）。
  4. 配置负数额度被拒绝并提示。
  5. **（`CH-012` 新增）账户级（层③）配置权**：以**零授权**账号、或**仅持 `CROSS_READONLY` 跨子账户只读**的审计岗账号写**层③**（账户级额度，`sub_account_id=0` 哨兵行）被拒绝并返回 `10003`，且越权尝试按 `R-AUTH-8` 留痕；以**授权主体**（财务/风控岗 或 系统管理员，**已确认 2026-09-21**）账号写同一层③行成功；层① / 层②（子账户级）仍按**子账户限定（`LIMITED`）写授权**判定（`NFR-SEC-7`），**不得**按层③功能权限规则放行。

### FR-PRODUCT-12 按子账户配置品种白名单

- **描述**：作为系统管理员，我希望为每个子账户分别配置允许交易的品种白名单，以便各业务线只能在授权品种内套保。
- **输入**：子账户标识、品种集合（增/减）
- **处理规则**：见 `R-PRODUCT-5`。白名单**按子账户独立生效**；未列入白名单的品种在该子账户下**下单必被事前风控拒绝**；白名单变更须**下发控制指令至 C++ 组件内存**；子账户的删除品种须校验是否存在未平仓持仓或未结束计划
- **输出**：成功 → 白名单更新并下发；失败 → 明确错误（品种停用 / 存在未平仓持仓 / 无权限）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 子账户 A 配置品种 X，子账户 B 未配置品种 X；以 B 下单 X 时事前风控拒绝。
  2. 从子账户白名单移除某品种时，若该子账户存在该品种未平仓持仓，系统拒绝并列出持仓。
  3. 白名单变更后，C++ 组件内存中的白名单同步更新（构造一笔应被拒绝的指令验证）。
  4. 审计可查询到白名单变更的操作人、时间与前后值。

### FR-PRODUCT-13 维护品种的计量单位与换算关系

- **描述**：作为财务/风控岗，我希望维护品种在现货侧与期货侧的计量单位及换算关系，以便敞口数量与期货数量可比。
- **输入**：品种标识、现货计量单位、期货交易单位、换算系数与换算方向
- **处理规则**：见 `R-PRODUCT-6`。**换算关系缺失的品种不得启用**；实货敞口与期货持仓的数量比较**必须换算到同一口径**，不得直接相加；换算关系变更须留痕，且**不影响已发生的历史计算**（历史按当时口径留存）
- **输出**：成功 → 换算关系生效；失败 → 明确错误（系数为 0 或负 / 单位缺失 / 无权限）
- **优先级**：P1
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 配置"1 手 = N 吨"后，实货敞口与期货持仓的数量比较按该系数换算，界面上展示换算后的同口径数量。
  2. 换算系数填写 0 或负数时提交被拒绝。
  3. 未配置换算关系的品种执行启用（`FR-PRODUCT-4`）被拒绝并提示。

### FR-PRODUCT-14 记录品种变更历史

- **描述**：作为审计/合规岗或系统管理员，我希望查看品种档案的全部变更记录，以便在审计时证明品种管理的合规性。
- **输入**：品种标识、时间范围、变更类型筛选（新建/修改/启用/停用）
- **处理规则**：变更历史**只增不改不删**；每条记录含变更类型、变更前后值、操作人、操作时间、子账户；**进入审计范围**（`AUDIT` 只读引用）；变更历史**不随品种删除而消失**（品种不允许物理删除）
- **输出**：变更历史列表（按时间倒序）；无权限时返回统一错误
- **优先级**：P1
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 连续执行"新建 → 修改名称 → 停用"，历史中按时间倒序出现 3 条记录，且修改记录含前后值。
  2. 变更历史记录中每条都有操作人与时间，无一为空。
  3. 系统内不存在删除品种变更历史的入口。
  4. 审计岗可跨子账户查看品种变更历史（`FR-AUTH-13`）。

## 4. 模块内规则

> 跨**多条 FR** 的公共规则写在这里（如状态流转、计算口径、校验总则）。
>
> **为什么需要本节**：FR 拆细之后，公共规则会面临"无处安放"——
> 写进任一条 FR 都会让其它 FR 引用它，形成隐式耦合。
> 放在此处，各 FR 按编号引用即可。

| 规则编号 | 规则内容 | 适用 FR | 说明 |
|---------|---------|---------|------|
| `R-PRODUCT-1` | **品种状态流转**：仅允许 `启用 → 停用` 与 `停用 → 启用` 两条边；不存在"删除"状态；品种**不得物理删除**（历史数据依赖其存在） | `FR-PRODUCT-1`、`FR-PRODUCT-3`、`FR-PRODUCT-4` | 状态机见 §2.1；删除会造成追溯链断裂 |
| `R-PRODUCT-2` | **停用前置校验**：品种存在**未平仓持仓**或**未结束的套保计划/交易计划**时**不得停用**；已成立的历史计划允许在其生命周期内自然结束 | `FR-PRODUCT-3` | 防止停用导致在途交易失去品种依据 |
| `R-PRODUCT-3` | **品种编码唯一性**：品种编码在全系统唯一，且**一经使用不得修改**；重复提交一律拒绝 | `FR-PRODUCT-1`、`FR-PRODUCT-2`、`FR-PRODUCT-7` | 编码是下游全部关联的锚点，改名等于断链 |
| `R-PRODUCT-4` | **分类与红线联动**（源自变更 `CH-001`，`Q-2`）：规模红线比例**默认由子账户分类决定**——**商品类 = 90%**、**贸易类 = 80%**（比例本身可配置，配置键 `sub_account.category`），**允许品种级覆盖**；分类变更由**风控岗发起、财务负责人审批**并留痕；分类一经用于未结束计划**不得变更**；**不同分类/不同品种的额度指标不得相互借用、串用** | `FR-PRODUCT-1`、`FR-PRODUCT-2`、`FR-PRODUCT-11` | 直接对应 8 号文红线；`Q-2` 已确认 |
| `R-PRODUCT-5` | **子账户白名单生效规则**：白名单**按子账户独立生效**；未列入者在下单时被事前风控（C++ 内存）拒绝；变更须经控制指令下发，**不得依赖定时轮询** | `FR-PRODUCT-12`、`FR-PRODUCT-3`、`FR-PRODUCT-4` | `PROJECT.md` §6「风控架构（硬约束）」 |
| `R-PRODUCT-6` | **计量单位换算总则**：现货数量与期货数量比较前**必须换算至同一口径**；换算关系缺失的品种**不得启用**；换算关系变更**不追溯重算历史** | `FR-PRODUCT-13`、`FR-PRODUCT-11` | 时点净持仓校验（`FR-RISK-5`）依赖同口径 |
| `R-PRODUCT-7` | **品种与子账户的归属**：品种档案为**全局共享**（编码全系统唯一），但**白名单与额度指标**为**子账户级配置**——即"品种一份，白名单与额度多份" | `FR-PRODUCT-5`、`FR-PRODUCT-11`、`FR-PRODUCT-12` | 对应 `PROJECT.md` §4.1.C「① 品种管理：子账户可各自配置品种白名单」 |
| `R-PRODUCT-8` | **下游引用保护**：任何被 `SPOT`/`PLAN`/`TRADE`/`SETTLE`/`ACCT`/`AUDIT` 引用的品种属性（编码、分类、计量单位换算关系）**不得静默变更**——变更须留痕并在追溯链中可识别变更时点 | `FR-PRODUCT-2`、`FR-PRODUCT-14`、`FR-PRODUCT-10` | 追溯链完整性（`PROJECT.md` §10 成功标准 16、29） |
| `R-PRODUCT-9` | **变更下发纪律**：凡影响事前风控判断的品种配置（白名单、额度指标、启用状态）变更，**必须**生成控制指令下发 C++ 组件内存；下发失败须告警且**该变更不得视为已生效** | `FR-PRODUCT-3`、`FR-PRODUCT-4`、`FR-PRODUCT-11`、`FR-PRODUCT-12` | 内存与数据库一致性（`PROJECT.md` §4.1 ⑥-d） |
