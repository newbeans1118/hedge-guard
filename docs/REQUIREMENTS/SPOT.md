## 1. 模块概述

- **职责**：管理企业现货侧的**采购、销售、生产、库存与现货价格**数据，并据此计算**实货敞口**——这是 17 号文「期现一体」的起点与全系统的数据源头。
- **解决的业务问题**：不解决则衍生品**无根可依**——套保计划失去匹配对象，只能退化成"先有期货成交、再反找现货"的投机式结构，正是 17 号文点名要防的行为；同时规模红线（90%/80%）与"时点净持仓 ≤ 实货风险敞口"因缺少实货口径而**无法校验**。
- **上游模块**：`PRODUCT`（品种、现货品类映射、计量单位换算关系）、`CONFIG`（子账户定义）、`AUTH`（操作人与子账户数据权限）
- **下游模块**：`PLAN`（实货敞口是计划编制与套保比率计算的输入）、`RISK`（规模红线与时点净持仓校验的实货口径）、`ACCT`（实货盈亏）、`AUDIT`（追溯链起点）、`SETTLE`

> ⚠️ **定位边界**（`PROJECT.md` §4.2）：本模块是**「为套保服务的现货视图」**，
> **不是完整 ERP**。做敞口相关字段与现货价格记录；**不做**完整采购流程审批、供应商管理、
> 仓库出入库作业、财务应收应付、生产排程。

## 2. 数据字典

> ⚠️ **边界红线**：本节只写**业务概念**——业务名称、业务语义、业务约束、
> 枚举值的**业务含义**。**不写**列名、数据类型、长度、索引、存储格式。

| 数据项 | 业务名称 | 业务语义 | 业务约束 | 枚举值业务含义 |
|--------|---------|---------|---------|--------------|
| 采购合同 | 采购合同 | 企业向上游采购原材料的合同，是**买入方向**实货敞口的主要来源 | 合同编号在系统内唯一；须归属**一个子账户**（贯穿性要求）；一经产生敞口不得删除，只能作废 | 状态见 §2.1 |
| 销售合同 | 销售合同 | 企业向下游销售产成品的合同，是**卖出方向**实货敞口的主要来源 | 合同编号在系统内唯一；须归属**一个子账户**；同上不得删除 | 状态见 §2.1 |
| 生产计划 | 生产计划 | 计划期内拟生产的产成品数量与所需原料，用于推导未来原料采购与产成品销售双向敞口 | 须归属一个子账户；计划期不得为空 | **已排产**／**调整中**／**已关闭** |
| 在制品 | 在制品 | 处于生产过程中、尚未完工的存货，其价格风险敞口介于原料与产成品之间 | 须归属一个子账户与一个品种 | — |
| 库存台账 | 库存台账 | 企业现货库存的数量与位置记录，用于识别**已持有存货**的价格风险敞口 | 须归属一个子账户；库存数量不得为负（若为负须告警） | **原材料**／**产成品**／**在制品** |
| 现货价格 | 现货价格 | 指定品种在指定日期的现货成交/报价水平。**由外部输入**（手工录入 / CSV 导入）。属**全账户共享的市场数据（单价）**，不是子账户业务归属维度 | **唯一口径**：`品种 + 日期 + 现货价 + 来源标注`，**不含子账户维度**；行内子账户标识语义为**录入归属**（记录由谁录入），**不参与业务归属判定与加总**（`CH-003`）；同一 `品种 + 日期` 只有一条共享价，多来源并存按 `R-SPOT-3` 留痕；**不得**由系统抓取或订阅（`PROJECT.md` §4.2）；同一品种同一日期重复录入须按 `R-SPOT-3` 处理 | 来源标注：**手工录入**／**CSV 导入**／**批量粘贴**（来源影响审计可信度评估） |
| 来源标注 | 来源标注 | 标识该条现货价的录入方式与提供者，用于审计时评估数据可信度 | 不得为空；CSV 导入须记录导入文件名与操作人 | 见上 |
| 实货敞口 | 实货敞口 | 企业因现货经营而暴露于价格波动风险的**数量与方向**（买入/卖出）。**17 号文「期现一体」的起点** | 须归属**一个子账户**（贯穿性要求）；须能映射到**一个品种**（无映射则不可参与套保）；方向与数量一经用于计划不得静默变更 | 方向：**买入敞口**＝未来需买入，担心价格上涨；**卖出敞口**＝未来需卖出，担心价格下跌 |
| 敞口方向 | 敞口方向 | 价格风险的方向 | — | **买入**／**卖出** |
| 敞口状态 | 敞口状态 | 敞口是否已被套保覆盖、是否仍有效 | 见 §2.1 | **待套保**／**部分覆盖**／**已覆盖**／**已关闭** |
| 敞口归属子账户 | 敞口归属子账户 | 实货敞口所属的逻辑子账户 | **必填**；是子账户贯穿字段规范中"敞口类"的必带标识（`INDEX.md` §2.1） | — |
| 敞口计算口径 | 敞口计算口径 | 由现货数据的哪一部分推导敞口 | **默认 = 组合口径（含生产计划）**：已签合同未执行量 + 库存持有量 + 生产计划需求量；**三类分量须分别记录与展示，不得只存合计**；三类分量**可分别开关、可按子账户/品种覆盖**（配置 `exposure.components=CONTRACT_UNEXECUTED,INVENTORY,PRODUCTION_PLAN`，默认全开；权重可配）（`Q-17`，源自变更 `CH-002`）；口径须在系统内**唯一且明示** | **已签合同未执行量**／**库存持有量**／**生产计划需求量**／**组合口径**（组合口径须在计划中标注构成与各分量权重） |
| 敞口快照 | 敞口快照 | 某一时点实货敞口的持久化记录，供事前/事中风控与事后复核取用 | **必须存三类分量（合同未执行量 / 库存 / 生产计划），不得只存合计**（否则审计无法自证，且 `Q-8`「敞口变动 > 20%」无法计算）；三分量与合计**须在同一事务内计算**，不一致即拒绝写入；**确需修正落库值时须重算生成新快照、旧快照保留，禁止静默覆盖**（`Q-17`，源自变更 `CH-002`/`CH-004`）；快照须带**时点标识**（`snapshot_as_of`） | — |

### 2.1 状态机

**合同（采购/销售）**：

```
  草稿 ──提交──→ 有效 ──执行完毕──→ 已关闭
                   │
                   └──作废──→ 已作废
```

| 状态 | 业务含义 | 可执行操作 | 后续状态 |
|------|---------|-----------|---------|
| **草稿** | 合同已录入但未生效，**不计入实货敞口** | 修改、删除、提交 | 有效 |
| **有效** | 合同已生效，**其未执行量计入实货敞口** | 查看、执行完毕、作废（须校验是否已被计划引用） | 已关闭 / 已作废 |
| **已关闭** | 合同执行完毕，**敞口归零** | 查看 | 终态 |
| **已作废** | 合同不再执行，**不计入敞口**；已引用它的计划须另行处理 | 查看 | 终态 |

**实货敞口**：

```
  待套保 ──被计划部分引用──→ 部分覆盖 ──全部引用且计划生效──→ 已覆盖
     ↑                              │
     └──────── 计划终止/驳回 ◄───────┘
                                    │
                              敞口归零 → 已关闭
```

| 状态 | 业务含义 | 可执行操作 | 后续状态 |
|------|---------|-----------|---------|
| **待套保** | 敞口已识别，尚无任何已批准计划引用 | 被计划引用、修改（未被引用时）、关闭 | 部分覆盖 / 已关闭 |
| **部分覆盖** | 部分数量已被已批准计划引用 | 被更多计划引用、关闭 | 已覆盖 / 待套保（计划终止时回退）/ 已关闭 |
| **已覆盖** | 全部数量均已被已批准计划引用 | 关闭 | 已关闭 |
| **已关闭** | 敞口已归零（合同执行完毕或库存处置） | 查看 | 终态 |

**状态流转规则**：见 §4 `R-SPOT-1`、`R-SPOT-5`。

## 3. 功能性需求

> **编号规范**：`FR-SPOT-<序号>`，序号在**本模块内**从 1 递增，不复用。

### FR-SPOT-1 新增采购合同

- **描述**：作为财务/风控岗，我希望录入采购合同及其数量、价格与执行计划，以便识别买入方向的实货敞口。
- **输入**：合同编号（该子账户内唯一）、子账户标识（必填）、品种或现货品类、供应商名称（仅作为文本说明，**不做供应商管理**）、合同总量、已执行量（初始通常为 0）、计价方式、合同起止日期、敞口方向（默认买入）
- **处理规则**：见 `R-SPOT-1`、`R-SPOT-2`。合同**必须归属一个子账户**且**必须能映射到品种**（通过 `FR-PRODUCT-10` 的映射），映射缺失时**允许保存草稿但不得提交为有效**，并明确提示先建立映射；初始状态为**草稿**，不计入实货敞口
- **输出**：成功 → 采购合同以草稿状态创建；失败 → 明确错误（子账户缺失 / 合同编号重复 / 总量非法 / 无映射导致不可提交）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 录入一份子账户 A 的采购合同，保存后状态为"草稿"，实货敞口列表**不出现**该合同贡献的敞口。
  2. 未选择子账户即提交被拒绝，提示"子账户必填"。
  3. 未建立品种映射的现货品类，草稿可保存但"提交为有效"被拒绝并提示缺失映射。
  4. 同一子账户内使用重复合同编号提交被拒绝。

### FR-SPOT-2 修改采购合同

- **描述**：作为财务/风控岗，我希望在合同变更时修改采购合同内容，以便敞口数据与实际一致。
- **输入**：合同标识、可修改字段（总量、已执行量、日期、计价方式、品类）
- **处理规则**：**草稿**状态可自由修改；**有效**状态修改须校验——**减少合同总量至低于已被计划引用数量**时**拒绝**（见 `R-SPOT-2`）；修改后须留痕并在追溯链可识别变更时点；**不得修改子账户**（子账户是贯穿性维度，改子账户等于换业务线）
- **输出**：成功 → 合同更新并留痕；失败 → 明确错误（不存在 / 总量低于已引用量 / 无权限 / 尝试修改子账户）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 修改草稿合同的总量后成功保存，内容更新。
  2. 某合同的未执行量被计划引用了 100 吨，尝试将合同总量减少到使未执行量低于 100 吨时，系统拒绝并列出引用的计划。
  3. 尝试修改已有效合同的子账户归属被拒绝。
  4. 修改操作在合同变更记录中留痕，含操作人与前后值。

### FR-SPOT-3 作废采购合同

- **描述**：作为财务/风控岗，我希望作废不再执行的采购合同，以便其不再计入实货敞口（**反向操作，不得遗漏**）。
- **输入**：合同标识、作废原因（必填）
- **处理规则**：草稿合同可**删除**；有效合同只能**作废**（不得删除，保留追溯链）；作废前校验**是否已被生效的套保计划引用**——被引用时**拒绝作废**，提示先终止相关计划（`FR-PLAN-17`）；作废后敞口归零并更新敞口状态
- **输出**：成功 → 状态"已作废"，敞口归零；失败 → 明确错误（已被计划引用 / 原因缺失 / 无权限）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 作废一份未被任何计划引用的有效合同，状态变为"已作废"，该合同贡献的实货敞口归零。
  2. 作废一份已被生效计划引用的合同被拒绝，提示先终止相关计划。
  3. 未填写作废原因时提交被拒绝。
  4. 作废后的合同仍可在列表中查询到（未被物理删除）。

### FR-SPOT-4 查询采购合同列表

- **描述**：作为财务/风控岗，我希望按条件查询采购合同，以便掌握买入侧敞口来源。
- **输入**：筛选条件（子账户、品种/品类、合同编号关键字、状态、合同起止日期范围、敞口方向）、排序、分页；边界值：空结果、超范围日期
- **处理规则**：默认按合同创建时间倒序；分页默认每页 20 条；**仅返回当前用户有权限的子账户范围**（`FR-AUTH-12`、`FR-AUTH-13`）；列表须展示每份合同**当前未执行量**与**已被计划引用量**
- **输出**：合同列表；空结果返回空列表
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 按"子账户=A、状态=有效"筛选，结果全部满足条件。
  2. 列表中每行显示未执行量与已被计划引用量，两值与详情页一致。
  3. 子账户 A 用户查询时看不到子账户 B 的合同。
  4. 日期范围反填（起 > 止）时给出明确提示。

### FR-SPOT-5 新增销售合同/订单

- **描述**：作为财务/风控岗，我希望录入销售合同或订单，以便识别卖出方向的实货敞口。
- **输入**：合同编号（该子账户内唯一）、子账户标识（必填）、品种或现货品类、客户名称（文本说明，**不做客户管理**）、合同总量、已发货量、计价方式、合同起止日期、敞口方向（默认卖出）
- **处理规则**：同 `FR-SPOT-1`（子账户必填、品种映射校验、初始草稿、不计入敞口）；**销售侧敞口方向为卖出**——担心价格下跌；允许同一合同存在**双向敞口**（如同时存在定价未定部分），此时须显式标注方向拆分
- **输出**：成功 → 销售合同以草稿状态创建；失败 → 明确错误（同 `FR-SPOT-1`）
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 录入一份销售合同并提交为有效后，实货敞口列表出现一条方向为"卖出"的敞口。
  2. 未选子账户时提交被拒绝。
  3. 一份合同被标注为双向敞口（如买入 60 吨 / 卖出 40 吨）时，敞口列表分别出现两条方向不同的敞口。
  4. 合同编号在同一子账户内重复时被拒绝。

### FR-SPOT-6 修改销售合同

- **描述**：作为财务/风控岗，我希望修改销售合同，以便敞口数据与实际一致。
- **输入**：合同标识、可修改字段（总量、已发货量、日期、计价方式、品类）
- **处理规则**：与 `FR-SPOT-2` 同口径——草稿可改，有效状态减少总量至低于已引用量时拒绝，不得修改子账户，变更留痕
- **输出**：成功 → 更新并留痕；失败 → 明确错误
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 修改有效销售合同的已发货量后，实货敞口数量同步更新。
  2. 减少总量至低于已被计划引用量时被拒绝并列出计划。
  3. 变更留痕含操作人与前后值。

### FR-SPOT-7 查询销售合同列表

- **描述**：作为财务/风控岗，我希望按条件查询销售合同，以便掌握卖出侧敞口来源。
- **输入**：筛选条件（子账户、品种/品类、合同编号关键字、状态、日期范围）、排序、分页
- **处理规则**：与 `FR-SPOT-4` 同口径（默认倒序、分页、子账户权限过滤、展示未执行量与已引用量）
- **输出**：销售合同列表；空结果返回空列表
- **优先级**：P0
- **来源**：初版
- **状态**：有效
- **验收标准**：
  1. 按子账户与状态筛选结果正确。
  2. 列表中每行展示未执行量与已引用量。

### FR-SPOT-14 计算实货敞口

- **描述**：作为财务/风控岗，我希望系统根据已录入的现货数据自动计算各子账户、各品种的实货敞口，以便作为套保计划的起点。

- **处理规则**：见 `R-SPOT-4`。**默认口径 = 组合口径（含生产计划）**：已签合同未执行量 + 库存持有量 + 生产计划需求量，按方向与品种汇总；**三类分量须分别记录与展示、可分别开关、可按子账户/品种覆盖**，敞口快照**必须存三类分量而非只存合计**（`Q-17`，源自变更 `CH-002`）。**敞口必须能按子账户分别计算**（贯穿性要求）；必须先完成**品种映射**才能计算（无映射时该部分数据**不参与**计算并列出未映射清单；**未映射清单按现货品类分别留行**——同一子账户内各未映射的现货品类**各占一行**，**不得**汇总为一行，也不得以净额合并同一品类的买卖方向；**品类维度仅在未映射行起区分作用**：**已映射**行的敞口仍按「子账户 × 品种 × 方向 × 口径 × 基准日」归并，同一品种下来自不同现货品类的现货数据**须合并为一条**，不得按品类拆行）；按方向（买入/卖出）分别汇总，**不得**用买卖相抵的净额替代双向敞口（净额可用于时点净持仓校验，但**敞口明细须保留方向**）；计算结果**须留存计算时点与口径**，供审计复现
- **输出**：成功 → 按子账户 × 品种 × 方向的敞口明细、**三类分量明细**与汇总；失败/部分成功 → 明确列出未映射或数据不完整的数据源

- **来源**：初版
- **状态**：有效
- **验收标准**：

  2. 某现货品类未建立品种映射时，计算结果中该部分被列入"未映射清单"而非静默丢弃；**清单按现货品类分别留行**——同一子账户下存在两个未映射的现货品类时，清单须出现**两行**（各可定位到该品类下的原始单据），**不得**合并为一行；反之，**已映射**部分的敞口**不得**因现货品类不同而拆成多条（仍按品种归并）。
  3. 同一品种同时存在买入 100 吨与卖出 40 吨时，明细保留两条方向数据（净额 60 吨可另行展示但**不替代**明细）。
  4. 重复执行计算，结果一致；计算结果中记录了计算时点与所用口径。
  5. 敞口记录**显式携带子账户标识**（`INDEX.md` §2.1 敞口类红线）。
  6. 默认组合口径下，结果分别列出**合同未执行量 / 库存持有量 / 生产计划需求量**三类分量；关闭某一分量后该分量不再计入且合计相应变化（源自变更 `CH-002`，`Q-17`）。
  7. 敞口快照中可查询到三类分量，而非仅有合计（支撑 `Q-8`「敞口变动 > 20%」判定）。

  1. 指定 `productId`、`from`、`to` 导出，文件行数 = 「表头 1 行 + 匹配数据行」，数据按 `price_date` **升序**，条数与同条件查询（`FR-SPOT-13`）一致。
  2. 首行表头逐字为 `product_id,price_date,spot_price,source_type,source_desc,import_file_name,price_unit,operator_id,entry_time`。
  3. 导出行的来源标注（`source_type`/`source_desc`）与录入人 / 录入时间与库内记录一致。
  4. 无匹配数据时返回 HTTP 200，文件**仅含表头行**（本口径逐字判定；与 `FR-PRODUCT-8`/`FR-SPOT-18` 的「不生成空文件」惯例不同——**该差异已裁定保留现状**，依据见处理规则）。
  5. `productId` 传非整数、`from`/`to` 传非 `yyyy-MM-dd` 时返回参数错误 `10001`。
  6. 单元格内容含逗号 / 引号 / 换行时按 CSV 规范转义，解析后各行**列数不串位**。
  7. `from > to`（反填）时**不报错**，返回 HTTP 200 且文件仅含表头行（实现未做反填校验）。

## 4. 模块内规则

| 规则编号 | 规则内容 | 适用 FR | 说明 |
|---------|---------|---------|------|
| `R-SPOT-1` | **实货敞口是系统的根，数据流单向**：敞口**只能**由现货数据（合同/生产/库存）推导；**严禁**由期货成交记录反向创建或修改敞口（17 号文「期现一体」硬要求） | `FR-SPOT-1`、`FR-SPOT-5`、`FR-SPOT-8`、`FR-SPOT-9`、`FR-SPOT-14` | `PROJECT.md` §6「17 号文期现一体」约束行 |
| `R-SPOT-2` | **子账户归属必填且不可静默变更**：所有现货单据与实货敞口**创建时必须携带子账户标识**；变更仅允许在未被生效计划引用时进行，且须留痕。**不得**通过"计划所属子账户"等关联关系间接推导单据的子账户。**注**：**现货价记录不属本规则所称"现货单据"**——现货价是全账户共享的市场数据，其子账户标识仅为**录入归属**，不作为业务归属维度，也不参与加总（`CH-003`，见 §2「现货价格」） | `FR-SPOT-1`、`FR-SPOT-2`、`FR-SPOT-5`、`FR-SPOT-6`、`FR-SPOT-16` | `INDEX.md` §2.1「敞口类」红线（**不含现货价**）；`PROJECT.md` §4.1.E（三）编码约定 |
| `R-SPOT-3` | **现货价重复录入处理**：同一 `品种 + 日期` 已存在价格时——**同日同期重复录入由同一来源**时提示"已存在"并要求确认覆盖；**覆盖须留痕**（记录被覆盖值、操作人、时间）；**不得静默覆盖**。多来源并存时以**最后确认的值为准**，历史值保留在变更留痕中 | `FR-SPOT-10`、`FR-SPOT-11`、`FR-SPOT-12` | 现货价是套保比率与实货盈亏的计算基础，静默覆盖会使历史计算不可复现 |
| `R-SPOT-4` | **敞口计算口径总则**（源自变更 `CH-002`，`Q-17`/`Q-12`；三分量处置见 `CH-004`）：敞口 = 按口径选取的现货数据 × 方向符号。**默认口径 = 组合口径（含生产计划）**：已签合同未执行量 + 库存持有量 + 生产计划需求量（配置 `exposure.components=CONTRACT_UNEXECUTED,INVENTORY,PRODUCTION_PLAN`，默认全开，权重可配）；**三类分量须分别记录、分别展示、可分别开关、可按子账户/品种覆盖**；**敞口快照必须存三类分量，不得只存合计**。**在制品按完工比例折算**。**三分量与合计的互校与处置（`CH-004`）**：三分量与合计**须在同一事务内计算**——**写入侧**：若 `Σ 分量（按方向符号）≠ 敞口合计`，**拒绝本次写入并明确报错**，不得入库半正确快照；**展示侧**：查询时若发现分量分组之和与合计不符，**以分量重算展示值 + 告警 + 写入现货（敞口）变动留痕**（留痕类型新增「**分量重算**」`COMPONENT_RECALC`）；**确需修正落库值时，须重算生成新快照（新快照标识）、旧快照保留**，**禁止静默覆盖**（否则历史快照不可复现，与 `Q-8`「敞口变动 > 20%」判定依据冲突）。计算须记录**口径 + 基准日期 + 计算时点**。**不得**以未来价格或系统推算价格参与敞口金额计算——金额计算所用现货价**只能来自已录入记录**；缺价时**按用途分两种**：① **套保比率计算（最小方差法）用途 → 拒绝计算并明确报错**（配置 `spot.price.gap_calc=REJECT`，可选"缺口 ≤ 3 个交易日线性插值" `INTERPOLATE_MAX_3D`，**默认关闭**）② **实货盈亏/敞口估值用途 → 沿用最近一期并必须标注价格时点与快照时点**（配置 `gap_valuation=CARRY_FORWARD_LABELED`，结果标记"非当日价"、必带 `price_as_of` 与 `snapshot_as_of`） | `FR-SPOT-8`、`FR-SPOT-9`、`FR-SPOT-14`、`FR-SPOT-15`、`FR-SPOT-18` | `Q-17`/`Q-12` 已确认口径；`CH-004` 三分量处置 |
| `R-SPOT-5` | **敞口状态流转规则**：`待套保 → 部分覆盖 → 已覆盖`，由**已批准计划**引用触发；计划被**驳回/撤销/终止**时对应覆盖量**立即回退**（`已覆盖/部分覆盖 → 部分覆盖/待套保`）；敞口数量归零时进入 `已关闭`（终态）。**状态只能由系统按引用关系计算，不得手工修改** | `FR-SPOT-14`、`FR-SPOT-15`、`FR-SPOT-3`、`FR-SPOT-16` | 状态机见 §2.1；手工改状态会使敞口与计划的引用关系失真 |
| `R-SPOT-6` | **现货价零外部依赖**：系统**不抓取、不订阅、不代理**任何第三方现货资讯源；现货价进入系统的**唯一途径**为手工录入、批量粘贴、CSV 导入。**不得**在代码或配置中内置任何资讯源 URL | `FR-SPOT-10`、`FR-SPOT-11`、`FR-SPOT-12`、`FR-SPOT-13` | `PROJECT.md` §4.2 排除项 + §6「数据来源」约束行 |
| `R-SPOT-7` | **ERP 边界**：本模块**只维护敞口相关字段与现货价**；**不提供**采购/销售审批流、供应商/客户管理、仓库出入库作业、应收应付、生产排程 | 本模块全部 FR | `PROJECT.md` §4.2「不做完整 ERP」；现货数据可录入也可从 ERP 导入（导入适配器不在本期） |
| `R-SPOT-8` | **样本不足不静默降级**：用于最小方差法的现货价序列 **< 30 个交易日**时，须**明确提示样本不足**，**不得**静默改用简单比率法或其它兜底算法 | `FR-SPOT-13`、`FR-SPOT-12`（供 `FR-PLAN-7` 使用） | `PROJECT.md` §4.1.E（一）+ §10 成功标准 9 |
| `R-SPOT-9` | **单据不可物理删除**：有效单据只能**作废**，草稿单据可删除；**已产生过敞口或被任何计划引用过的单据一律不得物理删除** | `FR-SPOT-3`、`FR-SPOT-1`、`FR-SPOT-5` | 追溯链完整性（`PROJECT.md` §10 成功标准 2、16） |
| `R-SPOT-10` | **数量口径统一**：比较现货数量与期货数量前，须按 `FR-PRODUCT-13` 的换算关系折算到同一口径 | `FR-SPOT-14`、`FR-SPOT-15` | 支撑 `FR-RISK-5` 时点净持仓校验 |
