### 2.3 独立取证（命令 + 输出）

**（a）`term_end_date` 备注实读**（`:1668`，取样 2026-09-21 10:46；以实时为准）：

**确认：现表述为 `min` 口径，且原 `OR` 表述作为勘误留痕保留**（实读成立）。

**（b）与本席原验收设计的取数口径一致性 —— 回到用例设计本身**（不只比对文档）

本席原测试设计中，期限红线用例**早已按 `min`（较早者）口径设计**，实读如下：

- `docs/TEST_PLAN/RISK.md` `TC-RISK-14`「期限红线取「建仓日+12 月」与「合同到期+30 天」较早者」（P0，`FR-RISK-6`）：
  前置「建仓日 2026-01-01，合同到期 2026-11-01（+30 天 = 2026-12-01 < 2027-01-01）」，预期「生效上限 = 合同到期 + 30 天 = 2026-12-01」。
- `docs/TEST_PLAN/PLAN.md` `TC-PLAN-10`（P0，`FR-PLAN-10`）步骤 2 预期：「提示生效上限取自「建仓日+12 个月」与「合同到期+30 天」**较早者**」。
- `docs/TEST_PLAN/BOUNDARY.md` `TC-BOUND-4`「期限临界」边界依据：「上限取**较早者**」。
- `docs/TEST_PLAN/INDEX.md` §追溯「期限红线（`Q-4`）｜取「建仓日+12 个月」与「合同到期+30 天」**较早者**」。

**判定**：本席原设计**一贯采用 `min`**。因此 `v1.3.4` 的勘误**不是**"改变了取数口径以致用例失效"，
