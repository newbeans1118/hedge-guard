（等价最小复现：`java/src/test/java/com/hedgeguard/service/SpotT133GuardBearingTest.java` 首版「确认覆盖」用例外挂了第二行新日期数据时，同一路径即抛本异常——证据见下。）

## 期望结果

依据：① `FR-SPOT-11` 验收 1 / `FR-SPOT-12` 验收 1 要求导入**成功并返回条数**；② 手工录入同域方法 `SpotService.putSpotPrice` 已强制 `requireText(price.priceUnit, "price_unit")`（`SpotService.java:565`），说明 `price_unit` 是**必填业务语义**；③ DDL `t_spot_price.price_unit` 为 `NOT NULL` 且无默认值。

⇒ 导入路径必须在落库前给出 `price_unit`（要么按 `FR-SPOT-11/12` 输入契约补默认单位并说明取值依据，要么在预校验阶段以 `10001` 明确拒绝并给出「缺单位」拒因——**不得**把它留给 DB 约束变成 500）。当前实现二者皆无：`importSpotPrices` 解析行只赋 `subAccountId/productId/priceDate/spotPrice`（`SpotService.java:1056-1076`），写入前只补 `sourceType/importFileName/isShared/operatorId/entryTime/overwriteConfirmed`（`:1118-1121`），**从未赋 `priceUnit`**。

## 实际结果

新增行支路每次落库即被 DB 拒绝：`违反 NOT NULL 约束：t_spot_price.price_unit`，异常经 `TxTemplate` 包装为 `IllegalStateException`（**HTTP 层将映射为 500，而非可判定的 10001/10019**）。⇒ 任意「新日期」行的批量粘贴/CSV 导入**全部失败**，导入功能整体不可用；仅「同日已存在」的覆盖行（update 支路）能工作。

## 复现率

必现（100%，与数据内容无关：只要落到 insert 支路即触发）

## 影响面

- **功能**：`FR-SPOT-11`（批量粘贴）/ `FR-SPOT-12`（CSV 导入）**完全不可用**；现货价只能逐条手工录入（`putSpotPrice` 路径正常）。
- **连锁**：`FR-SPOT-13` / `R-SPOT-8`（最小方差法需 ≥30 交易日序列）无法通过导入方式建立价格序列。
- **为何此前全绿**：现存导入用例（`SpotT109FixTest:115/180/264`、`SpotT110VisibilityTest:315`）**全部驱动内存假 DAO**（该类自述「完全离线：内存假 DAO 驱动」），假 `FakeSpotPriceDao.insert` 不执行任何列约束 ⇒ **假 DAO 掩盖真实 DDL 约束**（与 `T-052`/`TE-T023b` 同族：桩比真实现宽松导致假绿）。**本缺陷由「真实引擎 + 真实 DAO」形态首次暴露**。
- **规避方案**：无（业务侧只能改用手工录入）。
