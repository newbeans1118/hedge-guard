- **对应用例**：`PlanListDefaultSortTest.defaultSortIsCreatedTimeDesc @ web/handler/plan/PlanListDefaultSortTest.java`（另：`explicitSortIsRespected` 防守显式 `sort` 不被覆盖）

## 复现步骤

1. 在共享树执行 `mvn -B -o test -Dtest=PlanListDefaultSortTest`（或任一驱动 `PlanHandler` 列表分支的用例）。
2. 关注 `GET /api/v1/plan` **不传 `?sort=`** 时，`PlanHandler` 交给 `HedgePlanDao.findPage(...)` 的 `PageQuery` 的**方向**。
3. 观察其 `sortField()` / `direction()` / `ascending()`。

## 期望结果

`sortField = "created_time"`、`direction = "DESC"`、`ascending = false`（倒序）。
**依据**：`docs/REQUIREMENTS/PLAN.md:155`「处理规则：**默认按创建时间倒序**」；`ARCHITECTURE.md` §4.1.1 分页/排序口径；`PlanService.java:95` 自身 javadoc 亦写「列表默认排序字段（`FR-PLAN-4`：**默认按创建时间倒序**）」。

## 实际结果

`sortField = "created_time"`、**`direction = "ASC"`、`ascending = true`（升序）** —— 与需求**相反**。

## 复现率

**必现**（缺省参数路径，无随机因素）。

## 证据

修复前（缺陷态）实测输出：
```
[ERROR] com.hedgeguard.web.handler.plan.PlanListDefaultSortTest.defaultSortIsCreatedTimeDesc <<< FAILURE!
org.opentest4j.AssertionFailedError: FR-PLAN-4 要求默认倒序（BUG-001） ==> expected: <DESC> but was: <ASC>
[ERROR] Tests run: 2, Failures: 1, Errors: 0, Skipped: 0
```
根因链（**三层叠加**，逐层可查）：
| 层 | 位置 | 事实 |
|---|---|---|
| ① handler | `PlanHandler.list()`（原 `:119–120`） | `?sort=` 缺省时只传**裸字段名** `PlanService.DEFAULT_SORT_FIELD` |
| ② 公共件 | `PageQuery.of(..., defaultSortField)`（`PageQuery.java:62`） | `boolean asc = true;` —— **`sort` 缺省时方向恒为 ASC** |
| ③ DAO | `AbstractDmDao.findPage`（`:161`） | `ORDER BY <sortField> <query.direction()>` ⇒ 落为 `created_time ASC` |

> **绿测为何没挡住**：缺陷只在「**缺省参数**」下出现，而既有用例均以**显式**输入驱动（且新增的 `PlanListQueryTest` 未断言**方向**）⇒「实现与需求相反」被全绿掩盖。

## 影响面

- **功能**：`FR-PLAN-4`「查询套保计划列表」（P0）首屏顺序错误 —— 财务/风控岗与审批人「掌握计划全景与待办」时**最先看到的不是最新计划**；分页下每页边界随之错位。
- **规避**：前端可在请求中显式带 `?sort=created_time,desc` 规避；但**缺省即错**属契约不符，不能以"调用方记得带参数"为交付前提。
- **范围**：仅 `GET /api/v1/plan` 缺省排序；显式 `sort` 路径正确（已由 `explicitSortIsRespected` 覆盖）。

## 修复记录

- **修复人**：后端开发工程师（`backend-engineer#java`）
- **修复时间**：2026-09-21 00:37 (+08:00)
- **涉及文件**：
  - `java/src/main/java/com/hedgeguard/web/handler/plan/PlanHandler.java`（`list()` + 私有常量 `DEFAULT_SORT`）
  - 回归用例：`java/src/test/java/com/hedgeguard/web/handler/plan/PlanListDefaultSortTest.java`
  - （**未改**公共件 `dao/PageQuery.java`）
- **根因**：`PlanHandler` 在 `?sort=` 缺省时只把**裸字段名**当 `defaultSortField` 传给 `PageQuery.of(...)`，而该工厂在 `sort` 缺省时方向**恒为 `ASC`** ⇒ 生成 `ORDER BY created_time ASC`，与 `FR-PLAN-4`「默认倒序」相反。
- **修复方式**（**handler 侧最小修**，不动公共件）：
  1. 新增端点私有常量 `DEFAULT_SORT = PlanService.DEFAULT_SORT_FIELD + ",desc"`（即 `"created_time,desc"`）；
  2. `list()` 中 `?sort=` 缺省（`null`/空）时用 `DEFAULT_SORT`，再交 `PageQuery.of(...)`；显式 `sort` 一律原样尊重。
  - **为何不改 `PageQuery`**：它是 `dao` 公共件，改其缺省方向会影响**全部**分页端点 —— 属技术负责人裁定范围（已另提），本单不越界。
- **回归测试**：`PlanListDefaultSortTest`（2 例）—— ① 缺省 ⇒ `created_time` + `DESC`（`ascending=false`）；② 显式 `sort=plan_no,asc` ⇒ 被尊重（缺省方向不覆盖显式值）。
- **验证方式**：`mvn -B -o test -Dtest=PlanListDefaultSortTest` → 修复前 **1/2 失败**（`expected:<DESC> but was:<ASC>`）；修复后 **2/2 通过**。
- **影响面**：仅 `GET /api/v1/plan` 缺省排序对齐需求；显式排序、分页、筛选、详情端点**行为不变**。
