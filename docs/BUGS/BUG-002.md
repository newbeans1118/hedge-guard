## 实际结果

平仓指令被**拒绝**，且上报规则 = `R-RISK-2`（额度校验）：

```
P1a open  / quota exhausted                          decision=REJECT rule=R-RISK-2 code=0x1004 layer=SUB_PRODUCT entries=1 na=0
P1b CLOSE / quota exhausted  <== R-RISK-5 expects PASS decision=REJECT rule=R-RISK-2 code=0x1004 layer=SUB_PRODUCT entries=1 na=0
```

**根因链**：`evalQuota()`（`cpp/src/risk_engine/src/risk_engine.cc:210–235`）**无 `is_open` 判定**，对任意方向一律按 `used + frozen + reqq > limit` 判超限 ⇒ 平仓亦按「占用增加」处理。对照：

| `evalQuota`（`R-RISK-2`） | `risk_engine.cc:210` | **无** ← 本缺陷 |
| `evalPositionLimit`（`R-RISK-3`） | `risk_engine.cc:260` | `if (!is_open) return;` |
| `evalScale`（`R-RISK-4`） | `risk_engine.cc:287` | `if (!is_open) return;` |
| `evalNetPosition`（`R-RISK-5`） | `risk_engine.cc:321` | `if (!is_open) return;` |

## 影响面

- **功能**：额度已耗尽/触顶时，**平仓与风险处置类指令被误拒** ⇒ 风险无法释放（`R-RISK-5` 的原文动机即为防此）；与持仓上限/规模红线/净持仓/期限四规则的平仓豁免**行为不一致**，契约面自相矛盾。
- **规避**：调用方无合规规避手段（这恰是必须放行的方向）。
- **范围**：仅限「额度类校验（`R-RISK-2`）」；其余四类限制规则的平仓豁免经本席探针确认**正常**（`P4`）。

> **修复方向建议（供参考，不代开发定方案）**：将 `evalQuota` 与其余四规则对齐（平仓/减仓方向跳过额度判定，或按释放额度处理）；并**补一条「平仓 × 额度耗尽 ⇒ 放行」反退化用例**（现无守卫，故本缺陷得以逃逸）。是否采用及具体口径由责任开发 + 技术负责人裁定。
