## 5. 协议专项用例

### 5.1 帧格式 / 成帧 / CRC / 版本不匹配

#### TC-M2-01 同步字 `MAGIC` 不匹配

- **对应**：`T6`；`ARCHITECTURE.md` §4.2.2 / §4.3.2 `0x0102`；落点：**C++ ctest**（`hgcp.frame_test`）+ Java `HgcpFrameTest`
- **前置**：已建连；构造帧首 4 字节改为 `"XXXX"`。
- **步骤**：1) 送入该帧；2) 观察处置。
- **预期结果**：返回/上报错误码 **`0x0102`（`ERR_BAD_MAGIC`）**，**断连 + 告警**。判定方式：抓错误码 + 连接状态。
- **异常与恢复**：重连后按 §5.4 补数。
- **备注**：`FrameStatus` 须可区分该状态。

#### TC-M2-02 线格式版本 `VER` 不匹配

- **对应**：`T6`；§4.2.2 `VER`；落点：**C++ ctest** `hgcp.frame_test`
- **步骤**：1) 构造 `VER=0x0101` 的帧（期望 `0x0100`）；2) 送入。
- **预期结果**：错误码 **`0x0101`（`ERR_VERSION_MISMATCH`）**，拒绝连接。判定方式：抓错误码。
- **备注**：`HELLO.proto_version` 不符亦归 `0x0101`（§4.3.2）。

#### TC-M2-03 `CRC32` 校验失败

- **对应**：`T6`；§4.2.2 `CRC32`；落点：**C++ ctest** `hgcp.frame_test`
- **步骤**：1) 取合法帧，翻转 `PAYLOAD` 1 字节（CRC 不重算）；2) 送入。
- **预期结果**：错误码 **`0x0103`（`ERR_CRC_MISMATCH`）**，断连 + 告警，触发重连补数。判定方式：抓错误码 + 连接状态。

#### TC-M2-04 帧超限（`LEN > 1 MiB`）→ `0x0308` + 关闭连接

- **对应**：`T6`/`I-2`/`CH-014`（已生效）；§4.2.8.8；落点：**C++ ctest** `hgcp.transport_test`（`server_loop` `kFrameTooLarge` 分支）
- **步骤**：1) 送入 `LEN = 1 MiB + 1` 的帧；2) 观察回码与连接生命周期。
- **预期结果**：尽力回 **`MSG_ERROR{err_code=0x0308}`**（`err_msg` 含「请使用分片」提示，**不新增字段**），**随后关闭连接**；关闭后按 §4.2.6 走重连 + `MSG_RESUME_REQ`。判定方式：抓 `0x0308` + 连接关闭事件。
- **备注**：**专码优先于兼码**（`0x0308` 而非 `0x0104`）；「不中断连接」对该情形**不适用**。

#### TC-M2-05 单帧 `LEN` 边界（恰 1 MiB 通过）

- **对应**：`T10`；§4.2.2；落点：**C++ ctest** `hgcp.frame_test`
- **步骤**：1) 构造 `LEN = 1 MiB` 的帧 → 送入；2) 构造 `LEN = 1 MiB + 1` → 送入。
- **预期结果**：步骤 1 **通过**（`FrameStatus = kOk`）；步骤 2 **`0x0308`**。判定方式：两个返回状态**严格不等**。

#### TC-M2-06 未知消息类型 `TYPE`

- **对应**：`T6`；§4.3.2 `0x0105`；落点：**C++ ctest** `hgcp.frame_test`
- **步骤**：1) 送入 `TYPE=0x9999`（不在 §4.2.3 清单）；2) 观察连接。
- **预期结果**：错误码 **`0x0105`（`ERR_UNKNOWN_TYPE`）**，**丢弃该帧、不中断连接**（帧边界由 `LEN` 精确确定）。判定方式：抓错误码 + 连接仍存活。

#### TC-M2-07 载荷解析失败

- **对应**：`T6`；§4.3.2 `0x0104`；落点：**C++ ctest** `hgcp.envelope_test` + Java `HgcpFrameTest`
- **步骤**：1) `TYPE` 合法但 `PAYLOAD` 为非法 protobuf 字节；2) 送入。
- **预期结果**：错误码 **`0x0104`（`ERR_PAYLOAD_INVALID`）**，丢弃该帧、不中断连接。判定方式：抓错误码 + 连接仍存活。

### 5.2 握手 / 鉴权

#### TC-M2-08 错误令牌（摘要不匹配）

- **对应**：`T7`；§4.2.6(1) / §4.3.2 `0x0201`；落点：**C++ ctest** `hgcp.crypto_auth_test` + `hgcp.session_test`
- **前置**：已注入 `TokenVerifier`（正确令牌摘要 `H`）。
- **步骤**：1) `MSG_HELLO.auth_token = "wrong"` → 送入。
- **预期结果**：回 **`MSG_AUTH_FAIL{reason_code=0x0201}`** + **立即关闭连接** + 失败留痕（审计）。判定方式：抓码 + 连接关闭 + 留痕记录 = 1 条。

#### TC-M2-09 缺失令牌

- **对应**：`T7`；§4.3.2 `0x0202`；落点：**C++ ctest** `hgcp.crypto_auth_test`
- **步骤**：1) `auth_token = ""` → 送入。
- **预期结果**：**`0x0202`（`ERR_AUTH_TOKEN_MISSING`）**，拒绝连接，提示「鉴权凭据须手工录入」。判定方式：抓码。

#### TC-M2-10 令牌版本不符

- **对应**：`T7`/`I-1`；§4.2.6 / §4.3.2 `0x0203`；落点：**C++ ctest** `hgcp.crypto_auth_test`
- **步骤**：1) `HELLO.token_version` 与对端不一致 → 送入。
- **预期结果**：**`0x0203`（`ERR_AUTH_TOKEN_VERSION`）**，拒绝连接，要求双方重启。判定方式：抓码。
- **备注**：`token_version` 为 `MsgHello` 第 7 字段（`I-1` 补登），本用例同时验证该字段被读取。

#### TC-M2-11 鉴权重放

- **对应**：`T7`；§4.3.2 `0x0204`；落点：**C++ ctest** `hgcp.crypto_auth_test`
- **步骤**：1) 同一 `client_boot_id` + 令牌，在短窗口内重复建连 2 次。
- **预期结果**：第 2 次回 **`0x0204`（`ERR_AUTH_REPLAY`）** + 告警。判定方式：抓第 2 次码。

#### TC-M2-12 未握手先发业务消息

- **对应**：`T6`/§4.2.6；§4.3.2 `0x0107`；落点：**C++ ctest** `hgcp.session_test`
- **步骤**：1) 建连后不发 `HELLO`，直接发 `CMD_PLACE_ORDER`。
- **预期结果**：**`0x0107`（`ERR_NOT_HANDSHAKEN`）**，丢弃 + 断连。判定方式：抓码 + 连接关闭。

### 5.3 心跳与断连检出

#### TC-M2-13 心跳 3 次丢失 ⇒ ≤5 s 检出

- **对应**：`T5`；§4.2.6(2)；§4.3.2 `0x0301`；落点：**C++ ctest** `hgcp.timing_test` + `hgcp.session_test`（可注入时钟）
- **前置**：`HEARTBEAT_INTERVAL_MS=1000`、`HEARTBEAT_MISS=3`。
- **步骤**：1) 静默一侧（不回 `HEARTBEAT_ACK`）；2) 注入时钟推进。
- **预期结果**：检出时间 **`= 3000 ms`**（上限 `≤ 5000 ms`）；回/记 **`0x0301`（`ERR_HEARTBEAT_TIMEOUT`）**；关闭连接 → 进入重连 + 事件流缓冲。判定方式：注入时钟值 + 错误码。
- **备注**：`NFR-REL-2`。

#### TC-M2-14 重复业务连接被拒

- **对应**：`T6`；§4.2.1 / §4.3.2 `0x0302`；落点：**C++ ctest** `hgcp.session_test`
- **步骤**：1) 通道 A 已有活跃业务连接时，再建第 2 条。
- **预期结果**：**`0x0302`（`ERR_DUPLICATE_CONNECTION`）**，拒绝新连接 + 告警。判定方式：抓码。

#### TC-M2-15 重连退避与累计失败告警

- **对应**：`T5`；§4.2.6(3)；§4.3.2 `0x0303`；落点：**C++ ctest** `hgcp.timing_test`
- **步骤**：1) 连续失败 1..9 次 → 记录退避间隔；2) 第 10 次失败。
- **预期结果**：退避序列 **`500 → 1000 → 2000 → 4000 → 8000`** ms，**上限 8000 ms**，**无限重试**；累计 **`≥10`** 次触发 **`0x0303`（`ERR_RECONNECT_LIMIT`）** + 严重告警。判定方式：注入时钟序列 + 第 10 次码。

### 5.4 断连重连补数

#### TC-M2-16 断连 5 s 内 200 事件 ⇒ 重连全补齐、无重复落库

## 6. `NFR-PERF-6` 验证口径（验收 3，单独成节）

> `NFR-PERF-6`：**事件流吞吐 ≥ 1000 事件/秒，且不丢、不乱序**（`REQUIREMENTS/NONFUNCTIONAL.md:57`）。
> 架构承载：`ARCHITECTURE.md` §4.2.6(3)「补数完成判据」。

### 6.1 判据锚（关键）

| 项 | 口径 |
|----|------|
| **计数锚** | **以线路帧（wire frames）为准**，**不是**接收侧消费的事件数 |
| **理由** | `CH-007`：接收侧消费层**丢弃补数批次行情帧** ⇒ 若以消费数为锚，会**误判为丢帧**。`ARCHITECTURE.md` §4.2.6(3) 明载「本判据以线路帧为准」 |
| **一致性判据** | 两侧 `last_received_seq` 相等 **且** 逐帧数量与顺序完全一致 |
| **单帧比对元组** | `(TYPE, SEQ)` + 业务关键字段摘要（`digest`） |
| **吞吐判据** | ≥ **1000** 帧/秒（通道 A，含事件帧与控制帧） |
| **丢失判据** | 丢失帧数 **`= 0`** |
| **乱序判据** | 乱序帧数 **`= 0`** |

### 6.2 采集方法（可复现）

1. **发送侧**（C++）：对每一出站帧记录 `(SEQ, TYPE, digest, ts_ms)` 到有序日志 `S`。
2. **接收侧**（Java）：对每一入站帧（**含补数批次内行情帧**）记录 `(SEQ, TYPE, digest, ts_ms)` 到有序日志 `R`。
3. **对拍**：断言 `len(S) == len(R)` 且 `∀k: S[k] == R[k]`（**线路级**，不受消费层丢弃影响）。
4. **吞吐**：以 `S` 的首末 `ts_ms` 计窗口，`|S| / window_seconds ≥ 1000`。
5. **1000 笔压力**：连续产生 `1000` 个事件（`PROJECT.md` 成功标准 31）⇒ `len(R) == 1000`，`SEQ` 与业务字段逐条一致。

### 6.3 与既有落点的关系

| 既有用例 | 关系 |
|----------|------|
| `TC-PERF-6`（`NONFUNCTIONAL.md:96`） | 本节的**性能侧承载**；本节补登「**线路帧锚**」与 `CH-007` 限定语 |
| `TC-TRADE-21`（1000 条不丢不乱序并落库） | 业务侧落库；本节为其**协议层对拍口径** |
| `TC-EXC-3`（断连检出 + 补数） | 本节为补数后的**收敛判据** |

### 6.4 判定

- **通过**：`len(S)==len(R)` 且逐帧一致 且 吞吐 `≥1000` 且 丢 `=0` 且 乱序 `=0`。
- **不通过**：任一不满足；**注意**：若仅「接收侧消费数 < 线路帧数」而线路级对拍一致，**不判失败**（`CH-007` 预期行为）。
