## 1. 模块测试要点

| 项 | 内容 |
|----|------|
| 被测模块职责 | 由实货敞口编制套保计划、计算套保比率、生成套期关系书面文件与审批链（Java + 前端） |
| 本模块 FR 清单 | `FR-PLAN-1` … `FR-PLAN-20`（20 条） |
| 测试重点 | ① **计划必须由实货敞口出发**（单向，`R-PLAN-*`）；② **套保比率三档算法**（简单/最小方差/自定义规则法——自定义仅固定比例上限，取最严，`Q-6`）；③ **书面文件三要素门禁**（正式指定+有效性评估方法+再平衡机制，缺一不得提交审批）；④ **提交前合规预校验**（规模红线 90%/80%、期限红线取较早者，`Q-1`/`Q-4`）；⑤ **审批链**（审批人与编制人不得同一人，驳回原因必填）；⑥ **计划数量 ≤ 敞口未覆盖数量、Σ交易计划 ≤ 套保计划数量**（服务层跨表聚合，`DATA_MODEL.md` §4.4） |
| 特殊要求 | 需构造现货价样本 <30 以验证最小方差法；需构造规模/期限红线临界值 |
| 里程碑 | M1（与 `PRODUCT`/`SPOT` 同期） |

**JUnit 既有覆盖（追溯锚点）**：`java/src/test/java/com/hedgeguard/service/PlanServiceTest.java`（11 个 `@Test`）。
