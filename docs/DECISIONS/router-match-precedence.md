## 0. 结论摘要

**裁定 (a)：维持现状。** 即：**不**在 `Router` 中引入「静态字面段优先于占位符」的匹配语义；该缺陷类由 **(i) 「占位符路由须最后注册」的注册序约定 + (ii) `T-154` 的机械判据（构建期自动运行）** 防守。

一句话理由：**该缺陷类的现存暴露面已被 `T-151` 就地清零（本席实测 81 路由、遮蔽 0），且 `T-154` 使其在 `mvn test` 中即红 ⇒ 该缺陷已不可能进入生产；而改动 `Router` 的匹配语义是给一个 `CONTRACTS.md` 列举的冻结类型新增一条「在任何权威文本中均无源」的规范（＝设计变更，须开 `CH`），其全部可观测效果只发生在未来假定的路由配置上（现表零行为差异）⇒ 收益已被 `T-154` 覆盖，成本与风险不划算。**

**本裁定给出**：必要性判据与残留风险（§2）、为何「冻结类 + 非冻结行为」无需升版（§3）、约定的**可发现化落点**（§4）、**证伪条件**（§5，何者翻转）、以及备选 (b) 的**等价性论证 + 变更定级 + 可直接入册的 `CH` 提案本文（未生效）**（§6）。

## 2. 裁定

### 2.1 结论：**(a) 维持现状**

> **不引入**「静态字面段优先于占位符」的框架语义。该缺陷类的防守 = **「占位符路由须在同 `(方法, 段数)` 的静态路由之后注册」的注册序约定** ＋ **`T-154` 判据（`mvn test` 中自动运行）**。
> **零代码改动、零升版、不开口 `CH`。**

### 2.2 必要性判据（**为何「不改」**）

| # | 判据 | 依据（本席实测） |
|---|---|---|
| **N1** | **该类缺陷的全部现存暴露面已清零** | §1.3 #4/#6：当前遮蔽 `0`；改前 `5`（`T-151` 已修，复核席 `te-verify-t151` = 通过 ⇒ `T-151` 已 `DONE`） |
| **N2** | **该类缺陷在构建期即不可通过 ⇒ 不可能进入生产** | `T-154` 判据对**每条**已注册路由做「实例路径自匹配」回查（作业期实读其判据本文 `RouteReachabilityExhaustiveTest`：`everyRegisteredRouteMatchesItself` + 装配规模 `81` 守卫 + 镜像方向 `unregisteredPathsAreNotMatched` + 非空转自测 `detectorIsNotVacuous`）。该判据**天然完备于本缺陷类**：任一「静态路由被更早注册的同段位占位符吞并」都会使其**实例路径回查为对方模式** ⇒ 必红。⇒ **「约定 + 机械守卫」在本类上已达到与「框架保证」同等的工程效果：不可交付。** |
| **N3** | **改 `Router` 是「无源规范新增」，不是勘误** | §1.2：任何权威文本均未载匹配优先序；`CONTRACTS.md` §1.4 冻结四条（**逐条在 (b) 下仍成立**）＋ §0② 只冻结**签名**（(b) 下 `register/match/pathExists/routes` **签名全不变**）。⇒ 引入优先序＝**新增一条规范**。按本项目既有口径（`T-032` `from_seq/to_seq` 先例：无源 ⇒ 判 `L3`、须 `CH` + 批准），属**设计变更**，须走 `CH` |
| **N4** | **(b) 在当前表上零行为差异 ⇒ 收益只落在未来假定配置** | §1.3 等价性探针：**820 次比对 `DIFFS = 0`**。即「为一段当前**不可观测**的语义，去改一个 `CONTRACTS.md` 列举的冻结类型的公开行为」，须付 `CH` + 独立复核 + 批准，而收益已被 N2 覆盖 |
| **N5** | **(b) 引入的语义在当前生产表上「永不被行使」，且与既有判据无耦合** | 81 路由表中**不存在**任何需要该语义的配置（§1.3 #5：可重叠对仅那 5 处、且均已是「静态在前」）。同时 `pathExists`（405）为**全体 OR**、`ModuleRoutesConsistencyTest` 为 **`HashSet` 等值**（本席实读）⇒ 两者与顺序均无关，(b) 对它们**不产生任何可断言的变化** ⇒ 该语义**无可锚定的生产行为**，只能靠合成路由自测 |

### 2.3 残留风险与「为何可接受」

| 残留风险 | 严重度 | 为何可接受 / 缓解 |
|---|---|---|
| **R1** 约定是**隐性**的（写在 `ProductRoutes`/`SpotRoutes` 的 javadoc，非编译期约束） | 中 | **N2 兜底**：`T-154` 在**构建期**必红 ⇒ 隐性约定即使被遗忘，也**不会产出缺陷**；且失败消息**自解释**（「存在不可达 / 被遮蔽的路由（注册序须『先静态、后占位符』）」+ 点名被遮蔽项与实际命中项）⇒ 违规者**立刻得到修复指引**（§4.1） |
| **R2** 新成员不知此约定；新模块（`TRADE`/`SETTLE`/`RISK`/`ACCOUNT`/`FUND`/`AUDIT`）尚未注册路由 ⇒ 未来会大量新增路由 | 中 | 同 R1；另 **§4.3** 建议在框架类 javadoc 加**显式标注「非冻结·实现约定」**的指针段（**不改**冻结四则） |
| **R3** `T-154` 判据**若被移出门禁**（`@Disabled` / profile 排除 / 移出 `src/test`）⇒ 守卫失效 | 高（但可控） | 列为 **证伪条件 F1**（§5）：一旦发生，本裁定即翻转 |
| **R4** `T-154` 的**判据边界**：只检测「同段位」静态↔占位冲突；**不检测**「占位符∩占位符」的部分遮蔽（如先 `/p/x/{b}`、后 `/p/{a}/{b}` ⇒ 后者在 `/p/x/*` 上被前者部分吞并） | 低 | 该形态在**当前表上不存在**（§1.3 #5）；且「具体胜过通用」本身是**良性**的常见路由语义，是否须显式化**无源可依** ⇒ 列为 **F2**，出现即须显式钉住 |

**为何可接受（总括）**：本项目的基本纪律是「**制品按源改动、无源即设计**」。在「缺陷类已被清零且被构建期机械守卫」的前提下，**引入一条无源规范**的成本（`CH` + 批准 + 独立复核 + 为不可观测语义写测试）**高于**其增益（N2 已等价达成）。⇒ 以**最小改动**维持现状，并把「何时必须翻转」写成可执行的证伪条件（§5）。

### 2.4 方案 (c)（拆分静态 / 动态两张注册表）予以否决

- **等价性**：(c) 与 (b) 在**语义效果上等价**（都是「字面优先」），故 §6.2 的零差异论证同样适用。
- **否决理由**：① **成本最高而收益与 (b) 相同** —— 需新增结构（两张表 / 注册分派 / 查表顺序），改动面比 (b) 更大，却未带来 (b) 之外的任何能力；② **对冻结面的触碰更重**（`Router` 的**内部结构与 `routes()` 自检清单的构造方式**都要动，而 `routes()` 已被 `ModuleRoutesConsistencyTest`/`BootstrapAssemblyTest`/`T154` 依赖）；③ **不解决 R4**（占位符∩占位符仍需额外规则）；④ 违反「**三行代码优于过早抽象**」与「不为假设的未来需求设计」。⇒ **不采纳**。

## 3. 为何 (a) **无需升版**（「冻结类 + 不在其冻结清单内的行为」）

### 3.1 三问

| 问 | 答 | 依据 |
|---|---|---|
| ① 冻结范围**是否含**该内容？ | **否** | `CONTRACTS.md` §0① 载体列表**不含 `Router`**；§0② 只冻结**签名**；§1.4 四条**不含优先序**；§3.1 只列**成员**。§1.2 已逐处实测 |
| ② 是否有**契约级**条款？ | **否** | 与前端/REST 的契约 = **路径 + 方法 + 信封**（§4.1.1 / §1.1），**不含匹配算法**；无任何条款把 `Router` 的匹配顺序列为契约 |
| ③ 有**可转录的源**？ | **否** | 优先序在任何权威文本中**均无源**；现有行为（注册序首次命中）是**实现涌现值**，非受契约束的行为 |

### 3.2 处置原则（**可复用**）

> **原则（本裁立）**：**「某类型被冻结登记」≠「该类型的一切行为被冻结」。** 冻结面按**载体**与**清单内容**界定：
> - **签名 / 路径 / 字段 / 错误码 / 信封** 属冻结面 —— 改之须 `CH`（`CONTRACTS` §5.3 / §5.5 / §0）。
> - **未被任何清单列举的行为**（此处：匹配优先序）属**实现自由区** —— **维持其现状 = 零改动 ⇒ 不触发任何升版义务**；**冻结它**（或改变它）才是变更、才须 `CH`。
>
> 因此本裁定的「不升版」**不是**因为「匹配顺序不重要」，而是因为 **`(a)` 状态下不存在任何被改动的冻结条目**（§3.1 三问逐条为「否」）。附带的可验证事实：`T-151` 的 `CONTRACTS.md` §5.1 登记（本席实读该行）已确认「**§1 信封 / 分页 / 幂等 / 鉴权、§4.1.1 路径与方法、§1.3 错误码集合均未变 ⇒ 未升版、无需 `CH`**」—— 该判定**同样成立且是本裁定的先例**。
