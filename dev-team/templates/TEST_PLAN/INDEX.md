## 2. 用例总表

> ⚠️ **本表是测试用例文件的唯一事实源**——哪些模块有独立用例文件、各有多少条。
>
> **模块代号必须复用 `REQUIREMENTS/INDEX.md` §2 模块登记表**：
> **不得新建、不得改名、不得自造**。理由：`TC-<模块>-<序号>` 与 `FR-<模块>-<序号>`
> 的 `<模块>` 必须指向同一个业务模块，否则追溯链无法自证。

| # | 模块代号 | 模块名 | 用例文件 | 用例数 | 状态 |
|---|---------|--------|---------|-------|------|
| 1 | `<代号>` | | `docs/TEST_PLAN/<代号>.md` | | 已写 / 未写 |
| … | | | | | |
| — | — | **边界与异常** | `docs/TEST_PLAN/BOUNDARY.md` | | |
| — | — | **非功能** | `docs/TEST_PLAN/NONFUNCTIONAL.md` | | |

> **不是每个需求模块都必须有用例文件**——只有被测模块才建。
> 但**每个 FR 都必须被某条用例覆盖**（见 §6 追溯矩阵）。

### 2.1 用例拆分规则

> 本文件适用**通用「模块化文档拆分规则」**（见编排规则 §8.3）。

**两份跨模块文件恒存在**：`BOUNDARY.md` 与 `NONFUNCTIONAL.md` 是**固定文件名**，
不因条数少而省略——条数少就写少几条，但文件本身必须有（§12 文件清单按"必须存在"自检）。
理由：跨模块用例**天生不属于任何模块**，如果连文件都没有，它们只会散落或干脆不写。

| 情形 | 处理 |
|------|------|
| 单模块用例 ≤ 20 条 | 保持单文件 |
| 单模块用例 > 20 条 | **先拆模块**：识别子域 → 提成新模块（须同步登记到 `REQUIREMENTS/INDEX.md` §2） |
| 拆模块后仍 > 20 条 | 兜底：拆二级文件 `<模块>-<子域>.md`，在 §2 登记 |
| `BOUNDARY.md` 用例 > 12 条 | **文件不变**，内部按边界类型分节（数值边界 / 状态边界 / 并发边界 …） |
| `NONFUNCTIONAL.md` 用例 > 12 条 | **文件不变**，内部按 NFR 类别分节（本模板已预置 8 类） |

**新增模块时代价必须清醒**：模块代号要同时改需求侧登记表——
**这是有意的**，它保证两侧永远对齐。

## 6. 需求追溯矩阵

> **双向核对**：正向查"需求有没有用例覆盖"，反向查"用例有没有需求来源"。

### 6.1 正向：需求 → 用例

| 需求编号（含文件归属） | 需求描述 | 对应用例（含文件归属） | 覆盖状态 |
|---------------------|---------|---------------------|---------|
| `FR-TRADE-1 @ REQUIREMENTS/TRADE.md` | | `TC-TRADE-1 @ TEST_PLAN/TRADE.md` | ✅ / ❌ |

> ❌ 未覆盖的必须写**理由与处理方式**（补用例 / 标注不测 + 理由），不得留空。
>
> **非功能性需求也要进本表**：`NFR-*` 的归属写 `REQUIREMENTS/NONFUNCTIONAL.md`，
> 对应用例写 `TC-PERF-1 @ TEST_PLAN/NONFUNCTIONAL.md` 这类。

### 6.2 反向：用例 → 需求

| 用例编号（含文件归属） | 无对应需求的理由 |
|---------------------|----------------|
| `TC-BOUND-3 @ TEST_PLAN/BOUNDARY.md` | <如"探索性用例，用于验证并发下单的时序假设；已记入风险 §11"> |

> 反向检查为空是正常的；**有内容也不一定是错**（如探索性用例），
> 但必须说明理由。

## 9. 缺陷管理

### 9.1 缺陷分级

| 级别 | 定义 | 处理时限 |
|------|------|---------|
| P0 致命 | 核心功能不可用、数据丢失、安全漏洞、崩溃 | 立即，阻塞发布 |
| P1 严重 | 主要功能异常、无规避方案、契约不符 | 当轮修复 |
| P2 一般 | 次要功能异常、有规避方案 | 可延后 |
| P3 轻微 | 界面瑕疵、文案、体验 | 排期优化 |

### 9.2 缺陷生命周期

```
NEW → ASSIGNED → FIXED → VERIFYING → CLOSED
                            └──> REOPENED → ASSIGNED
```
