## 要求

1. **必读章节**：`ARCHITECTURE.md` §3.15（前端结构）、§4.1.1（REST 约定）、§4.1.2（WebSocket 端点）、
   §7.1.9（静态托管隔离方式）、§8.8（易用性）、§3.0.2 `E6`（零构建链校验）。
2. **硬约束（违反即架构偏离）**：
   - **零构建链**：代码库中**不得出现** `package.json` / `node_modules` / 打包产物 / `*.min.js`；
     改动 = 直接编辑 `.html` / `.js` / `.css` 源文件后刷新即生效（`NFR-MAINT-1`）。
   - **不得直接访问数据库或 C++ 组件**：前端只与 Java 的 `/api/v1/**` 与 `/ws/**` 通信（`NFR-MAINT-5`）。
   - **不得在前端做业务判定**（风控、额度、会计口径一律以后端返回为准）。
   - 建议使用**原生 ES Module**（`<script type="module">`，浏览器原生支持，**无需打包器**）+ 统一命名空间 `HG.<module>.*`。
3. **接口适配要点**：
   - 统一响应信封 `{ code, message, data, traceId }`；**金额 / 数量为字符串化十进制**（避免 JS 精度丢失）。
   - **阻断类错误必须渲染四项**：`ruleId` + `current` + `threshold` + `nextStep`
     （`NFR-USE-3`/`NFR-USE-4`；后端已强制返回，前端**不得只显示"操作不允许"**）。
   - 分页 `?page=&size=&sort=`（`size ∈ {10,20,50,100}`，默认 20）；写类接口须带 `Idempotency-Key`。
4. **易用性硬指标**（验收会用）：
   - `NFR-USE-1`：新用户 **30 min** 内完成"录入现货 → 计算实货敞口"（分步表单 + 内联说明 + 即时校验）；
   - `NFR-USE-2`：查看交易计划 → 提交指令 **≤ 5 步**（计划列表直接带"下单"按钮并预填计划 ID / 子账户 / 品种 / 方向）；
   - `NFR-USE-5`：**子账户 / 汇总视图切换 ≤ 2 次点击**；**套保效果页两栏同屏**（CSS 并排，**不分页不跳转**）。
5. **v1.1 新增界面**（源自 `CH-002`）：
   - **核对任务与电子签署页**（月度三方 / 季度管理层签收 / 年度审计覆盖）；
     需展示**快照哈希**、**逾期未签**、**签署 IP / 时间**，并对"非应签角色 / 代签"给出明确拒绝提示。
   - **交易理由**表单改为**结构化必填**（关联类型 + 关联对象〔计划 + 实货敞口〕+ 时点说明，+ 可选自由文本）。
   - **限额三层**展示（子账户+品种 / 子账户+合约 / 账户+品种，并标明"命中的层级"）。
   - **敞口三分量**展示（合同未执行量 / 库存 / 生产计划，支持分别开关与按子账户/品种覆盖，**合计与分量同时可见**）。
   - **价格偏离两档**提示（(2%,5%] 需**二次确认**；> 5% 阻断）。
